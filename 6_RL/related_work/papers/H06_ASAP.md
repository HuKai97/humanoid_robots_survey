# H06 · ASAP：用真实轨迹校正仿真，再回仿真改进动作

- **论文**：ASAP: Aligning Simulation and Real-World Physics for Learning Agile Humanoid Whole-Body Skills，Tairan He、Jiawei Gao、Wenli Xiao、Yuanhang Zhang 等。
- **时间 / 平台**：2025-02-03 首发；RSS 2025；Unitree G1，论文动作空间为 23 维。
- **类别 / 优先级**：动作模仿、sim-to-real、真实数据驱动动力学差异补偿；P1，进阶阅读。
- **证据深度**：A；v1 HTML、官方项目与仓库已核验；没有真机复现。访问日期：2026-09-29。

## 一分钟总结

ASAP 先在仿真学动作，在实机采一批执行轨迹；随后训练一个“动作修正模型”，让仿真产生更接近实机的行为，再在这个修正后的仿真里微调原策略。最后部署的是微调后的控制策略，**不是在实机外挂该修正器**。这与只扩大随机化范围是不同思路。[项目方法](https://agile.human2humanoid.com/)

## 详细介绍：问题与方法

敏捷动作对电机、时延和落地接触误差敏感，保守随机化又可能牺牲动作幅度。ASAP 用 delta action 作为仿真差异的可学习接口：给定记录的动作，在模拟器里加入修正，使得到的轨迹接近真实记录。冻结修正模型之后，策略在“更像真实硬件”的模拟器中再次优化。[项目流程](https://agile.human2humanoid.com/)

| 项目 | 已核验的设计 |
|---|---|
| Actor observation | 本体输入与动作时间相位；不要求全局位置目标或真实根部线速度 |
| Critic | 可读取额外仿真状态及参考信息 |
| Action | 23 维关节目标，经 PD 执行 |
| Reward | 身体/关节姿态和速度跟踪，配合限位、平滑、脚滑等惩罚 |
| Training | PPO、参考状态初始化、逐步收紧跟踪失败阈值；真实轨迹训练 delta action，再在修正仿真微调 |

必须区分两类传感需求：最终 actor 不依赖里程计，并不等于研究流程不需要外部定位；论文记录真实轨迹时使用动捕与机载传感器。校准数据里的位姿/速度误差会影响学到的补偿。[方法与采集 §II–III](https://arxiv.org/html/2502.01143v1)

## 证据与局限

作者在 IsaacGym→IsaacSim、IsaacGym→Genesis、IsaacGym→G1 场景做比较，并展示跳跃、踢腿等敏捷动作。视频强调的是执行质量和动力学迁移，不能直接支持自主规划、避障或新环境理解。[项目实验](https://agile.human2humanoid.com/)

官方仓库基于 HumanoidVerse，已有相位跟踪、delta action 训练、策略微调、重定向、部署的说明与入口；因此不应沿用早期“只有动作跟踪开源”的旧描述。但本轮未运行，不保证每条说明在当前软件环境开箱可用。[官方代码](https://github.com/LeCAR-Lab/ASAP)

完整流程使用真实交互数据，不能称为从头到尾零实机数据的 zero-shot 方法。补偿在已采集动作之外是否准确，仍要专门留出不同速度、接触、负载的轨迹评测。它也不自动分辨误差来自物理、传感器还是时间同步。

## 与传统感知的关系

研究建议：把轨迹对齐、时间同步、接触状态估计和不确定性建模用于提高校准数据质量。比较直接用估计轨迹、平滑后的轨迹、按置信度加权轨迹，评估是否减少“把感知误差学成动力学误差”的现象。对状态估计背景而言，这是直接的接口，不必从零设计新的 PPO。

## 阅读 / 复现重点

先手画预训练、真实采集、差异模型、微调四个阶段，逐一标明数据和梯度去向。没有实机时先做跨模拟器实验：刻意修改执行器或延迟，再检验差异补偿能否恢复。保存未补偿策略、随机化基线、系统辨识基线与失败轨迹；不要只比较最佳动作片段。
