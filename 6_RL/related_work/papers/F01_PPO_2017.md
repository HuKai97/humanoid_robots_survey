# F01 · PPO：先理解策略怎样被更新

- **论文**：Proximal Policy Optimization Algorithms。
- **作者 / 年份**：John Schulman, Filip Wolski, Prafulla Dhariwal, Alec Radford, Oleg Klimov；2017，arXiv 预印本。
- **类别 / 平台**：通用策略梯度算法；原实验包括仿真连续控制与 Atari，不是人形实机论文。
- **优先级 / 核验**：P0；2026-09-29；证据 B（原摘要、发布方介绍和官方教学文档；论文 HTML 转换不可用，未下载 PDF）。[原始记录](https://arxiv.org/abs/1707.06347)

## 一分钟总结

PPO 回答“收集一批动作及结果后，怎样改策略而不一次改得太猛”。它用新旧策略对同一个动作的概率比，加上优势估计，构造容易用梯度下降实现的目标。它没有规定机器人应该看到什么、输出什么、怎样奖励。读后续人形论文时，PPO 通常是训练发动机，研究贡献往往在观测、数据、奖励、课程和部署链路。[论文摘要](https://arxiv.org/abs/1707.06347)

## 问题与方法

普通策略梯度更新容易受噪声和步长影响；TRPO 使用更复杂的信赖域优化。PPO 的主要动机是在实现难度和训练效果之间取得实用平衡，同一批新采集数据可进行多轮优化。[作者发布说明](https://openai.com/index/openai-baselines-ppo/)

常见 PPO-Clip 目标写作：

$$L=\mathbb E[\min(\rho_t\hat A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t)],\quad \rho_t=\pi_\theta(a_t|o_t)/\pi_{old}(a_t|o_t).$$

优势为正，增加该动作概率；优势为负，降低概率。裁剪削弱某些过大更新继续获益的动机，**不保证整个策略分布变化严格受限**。官方教学实现还讨论 KL 提前停止。Actor 负责动作分布，critic 估计价值；后者不是传统轨迹跟踪控制器。[官方算法解释](https://github.com/openai/spinningup/blob/master/docs/algorithms/ppo.rst)

## 控制链路逐项理解

| 项目 | 本文规定了什么 |
|---|---|
| observation | 由环境给定；算法本身不规定 IMU、地图或图像 |
| action | 可适配连续或离散动作；关节力矩、PD 目标角由机器人任务定义 |
| reward | 环境给定标量；PPO 不自动解决奖励设计 |
| train | 当前策略采样 → 计算回报/优势 → 多轮更新 actor、critic → 再采样 |
| deploy | 通常只需策略前向计算；机器人还需状态估计、限幅、低层执行 |
| sim-to-real | 原算法没有独立解决方案，需其他建模、随机化与部署设计 |

这些接口区分是基于官方文档的教学整理，并非原论文提出一套完整机器人系统。[官方代码及教学入口](https://github.com/openai/spinningup)

## 证据与局限

论文报告了基准任务的经验效果，不能据此推出对任意机器人、奖励或感知输入都收敛。它是 on-policy 方法：每轮主要依靠当前策略新采集的数据；“一批数据用多轮”不等于可以任意复用很久以前的轨迹。裁剪也不等于关节安全约束。

## 与你的感知经验怎样衔接

**调研推断**：先把已有状态估计器当作观测前端，冻结它，再学习控制，是容易解释故障来源的起点。你熟悉的坐标系、时间戳、可观性、延迟，会直接决定策略输入是否可靠。地图精度变好却使行走变差并不矛盾：可能新增延迟，也可能训练时的地图误差分布与部署不符。

## 阅读顺序与复现检查

先补 MDP、回报和 actor–critic，再读本篇和 [F02 GAE](F02_GAE_2015_2016.md)，之后看 [F06 并行训练](F06_Massively_Parallel_2021_2022.md)。第一项练习应是读懂小环境的 rollout 和损失。

复现时检查旧 log-prob 是否固定、优势是否停止梯度、终止和超时是否区分、动作缩放是否一致，并记录 KL、熵、价值误差及任务成功率。本轮没有安装、训练或实机实验；官方教学实现也不能默认代表当代足式框架的全部工程细节。
