# P08｜Perceptive Humanoid Parkour: Chaining Dynamic Human Skills via Motion Matching

> Wu、Huang、Yang 等；arXiv v1 2026-02-17，项目页标 RSS 2026；Unitree G1 人形实机。优先级：前沿选读，先掌握基础后读。证据 A：论文 HTML＋官方项目页。访问：2026-09-29。

## 一分钟总结

PHP 将人类动作先验、技能串接和深度感知结合：先把短动作片段拼成可执行的长序列，训练动作跟踪专家，再蒸馏成统一的视觉学生。它展示了从“看地形后走过去”扩展到“看地形后选择全身接触技能”的路线。[官方项目页](https://php-parkour.github.io/)

## 详细机制与输入输出

| 项目 | 本文设置 |
|---|---|
| 动作数据 | 重定向后的原子技能，通过 motion matching 的特征近邻检索组合 |
| 教师观测 | 动作参考、机体/关节状态及特权地形信息 |
| 学生观测 | 深度图、本体状态、前一动作和速度命令 |
| 动作/奖励 | 关节 PD 目标；跟踪奖励与动作、关节限位、碰撞等正则 |
| 训练/部署 | 专家 RL→DAgger 与 PPO 联合训练学生→机载深度驱动实机 |

加入 PPO 的动机是动作模仿误差相近，不一定意味着最终越障结果相同；动态技能中一次关键发力不足就可能失败。相机建模还涉及外参扰动与延迟，几何和时序校准仍然重要。[论文 HTML：第 III 节](https://arxiv.org/html/2602.15827v1)

项目页展示了越障、攀上高障碍及连续技能，作者还提供浏览器示例；截至访问日，训练代码入口显示“Code (Coming Soon)”。交互示例不等于训练管线已完整开源。[代码发布状态](https://php-parkour.github.io/)

## 与传统感知研究的交点

以下是我们的解释：当脚、手、身体都可能接触环境时，一张地面高度图的表达能力可能不足。感知应回答“哪些表面可接触、从什么方向接近、接触后能否承受动作”，而非只画障碍轮廓。这为局部三维几何、可见性和接触区域预测提供了接口。

同时，动作数据生成不能忽略环境。若动作参考与箱子位置或尺寸不一致，低层控制再强也要面对错误目标。你可以把熟悉的几何配准用于动作与场景对齐，检验参考可行性，再将可行性结果反馈给数据筛选或课程安排。

## 证据边界与阅读次序

这是较新的动态实机工作，不能仅凭视频推出长期无人值守可靠性。它依赖动作库、重定向、专家训练和视觉蒸馏，工程链明显长于基础速度跟踪。论文中的方法比较也受实现和预算影响，不代表动作先验方法普遍压倒其他路线。

它与无动作先验的 [Humanoid Parkour Learning](P06_Humanoid_Parkour_Learning.md) 形成有用对照：前者用动作库降低复杂技能探索难度，后者主要从任务奖励出发。先理解这一区别，再看架构细节，能避免把所有人形 RL 都归为模仿学习。

## 初学者怎样利用这篇

不建议第一项复现就选择高速翻越。可以先固定一个走路或低台阶技能，添加场景几何变化，分析相机视角和接触位置误差造成的失败。传统多视图几何、时空标定、三维接触面估计，都可以在这个小任务中发挥作用。

我们的候选实验是比较“仅深度”“深度＋接触面几何”“深度＋几何及可见性”，在未见障碍姿态和局部遮挡下测试技能启动时机。保持动作库、教师质量和训练预算一致，避免把更优先验误认为更优感知；同时记录任务成功、误接触、动作平滑和计算延迟。这是可研究假设，尚非已证明的新颖性。
