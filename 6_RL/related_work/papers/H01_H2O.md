# H01 · H2O：从人体姿态到实时全身遥操作

- **论文**：Learning Human-to-Humanoid Real-Time Whole-Body Teleoperation，Tairan He、Zhengyi Luo 等。
- **时间 / 平台**：2024-03-07 首发；IROS 2024；Unitree H1，19 维身体关节控制。
- **类别 / 优先级**：RL 动作跟踪、人体重定向、遥操作；P1，读完基础行走后阅读。
- **证据深度**：A；已读 arXiv v1 方法与部署部分、作者项目页和官方仓库说明；未下载论文、未运行代码。访问日期：2026-09-29。

## 一分钟总结

H2O 把“摄像头看见人怎么动”变成“人形机器人能稳定地跟着动”。关键不只是人体姿态估计，而是先把人体动作转到机器人骨架，再用仿真策略筛掉难以实现的动作，最后训练可上实机的 RL 跟踪器。它属于**有人给动作目标的遥操作**，不等于机器人自主理解场景并决定任务。[项目页](https://human2humanoid.com/)

## 详细介绍：问题与方法

人的关节数量、腿长、惯量和驱动力与 H1 不同。运动学上能摆出的姿态，机器人可能在落地时失稳。H2O 的处理链是人体模型拟合、动作重定向、特权跟踪器筛选、实机策略训练。“特权”意味着仿真中可读取真实刚体状态；这种策略适合筛选训练样本，却不能原样上机器人。我们的判断是：筛选器失败也可能来自学习能力不足，因此不能将它视为严格物理可行性证明。[方法](https://arxiv.org/html/2403.04436v1#S4)

| 项目 | 已核验的设计 |
|---|---|
| Observation | 关节位置/速度、根部线速度/角速度、重力方向、上一动作；目标由 8 个关键点的位置、相对误差、速度构成 |
| Action | 19 维关节目标，由 PD 转为关节力矩 |
| Reward | 关节与刚体姿态/速度跟踪，加平滑、滑动、限位等约束 |
| Training | PPO；重定向动作数据；动力学、时延和地形随机化 |
| Deployment | 单目人体姿态提供目标，机器人自身状态反馈闭环跟踪 |

这些定义说明 RL 学的是在动力学约束下执行目标，而非静态的人与机器人关节角对应。[方法与奖励](https://arxiv.org/html/2403.04436v1#S5)

## 证据与局限

作者展示行走、踢球、后跳、挥手等 H1 实机遥操作；官方仓库同时覆盖 H2O 和后续 OmniH2O，阅读配置时必须确认所属工作，不能把后作能力算回 H2O。[项目](https://human2humanoid.com/) · [官方实现](https://github.com/LeCAR-Lab/human2humanoid)

最容易误读的是“只需要 RGB 摄像头”：这指**人体动作输入**。论文实机部署还使用 50 Hz 动捕估计机器人线速度；作者提出可换成视觉/LiDAR 里程计。视频中的扰动恢复也不是覆盖所有场景的稳定性证明。[部署 §VI-B](https://arxiv.org/html/2403.04436v1#S6.SS2)

## 与传统感知的关系

以下是研究建议，不是论文结果。第一，把动捕速度换成 VIO/LIO 或接触辅助状态估计，研究跳跃、脚滑、弱纹理时的估计退化怎样影响跟踪。第二，给人体关键点附带置信度、遮挡标记和时延，而非只给确定坐标。第三，检验重定向是否放大单目尺度误差。应同时记录人体重建误差、机器人跟踪误差、跌倒率及端到端延迟，避免“姿态更准”却“控制更差”。

## 阅读 / 复现重点

先读框架图，再读状态空间和部署接口，最后读 sim-to-data 消融。复现准备先画各坐标系，核对关键点对应和时间戳；固定策略回放不同程度的速度偏差、延迟和丢帧。不要一开始同时改姿态估计、重定向和奖励，否则无法定位改进来源。
