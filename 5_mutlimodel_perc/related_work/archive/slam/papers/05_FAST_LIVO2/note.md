# 05｜FAST-LIVO2

> 范围修订：用户明确不做SLAM。本篇仅保留为初版材料归档，不纳入当前核心阅读、复现或评价。
## 先读总结

FAST-LIVO2 将激光雷达、IMU 和相机组合成一个状态估计系统。相机提供纹理，雷达提供几何，IMU 提供高频运动先验；三者在不同环境中有不同的退化方式。它通过统一地图和顺序状态更新组织这些约束，适合用来理解真正的异构传感器融合。论文中的机器人应用包含无人机等平台，不能直接视为人形验证。对人形而言，最值得借鉴的是如何处理传感器互补，以及标定和同步为何是融合成立的前提。[S1][S2]

## 论文信息与证据

- 全名：FAST-LIVO2: Fast, Direct LiDAR-Inertial-Visual Odometry。
- 作者：Chunran Zheng 等；首次公开：2024，arXiv:2408.14035。
- 类别：三模态里程计与建图；优先级 P1。
- 模态：LiDAR、RGB、IMU；输出：位姿／运动状态与带视觉信息的几何地图。
- 人形关系：**可迁移方法，非直接人形实验**。
- 本轮证据：arXiv v2 HTML 的概述、方法与实验章节浏览，以及官方仓库；不是完整复现或逐公式审计。

## 详细介绍

### 1. 从“两种传感器”到“三种约束”

长走廊可能缺少足够几何变化，纯雷达匹配受到影响；低照度或无纹理场景会使视觉受限。融合的价值在于退化模式不同，但如果所有模态同时失效，数量更多也不会创造可靠信息。

### 2. 论文方法

系统先用 IMU 传播状态，再使用雷达和图像顺序更新误差状态迭代卡尔曼滤波器。统一体素地图同时服务几何匹配与图像块对齐；雷达构造点到平面的约束，视觉利用光度误差。[S1] 这是测量和状态层的融合，不是给彩色点云附上一张图片就算完成。

教学理解：先根据惯性预测“我大概移动到了哪里”，再让新点云对齐既有地图，最后让参考图像块在新图像中对齐。多个约束不断修正同一个状态。直接法减少对显式特征提取的依赖，但仍依赖合理初值和数据关联。

### 3. 哪些前提特别重要

HTML 的状态模型部分明确假定时间偏移已知，传感器刚性连接且外参预先标定。[S1] 因而将相机装在转动的头部、雷达装在躯干时，不能照搬同一套固定外参。关节链误差、结构震动和同步误差，是人形迁移需要单独解决的问题。

### 4. 实验与开源边界

论文覆盖公开数据与实际应用，并比较不同模块的作用。[S1] 官方仓库可核对实现和配套资源入口，但本轮仅阅读说明，没有验证安装、依赖或运行时间。[S2] 本笔记不将某个平台上的实时表现推广成所有嵌入式硬件的保证。

读实验时应同时看精度、失败情况与计算成本，还应区分“建图结果视觉上漂亮”和“位姿误差可靠地下降”。没有真值的渲染展示只能补充定性证据。

### 5. 对研究选题的启发

可以先问：遮挡相机时，几何定位是否仍稳定？雷达几何退化时，视觉贡献多少？人为引入时间偏移时，哪种残差先异常？这些可证伪问题比“再加一种模态能否涨点”更适合作为初期实验。

## 初学者怎么学

先读 VINS-Mono，补点云、点到平面距离、体素地图和滤波。FAST-LIO2 可作为两模态前序阅读，但本目录不把它另计为详解条目。

**小练习（尚未执行）：**画出 IMU、雷达点和相机帧的时间轴；对一帧点云施加旋转／平移，观察点到平面残差。后续再做相机丢帧与延迟敏感性实验，记录完整扰动条件。

阅读问题：顺序更新为什么需要一致的状态定义？图像“有内容”是否意味着对定位“有约束”？不同时刻测得的点为何要考虑运动补偿？
