# 07｜CLIP：视觉与语言共享语义空间

## 先读总结

CLIP 把图像和文字分别编码成向量，再通过图文配对训练，让内容相符的向量靠近。这样，识别类别不必总是写死在分类器里，而可以由“杯子”“椅子”等文字描述临时指定。对人形机器人研究，它最重要的作用是提供可复用的语义表示，后续 LSeg、OpenScene、ConceptFusion 等工作再把这种表示落到像素或三维地图中。CLIP 本身主要回答图像与文字是否匹配，不直接输出物体三维位置、机器人状态或控制动作；零样本也不等于从未见过相关概念。[论文摘要](https://arxiv.org/abs/2103.00020)

## 问题、输入输出与融合层级

传统分类器通常为固定类别各设一个输出通道；新增概念往往需要调整训练任务。CLIP 用语言表示类别，使图像分类可以改写为“这些文本描述中，哪个与图像最匹配”。训练输入是配对图像与文本；使用时可以输入图像和候选描述，输出相似度或排序。图像和文字在各自编码器后进入共同空间，因此这里是**表示对齐与特征级匹配**，不是相机、IMU、触觉的原始信号融合。[官方实现](https://github.com/openai/CLIP)

## 方法怎么理解

1. 图像编码器把图片转成向量，文本编码器把描述转成同维度向量。向量不是自然语言句子，也不是物体坐标。
2. 训练时把同一批次中正确配对的图文作为正例，其他配对作为对比对象，学习匹配关系。
3. 推理时先写候选类别的文字提示，再计算图文向量相似度，按分数选类别。官方 README 展示了分别调用图像、文本编码器以及归一化后匹配的方式。

**调研者解释：**余弦相似度可以理解成比较两个向量的方向；归一化后，点积主要表达方向是否接近。若图像向量为 (v)、文本向量为 (t)，则 (s=v^Tt/(\|v\|\|t\|))。这个分数表达语义匹配程度，不等于经过校准的“物体真实存在概率”。候选集合改变后，softmax 输出也会改变，因此不能把一个很高的相对分数直接作为机器人执行动作的依据。

## 实验支持什么，不支持什么

作者在多个视觉数据集上考察迁移与零样本分类，支持“图文预训练可产生通用视觉表示”这一结论；本笔记不摘录单个准确率，避免丢失具体模型和数据设置。[ICML 官方记录](https://proceedings.mlr.press/v139/radford21a.html)

这些实验不是人形机器人闭环测试，也没有证明单张图像的匹配向量足以判断可抓取位置、接触稳定性或行走安全。论文中的零样本，主要指下游任务不依赖该任务专门的监督训练；不能据此证明互联网预训练中不存在同名概念或相似图像。

## 局限与人形机器人中的位置

**调研者解读：**全图表示容易把前景与背景混在一起。桌上有两个杯子时，“cup”分数不能告诉机器人该抓哪个，更不能给出手指接触点。头部运动、遮挡、相机视角变化、专业工具和中文提示等因素也需要在自己的应用中验证。合理接口是“图像/区域 → 语义向量 → 地图检索或目标候选”，之后仍需要定位、实例分割和几何模块。

**待验证假设：**在未来实验中，将整图替换为物体裁剪，可能降低背景干扰，但也可能丢掉有用上下文；应同时保留两种设置，不能仅展示成功案例。

## 初学先修、小练习与阅读问题

先修：Python 张量、向量点积、softmax、训练集/测试集、监督学习与对比学习。不必一开始推导 Transformer。

**未执行的小练习：**先用纸笔画一个三张图片、三句描述的相似度矩阵，标出对角线正例；再为同一杯子写“cup”“a photo of a cup”“a red cup”三个提示，说明它们可能改变什么。后续获准准备环境后，可用自己拍摄的少量图片运行预训练推理，保存全部分数、错误和提示版本；无需从头训练 CLIP。

阅读时回答：零样本针对哪一阶段？输出是图像级还是像素级？提示词与候选集合如何影响结论？下一篇 LSeg 为增加空间定位能力引入了什么训练？
