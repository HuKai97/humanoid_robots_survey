# 19｜Octo: An Open-Source Generalist Robot Policy

## 先读总结

Octo 是通用机器人操作策略，不是单独的感知模型。把它放进这份调研，是为了看清感知表征最终如何连接动作，以及新传感器怎样接入已有策略。它把语言或目标图像、观测历史转换成 token，由 Transformer 处理，再用扩散动作头输出连续动作。值得关注的是其可扩展接口和带力/力矩输入的微调例子。初学时应先读输入输出与适配实验，不急于训练完整模型，也不能把“支持新输入”误读成任意触觉传感器即插即用。[项目页](https://octo-models.github.io/)

## 输入、输出与融合

模型将任务条件与不同观测编码成 token；缺失观测用掩码处理，读出 token 聚合信息，扩散动作头生成动作片段。适配时可加入新的观测编码器或动作头，并利用预训练主干。它属于特征/token 层整合，而输出属于策略层。[方法 §III-A](https://arxiv.org/html/2405.12213v2)

**调研者解读：**感知研究可以把 Octo 当作下游使用者：比较“接入哪一种表征后任务更稳定”。但动作成功率同时受数据、控制器、动作空间和感知影响，不能把所有提升归因于融合模块。另外，论文中的 multi-modal action distribution 指多峰动作分布，不是说输出包含多种传感器模态。

## 关键实验与证据边界

作者的插孔微调例子使用侧面相机、末端运动信息和力/力矩反馈，说明架构能够适配新增观测；这是接触感知与通用策略相接的具体证据。项目及仓库公开了模型和微调入口。[实验设置及附录](https://arxiv.org/html/2405.12213v2)、[官方代码](https://github.com/octo-models/octo)

这不等于原始预训练模型已具有通用高分辨率触觉理解，也未证明其能控制人形机器人的平衡与全身接触。**待核验：**若将来采用，需要确认当前 checkpoint 的输入规范、动作归一化和平台约束；本轮没有在用户硬件上验证推理耗时。arXiv 版本与早期项目材料的实验平台数量可能不同，因此这里不拼接版本数字。

## 局限与对人形感知的启发

**调研者解读：**灵活接口解决“能否接入”，不能独自解决“新增模态是否有用”。人形机器人往往有更多自由度、移动相机与更严苛的时延；若直接把手部策略输出接到全身执行器，会跳过必要的控制设计。更合理的研究边界是选一个接触任务，冻结动作定义，比较视觉、本体感觉、视觉加力等输入，再检查缺失或延迟传感器下的退化。

## 先修与可执行小练习

先修：模仿学习、Transformer、掩码、扩散模型基本概念、动作坐标与归一化。

**拟练习，尚未执行：**设计一个新增腕力观测的接口说明，列出维度、坐标系、单位、采样时间、历史窗口和缺失掩码；画出它进入 token 编码器到动作头的路径。再写三种必须阻止的错误：把世界系与工具系混用、把未来力放进当前历史、把未测量值当真零值。无需加载模型。

阅读问题：动作片段多长会影响接触响应？预训练时没有的新通道如何初始化？改观测和改动作是否使用相同数据量？策略变化能否通过感知独立指标解释？这些决定后续实验是否可归因。
