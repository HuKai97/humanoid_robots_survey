# 29｜PointNet++：点云编码的入门基础

## 先读总结

PointNet++ 解决的是怎样让神经网络理解无序点云及其局部几何。它从点集选择中心，在不同半径内寻找邻居，用共享网络提取局部形状，再逐层汇聚成较大范围的表示。多尺度设计与训练时随机丢点，使网络能够应对点云疏密变化。它是理解 LiDAR 或 RGB-D 点云编码器的基础，原论文本身既不是多传感器融合，也不是强化学习：主要用类别或逐点标签训练分类、分割模型。将其接到视觉—本体策略中是后续可选设计，不能把这种可能性写成原文已证明的人形机器人能力。[摘要](https://arxiv.org/abs/1706.02413)

## 问题与输入输出

图像像素有固定网格邻居，点云却没有可靠的存储顺序。同一组点打乱排列，物体身份不应改变；但点之间的距离和局部形状很重要。早期 PointNet 善于汇总整个点集，PointNet++ 增加分层局部结构。输入通常是 (N\times3) 坐标，也可带法向等逐点属性；输出可为整体类别、逐点类别，或中间特征。[作者项目页](https://stanford.edu/~rqi/pointnet2/)

**训练与部署模态：**训练使用点坐标、所选属性及类别/分割标签；推理使用同样定义的点属性，不需要真实标签。原文 ScanNet 对照明确去除了 RGB；因此不能仅因数据来自 RGB-D 扫描，就说该实验融合了 RGB 与深度。点云是表示，来源可以是 LiDAR、深度相机或模型采样，来源变化仍会产生分布差异。[论文 HTML](https://arxiv.org/html/1706.02413v1#S4)

## 方法逐步理解

1. **采样中心。** 最远点采样逐次选取离已选集合较远的点，让有限中心覆盖更多空间。
2. **构造邻域。** 在中心周围按距离寻找点。球查询固定物理半径，k 近邻固定邻居数量，两者面对稀疏区域时含义不同。
3. **局部编码。** 将邻居坐标变为相对中心的位置，用小型 PointNet 和对称汇聚生成局部向量。
4. **扩大范围。** 重复上述过程，逐层减少点数、扩大覆盖区域；分割任务再通过插值和跳跃连接把特征传回原始点。
5. **处理密度变化。** 多尺度/多分辨率分组结合随机丢点训练，使网络有机会利用粗细不同的结构。[HTML 方法节](https://arxiv.org/html/1706.02413v1#S3)

**调研者解释：**多尺度特征汇聚不是多传感器融合。它结合的是同一输入在不同空间范围内的信息。对点顺序不敏感，也不等于对任意旋转、坐标尺度、外参误差自动不敏感。

## 监督信号与 RL 边界

原文由分类/分割任务标签提供学习目标，没有动作、奖励、环境交互或策略优化。随机丢点属于数据增强，不是强化学习探索；采样点也不是由奖励训练的主动传感策略。

**调研者迁移设想：**未来可让点云编码输出环境向量，再与 IMU、关节位置/速度特征组合送入 actor。编码器可以先受监督预训练，也可以随策略损失更新，两种设置必须分开记录。这是候选方案，原论文没有比较它们对人形行走或操作的效果。

## 实验、限制与迁移条件

作者用物体分类、室内场景标注和采样密度变化验证点集表示；这些证据支持几何编码能力，不证明控制稳定性。官方实现可访问，但包含旧版框架与自定义算子，不能把“有代码”理解为当前环境已经可以直接复现。[官方代码](https://github.com/charlesq34/pointnet2)

**调研者解读：**人形点云常包含自身手臂、近距离截断、运动造成的缺测和稀疏落脚边缘。按整物体归一化到单位球的分类预处理，会丢失控制所需的真实尺寸；不能原封不动用于判断台阶高度。也应检查采样是否抹掉细小把手或支撑边缘，并记录编码时延是否满足策略频率。

## 先修、小练习与阅读问题

先修：向量距离、点云坐标系、MLP、最大池化、分类与分割。暂时不需要 SLAM。

**未执行练习：**手画一组稠密和稀疏混合的二维点，分别用固定半径和固定邻居数分组；删去台阶边缘的一半点，检查哪些局部形状还可辨识。未来做最小程序时，用自造点集验证打乱顺序不改变汇聚结果，并保留真实尺度。

阅读问题：哪个环节保证集合性质？稀疏区域的大邻域会混入什么？分类特征与落脚几何需要相同的不变性吗？接入 RL 后，怎样判断收益来自点云信息而非参数增加？
