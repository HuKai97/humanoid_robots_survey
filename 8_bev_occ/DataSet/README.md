# 数据目录约定

**当前只有说明文档，没有下载数据、标签、权重或论文。** 候选数据及获取状态见 [dataset.md](../dataset.md)。本目录目前只用于数据准备记录；所有下述结构都是未来建议，尚未创建或执行。

## 后续建议布局

```text
DataSet/
  README.md
  <dataset_name>/<version>/
    manifest.md        # 来源、版本、使用条件与处理状态
    splits/            # 冻结的场景/轨迹列表
    calibration/       # 内外参、畸变与时间同步说明
    label_mapping/     # 原始ID、训练ID、unknown/ignore约定
    checks/            # 少量样本投影与掩码检查记录
```

大体量原始数据可保存在指定数据盘，用配置记录绝对路径；不要把别人机器上的示例路径当本地已存在目录。原始数据与派生标签分开命名，例如 `nuscenes` 与 `occ3d_nuscenes`，避免覆盖同帧的另一套标签。

## 每个 manifest 至少记录

| 字段 | 必填内容 |
|---|---|
| provenance | 官方来源、核验/获取日期、原始版本、派生标签版本、处理脚本提交 |
| access_status | 未获取 / 已申请 / 已下载 / 已校验 / 已完成样本检查，按实际更新 |
| sensors_and_inputs | 采集模态、训练监督、推理输入三列；参考位姿或在线位姿 |
| geometry | 相机模型、单位、坐标链、网格原点/范围/尺寸、时间戳约定 |
| labels_and_masks | 原始类表、训练映射、free/unknown/ignore、损失与评价掩码 |
| split | 场景/轨迹清单与校验和，相关扫描是否同组，仿真/真实比例 |
| checks | 文件数量与完整性、投影叠图、细障碍/动态伪影、已知缺失项 |

新建自采数据时，应先用少量片段验证格式与标定，再批量处理。相邻帧拆分会产生泄漏，预计算完整场景地图也可能把未来观测带入输入。重新映射标签或修改 mask 后应产生新版本，并同步修改实验配置。

本项目传感器尚未确定，不预设六相机、双目、LiDAR 或深度相机一定存在。未经实际获取和验证，不在 manifest 里填写虚构容量、哈希、样本数或“已通过”。
