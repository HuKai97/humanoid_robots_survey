# 从轮式感知进入人形 BEV / OCC：先读这份

你的已有经验很有价值：标定、坐标变换、点云处理、SLAM、代价地图和时序同步，都是这条路线的底座。新增的学习重心是图像到三维的特征构建、不可见区域的学习式补全、三维表征的效率，以及地图如何服务全身运动。

## 先建立五个判断

1. **BEV 是表征视角，不等于一个任务。** 它可以服务检测、地图分割、预测，也可作为解码三维占用的中间特征。俯视图上的一个格子可以有很多特征通道，并不必然只存一个二值占用。
2. **Occupancy mapping 与 occupancy prediction 有交集，也有不同假设。** 前者典型做法是累积传感器证据，后者可能用学习先验推断未观测区域。讨论任何论文前先查输出、监督和可见性定义。
3. **占据、自由、未知必须分清。** 未被表面点命中的体素不自动成为自由空间；观测射线在有效测距前的区域才有自由证据。学习模型的高置信度也不是传感器观测证据。
4. **人形的感知问题包含身体高度和姿态。** 地面可通行不保证膝盖、躯干、头部和手臂可通过；无碰撞也不保证足底可稳定支撑。需要结合三维几何、机器人形状、接触与运动学约束。
5. **先建立可解释 baseline，再评估学习式增益。** 对有深度/激光的系统，先建立测量驱动的地图参照，再问语义、补全和记忆各提升了什么。推荐次序来自本调研的工程判断，非某篇论文的实验结论。

这些区分可对照 [OctoMap](papers/octomap/README.md)、[LSS](papers/lift_splat_shoot/README.md)、[MonoScene](papers/monoscene/README.md)、[EmbodiedOcc](papers/embodiedocc/README.md) 阅读。

## 第一次学习按这个顺序

| 顺序 | 阅读 | 带着什么问题 |
|---|---|---|
| 1 | [领域地图](SURVEY.md) + [术语表](GLOSSARY.md) | 哪些是地图，哪些是特征，哪些是任务？ |
| 2 | OctoMap → Voxblox → nvblox | 三维证据、表面、碰撞距离如何表达？ |
| 3 | LSS → BEVDepth → BEVFormer | 图像信息怎么落到有度量单位的空间？ |
| 4 | MonoScene → TPVFormer → SurroundOcc | 深度歧义、高度信息、占用监督怎么处理？ |
| 5 | EmbodiedScan → EmbodiedOcc → Humanoid Occupancy | 室内、在线、人形的数据与坐标系改变了什么？ |
| 6 | [完整论文索引](PAPER_INDEX.md) 的进阶分支 | 按效率、行走、语义操作、预测深入 |

不需要先读完全部论文才能动手。完成第 3 步，就可以做投影、坐标系和时序对齐的小实验；完整训练计划见 [学习路线](LEARNING_ROADMAP.md)。

## 读每篇论文时先回答

- 推理时实际输入什么？是否依赖位姿、深度模型或历史缓存？
- 输出坐标系、空间范围、体素大小和类别是什么？
- 深度/激光是训练监督、标注来源，还是推理传感器？
- 没看到、看不到、已经看到但分错，在损失和评测中分别怎么处理？
- “实时”是否只测网络？传感器同步、深度、位姿、融合、地图发布是否计入？
- 是否有机器人闭环实验？“embodied”或“robot”出现在标题里并不回答这个问题。

## 当前建议

先并行理解两条路线：**测量驱动的局部三维地图**与**学习驱动的语义占用**。最终系统可以组合二者，但需要通过对照实验验证。现阶段传感器和平台未定，因此不承诺某种网络、分辨率或模型能满足你的上机要求。
