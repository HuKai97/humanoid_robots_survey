# 方法比较：按照问题选择，而不是跨表格排名

以下是基于 [逐篇来源](PAPER_INDEX.md) 的综合分析。不同论文的输入、标签、范围、可见性和评价不一致，因此不制作统一精度/FPS总榜。

| 路线 | 典型输入与先验 | 表示/输出 | 主要收益 | 人形迁移优先检查 | 代表 |
|---|---|---|---|---|---|
| 概率占用融合 | 测距、位姿、传感器模型 | 三维占用信念 | 证据更新、未知区可区分 | 位姿误差、自体点、动态残影 | OctoMap |
| TSDF/ESDF | 深度或点云、位姿 | 表面/距离场 | 规划距离查询 | 细障碍、未知策略、地图新鲜度 | Voxblox、nvblox |
| 高程图 | 点云、姿态 | 2.5D地形 | 足下局部几何紧凑 | 单层限制、台阶边缘、支撑区域 | Elevation Mapping GPU |
| 显式深度提升 | 标定图像、预测深度分布 | BEV特征 | 几何链路清楚 | 深度误差、外参、近场分辨率 | LSS、BEVDet、BEVDepth |
| 几何引导查询 | 多视图与标定、可选历史 | BEV/三维特征 | 空间和时序关联 | 历史对齐、头部运动、总延迟 | BEVFormer、SurroundOcc |
| BEV多传感器融合 | RGB与其他传感器 | 共享BEV、多任务输出 | 互补信息 | 模态缺失、同步、融合对齐 | BEVFusion、Simple-BEV |
| 视觉三维补全 | RGB或深度，训练三维标签 | 稠密语义体素 | 推断遮挡结构 | 可见/推断分离、域外失败 | SSCNet、MonoScene、VoxFormer |
| 多平面压缩 | 多视图标定图像 | 平面特征再解码体素 | 减少中间表示规模 | 多层结构、插值、高度坐标 | TPVFormer、SliceOcc |

## 表示、状态估计与任务接口分开比较

“Gaussian 比 voxel 好”通常过于宽泛。应把问题拆成：相同内存能表示多少细节；相同传感器能估计多准确；地图更新如何对付错误；下游查询要多快。一个表示可以重建很好，却未必具备便于规划的查询接口；一个地图查询快，也可能缺少语义补全。

“单目 vs RGB-D”的比较也应拆开。推理模态、训练监督与预训练数据是三个维度。若 RGB 模型用额外的深度教师，不能只按传感器数量判断学习成本；若 RGB-D 方法直接测得几何，也不应抹掉其输入优势。

## 按当前目标筛选

| 当前最想解决的问题 | 优先读/试 | 暂时不必优先 |
|---|---|---|
| 建立能用的局部几何地图 | OctoMap / Voxblox / nvblox | 世界模型大规模预训练 |
| 搞懂视觉到BEV | LSS、Simple-BEV、BEVDepth、BEVFormer | 一开始叠复杂多任务头 |
| 建立室内语义OCC baseline | EmbodiedScan、MonoScene、EmbodiedOcc | 不同基准的数字排行榜 |
| 面向人形看全身空间 | Humanoid Occupancy、Humanoid-OmniOcc，配合几何地图 | 只拿二维地面掩码判断可通过 |
| 足下地形与落脚 | 高程建图，结合身体碰撞和运动学 | 将floor语义直接当稳定支撑 |
| 语言目标与操作语义 | VLMaps、ConceptGraphs | 用语言匹配分数代替精确碰撞 |
| 延迟/显存瓶颈 | Simple-BEV、SparseOcc、GaussianFormer；先profiling | 未测瓶颈就更换全部架构 |
| 长期在线探索 | EmbodiedOcc系列、GEM-Occ | 忽略定位漂移的无限累积 |
| 动态/主动观察研究 | FIERY、OccWorld、RoboOccWorld | 把视角变化等同于物理动态 |

最后一列是学习顺序建议，不是排除这些研究方向。硬件和任务确定后应重排优先级。
