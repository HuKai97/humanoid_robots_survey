# SurroundOcc：环视图像直接形成三维体积

## 一分钟总结

**定位：理解稠密 3D volume 路线及其标签构造。** SurroundOcc 用多相机图像特征直接查询三维体积，通过多尺度三维卷积逐步产生语义占据；同时给出从多帧 LiDAR 生成稠密监督的流程。它是比较 BEV、TPV、稀疏体素和高斯表示时应掌握的清晰基线。[论文原始入口](https://arxiv.org/abs/2303.09551)

## 输入输出与方法步骤

输入为标定的环视多相机图像；输出为当前空间的三维语义体素。图像主干抽取多尺度特征后，三维 volume queries 投影到图像，使用二维到三维的空间注意力融合不同视角；随后用三维卷积上采样并融合多尺度特征，每个尺度施加占据监督。[方法 §3](https://arxiv.org/html/2303.09551#S3)

标签生成是另一条离线流水线：对静态场景和动态物体分别对齐并聚合多帧点云，用 Poisson Reconstruction 增密表面，再体素化、赋予邻近语义。它解决的是监督稀疏，不意味着推理阶段使用 LiDAR。[标签流程 §4](https://arxiv.org/html/2303.09551)

## 关键概念解释

**BEV query** 主要落在水平网格；**volume query** 同时有 x/y/z 索引，能在不同高度保留不同特征。桌面和桌下空隙投影到同一水平位置，三维体积能够显式区分二者，这是人形全身空间理解的基础。

**多尺度监督** 让粗分辨率先学大结构、细分辨率再恢复细节，但不会自动保证细障碍可见。**Poisson 重建** 利用表面连续性先验填孔；“连续而好看”的表面并不等于没有标签误差，尤其对薄结构、运动边界和真实孔洞应回查观测。

## 实验应看什么

在原文中重点看多尺度设计、空间注意力、稠密标签的消融和模型效率分析。官方仓库说明其数据与训练配置；复现时要核对使用的标签来源与评估协议，不能用 Occ3D 的 mask 跑出的结果冒充原协议成绩。[官方 README](https://github.com/weiyithu/SurroundOcc)

对自己的实验，应固定图像骨干与 voxel size，比较 BEV 解码与完整三维 volume 是否确实提升垂直结构。建议单列悬空横杆、桌下通道、楼梯立面、细腿家具四类场景；同时记录 GPU 峰值显存及端到端延迟，因为稠密特征的代价会随空间分辨率快速增加。

## 局限与人形迁移分析（本调研推断）

它保留高度信息，但训练所面对的车载环视视角仍然与人形有差别。头部双目通常没有同时覆盖背后或脚边；将两张前向图像塞进环视模型并不会生成真实全景证据。对视场外可以做补全，但应保留 unknown 与预测来源标签。

如果人形有胸部、头部多相机，空间注意力可作为跨视角融合基线，前提是每帧使用真实关节状态求外参，并处理不同相机曝光时间和自遮挡。工程上适合先做有限范围的局部体积，降低计算开销；远处可以保留更粗的表示，足边与手部工作区再细化。具体分辨率应由传感器误差和下游动作容差决定，不直接照抄车载配置。

模型输出单次预测体积，不负责 SLAM 回环、地图衰减和动态物体跟踪。长期建图仍需独立的状态融合逻辑；使用多帧生成离线标签也不等于在线模型已经具有这些能力。

## 阅读与复现检查点

- 能画清“图像多尺度 → 三维查询 → 3D 特征融合 → 逐尺度监督”。
- 核对数据准备时动态物体的对象坐标变换，避免把运动拖影当作占据真值。
- 先画三维体素投影到各相机的可见区域，再核对空类与无效区域。
- 记录所有相机的内参、每时刻外参、图像增强矩阵及体素原点；逐项关闭增强做首轮调试。
- 与 [OccFormer](../occformer/README.md) 对照三维编码方法，与 [GaussianFormer](../gaussianformer/README.md) 比较表示资源分配。
