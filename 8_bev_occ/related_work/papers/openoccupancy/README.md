# OpenOccupancy：理解占用标注与多模态基准

## 一分钟总结

这篇的核心学习价值是：好的 OCC 模型依赖怎样的三维真值。稀疏激光叠帧不自然变成完美稠密占用，标签生成、动态伪影和人工清理都会改变训练与评价。它适合与 Occ3D 对照读，理解“同样使用 nuScenes”为什么仍可能不是同一个任务。

## 元数据与证据

- 标题：**OpenOccupancy: A Large Scale Benchmark for Surrounding Semantic Occupancy Perception**。
- Xiaofeng Wang 等，ICCV 2023；[arXiv 原始记录](https://arxiv.org/abs/2303.03991)。
- [官方仓库](https://github.com/JeffWang987/OpenOccupancy)，已查 [数据准备和类表](https://github.com/JeffWang987/OpenOccupancy/blob/main/docs/prepare_data.md)。
- 核验日期：2026-09-29。阅读层级：摘要、官方仓库和数据文档；本次 HTML 正文访问失败，未作全文逐公式复核。以下详细介绍限于已核验的框架与教学分析。代码/配置目录可见，未运行。

## 任务和输入输出

基准扩展 nuScenes 的环视三维语义占用标注，并建立相机、激光、多模态方法。论文引入 Augmenting And Purifying（AAP）标注流程和从粗到细的 Cascade Occupancy Network（CONet）。[原始摘要](https://arxiv.org/abs/2303.03991)

## 方法怎么理解

1. **数据侧：补充稠密程度与清理错误。** 累积点云会遗漏未采样表面，也可能留下运动物体伪影。AAP 是围绕标签质量的关键贡献，不能把网络推测得到的标注当无误差的测量。
2. **模型侧：先粗后细。** CONet 用级联方式细化占用预测。学习时先理解它如何分配计算，再去核对具体模块；本次不对未复核的模块公式作细节断言。
3. **工程侧：标签与配置必须对应。** 官方文档明确区分已弃用的 v0.0 与 v0.1，并描述动态伪影改善。它还说明原始噪声标签与训练 empty 标签的处理，直接提醒读者不能照搬原始 ID。[官方数据文档](https://github.com/JeffWang987/OpenOccupancy/blob/main/docs/prepare_data.md)

## 实验该怎么看

比较时记录传感器输入、标签版本、空间范围、voxel size、free/ignore 与模型输入历史长度。论文自述的相对提升不等于 mIoU 增加了同样数量的百分点，也不能直接跨到 Occ3D 排行。还应区分激光用来制备标签，和推理时真正给模型激光输入。

## 局限与面向人形的迁移分析

**本调研分析：** 直接复制道路地图范围到人形室内未必合理；应保留数据标注思想，重新设计近场细节。椅腿、台阶、桌下空间尤其容易受体素化与标签缺失影响。若评价标签漏掉了细障碍，模型把它判成自由也可能不受惩罚，最终指标无法反映真正的避碰能力。

对于你已有的点云背景，最有价值的练习是画出一条射线：命中之前有什么证据、命中之后哪些位置只是未知、相邻帧的新观测怎样改变这一判断。然后检查数据生成脚本与损失 mask 是否保留这一区别。

## 阅读与复现检查点

- 与 [Occ3D](../occ3d/README.md) 对照写两列：标签来源、可见性规则、类别、范围和精度。
- 从官方代码确认 empty/ignore 的真实映射，不根据 RGB 可视化猜标签。
- 可视化动态物体附近以及远距离的标注错误。
- 若要复现 CONet，需要进一步在线读正文并核对配置；本次不声称已完成该步骤。
