## 一分钟总结

BEVFusion 先把各传感器特征分别转到同一 BEV 空间，再做融合和多任务预测。它的重要问题意识是：只在稀疏 LiDAR 点上附着图像特征，会丢掉大量相机语义信息；统一空间应兼顾各模态的优势。另一个贡献是将视角转换的计算瓶颈作为系统问题处理。[MIT 项目页](https://hanlab.mit.edu/projects/bevfusion)

## 任务、输入和输出

主要输入是多相机图像与 LiDAR 点云；各自编码后形成公共 BEV 特征，再输出三维检测或 BEV 地图分割。它提供的是多模态特征接口，不直接保证任意三维体素的占据、可观测性或距离场。[正文 §III](https://arxiv.org/html/2205.13542)

## 方法拆解

1. 使用模态专属编码器，让点云与图像保留各自合适的特征提取方式。
2. 把各模态变到一致 BEV 网格，随后由卷积式 BEV 编码器融合。
3. 利用预计算与区间归约优化 BEV pooling。
4. 在共享空间上连接任务头，评估检测与分割。[正文 §III](https://arxiv.org/html/2205.13542)

对传统融合经验的连接：后融合通常组合检测结果，中间特征融合则在信息尚未被压成框或类别前交互。“坐标一致”只是必要条件，相机和 LiDAR 对同一格仍可能具有不同视场、遮挡和延迟。卷积能吸收一定局部偏差，但不应成为掩盖同步或标定问题的理由。高效 pooling 则类似点云栅格化的工程优化：确定哪些元素属于同一格，再减少重复索引和归约开销。

## 实验应关注的证据

作者项目报告检测和分割两类收益；公开仓库列出 camera-only、LiDAR-only 与 fusion 配置，也区分测试时增强和不同计算量的模型。应在同一输入范围、骨干、训练设置下考察每个传感器贡献，并把 pooling 局部加速与整个系统加速分开理解。[项目页](https://hanlab.mit.edu/projects/bevfusion)、[官方模型表](https://github.com/mit-han-lab/bevfusion)

本笔记不抄用网页上的排行榜数字作为当前性能结论；这些是历史论文配置结果，也不能与不同数据划分的占据 mIoU 直接比较。

## 局限与对人形机器人的迁移价值（分析）

人形机器人可借鉴“统一坐标与任务接口”，将 RGB、深度、稀疏点云分别编码。传感器选型应围绕近场盲区与操作需求：车载 LiDAR 环绕覆盖并不等于头部深度相机能覆盖身体附近。手臂遮挡、低头与转头导致不同模态有效范围变化，融合时应提供可靠性或有效性信息，并测试单模态失效。

预计算的性能收益依赖哪些几何量保持不变。若相机装在转动头部，映射到机身或重力坐标系的对应关系会更新，不能不加检查地复用固定车载 lookup。可将相机内部成像几何与每帧外部变换拆开，分别评估能缓存的部分；这是一项工程设计假设，需实际 profiling 验证。

更根本的限制是二维共享平面可能把同一水平位置的地面、桌板与高处悬障混合。导航任务可受益于共享 BEV，手臂与全身避碰则宜进一步使用三维占据或距离场，并保留来自直接量测与模型补全的差别。

## 阅读与复现检查点

- 明确每个模态的时间戳、参考系、网格边界、有效观测区域，检查边界格是否一致。
- 分别测图像编码、视角变换、点云编码、融合及输出头延迟，避免只优化不是瓶颈的部分。
- 加入相机遮挡、深度失效、传感器延迟与外参扰动的分层测试。
- 仓库中部署示例的帧率只对其模型、设备与输入配置成立；本次未测试机载兼容性。
- 与 [Simple-BEV](../simple_bev/README.md) 配对阅读，理解复杂融合结构和公平训练对照之间的关系。
