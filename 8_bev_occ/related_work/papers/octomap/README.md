# OctoMap：从轮式占据栅格走向全身三维空间

## 元数据与证据

- **原题**：OctoMap: An Efficient Probabilistic 3D Mapping Framework Based on Octrees。
- **作者**：Armin Hornung、Kai M. Wurm、Maren Bennewitz、Cyrill Stachniss、Wolfram Burgard。
- **发表**：Autonomous Robots，2013；DOI `10.1007/s10514-012-9321-0`。
- **原始来源**：[论文 DOI](https://doi.org/10.1007/s10514-012-9321-0)、[作者项目页](https://octomap.github.io/)、[官方代码](https://github.com/OctoMap/octomap)。
- **证据阅读级别**：项目说明、官方仓库与元数据已核验；未逐页精读论文、未运行代码。未下载PDF/source。核验日期：2026-09-29。
- **定位 / 优先级**：概率几何建图基础，P0。它属于观测融合，不是学习型语义场景补全。

## 一分钟总结

你已有轮式机器人背景，最值得从 OctoMap 带走的是：保留空闲、占用、未知的区别，再用八叉树控制三维地图内存。同一平面位置可以保存桌面、桌下空间和横梁等不同高度结构，因此它适合用来理解人形全身碰撞地图。它不猜测遮挡后的完整物体，不给语义，也不直接判断足底能否稳定支撑。[项目说明](https://octomap.github.io/)

## 输入与输出

输入为带位姿的距离观测/点云，还需要射线起点；输出为可增量更新的八叉树占据地图。点云给表面采样，而射线更新还提供观测到的自由空间。占用概率反映融合证据，不能直接当作踩上去摔倒的概率。[官方仓库](https://github.com/OctoMap/octomap)

## 方法详解

作为基础原理解释，可令体素 log-odds 为 `l=log(p/(1-p))`。每次观测提供增量证据，累积时扣除先验，并以阈值限制过度置信。测量端点增加占用证据，传感器到端点之间增加自由证据；端点后方没有被证明为空。具体概率和最大量程必须看实际配置。

八叉树不断将空间八分，在细节区保留较细节点，在状态一致区域合并子节点。这种空间组织使地图无需始终为整个大立方体分配稠密数组。它仍然依赖上游位姿：若头部摆动没纳入变换，同一面墙会融合成厚墙；概率更新无法修复系统性时间同步错误。这里的公式和误差例子是通用原理讲解，不代表本次已复核论文每个实现细节。

## 实验应该怎样读

原工作的核心证据是表达、更新效率和内存，不能解释成人形行走成功率。[作者项目页](https://octomap.github.io/) 阅读时记录分辨率、扫描范围、射线数量、地图规模、CPU和阈值。复现时建议额外记录细杆漏检、自由空间误判、地图延迟、障碍移除后的残留时间；这些是本调研提出的工程指标。

## 局限与人形迁移判断

**碰撞**：可以给脚、膝、躯干、手臂与搬运物体提供三维查询，但还需要机器人几何和连续运动碰撞检测。**落脚**：应另外计算表面法向、粗糙度和足底支撑面积；有占用不等于可接触。**动态**：旧证据会残留，应研究时间衰减与局部滚动地图。**学习补全**：以后接入OCC网络时，应分别保存观测证据和模型推断，避免把未知区的预测空闲直接当作实测安全。

这些判断说明三维占据并非二维costmap增加一个高度维就结束了。轮式系统常可近似使用固定水平轮廓，人形需要随关节姿态改变的全身占据；地图本身不包含这一运动学信息。可先在一个离线桌子场景验证多高度碰撞，再对接步态控制。
