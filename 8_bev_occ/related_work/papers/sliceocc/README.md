# SliceOcc：用高度切片保留室内三维结构

## 一分钟总结

它针对室内多层、密集、遮挡重的结构，用沿高度划分的切片和平面对来构建三维特征。适合回答你可能有的问题：“普通 BEV 把高度压缩以后，桌上、桌下与柜内空间怎样区分？”它是空间表征方法，不是完整在线地图维护系统。

## 元数据与证据

- 标题：**SliceOcc: Indoor 3D Semantic Occupancy Prediction with Vertical Slice Representation**。
- Jianing Li 等，arXiv 2025；本次未确认正式录用信息，按预印本记录。
- [论文记录](https://arxiv.org/abs/2501.16684)、[已读 HTML v1](https://arxiv.org/html/2501.16684v1)、[作者指定仓库](https://github.com/NorthSummer/SliceOcc)。
- 核验日期：2026-09-29。已阅读方法、实验设置和对比表；仓库可见一个 SliceOcc 子目录，但未核验完整安装、权重与复现链路，不将“仓库存在”写成“可一键复现”。

## 任务和方法分解

模型输入为多视图 RGB、内外参，输出室内三维语义占用。它沿竖直方向分段，每段用上下平面对组织查询，经图像交互、平面交互后恢复体素特征。

1. 图像编码器提取多视图特征。
2. 使用三维锚点与高度嵌入初始化 slice queries。
3. Sliced Spatial Cross-Attention 关联图像与切片附近空间。
4. Planar Cross-Attention 建立平面间交互。
5. 汇合并沿高度插值形成体素特征，解码语义占用。[正文 §III](https://arxiv.org/html/2501.16684v1)

## 关键概念解释

“沿竖直方向切片”不意味着把场景切成一组竖直墙片。按论文的描述，每个高度区间有 floor/ceiling 两个边界平面，任一点关联到邻近的上下平面。阅读示意图时应先找坐标轴，再理解插值。

从传统感知角度，它类似于意识到“同一个 xy 位置需要多个高度层”，但存储的是学习特征而非简单每层二值格子。插值能提高表达效率，也意味着相邻切片的细节恢复依赖模型和切片密度。

## 实验该怎么看

论文使用 EmbodiedScan 多视图占用任务，并列出相同输入视图数的重新实现基线。其设置中输入视图数量、切片数和最终体素输出大小都有明确说明。[正文 §IV 与 Table I](https://arxiv.org/html/2501.16684v1) 评价时应优先比较信息量一致的基线，不能把原版少视图结果直接当作纯表示结构收益。

## 局限与人形迁移分析

**本调研分析：** 高度切片为桌面、柜体和上下层空间提供学习思路，但网络的输出体素精度仍会限制椅腿、桌沿等细结构。具有“多高度”不等于已经满足足部和手指接触需求。需要把切片数、体素大小、目标尺寸与计算成本放在同一张图上比较。

使用室内平面结构的先验，还隐含坐标定义的重要性。人形躯干倾斜时，应明确切片轴沿世界重力还是机体轴；误对齐会改变模型看到的结构分布。这是迁移问题，不是本文已验证的缺陷。

## 阅读与复现检查点

- 画一个桌子和桌下椅子的截面，标出上下平面、查询点和插值位置。
- 在相同 RGB 视图数、骨干与输出精度下比较 BEV、TPV、Slice 表达。
- 查清 empty 是否进入平均和类别数如何统计。
- 检查输入集合是否包含未来视图；多视图设置不自动满足在线因果性。
- 学完再看 [EmbodiedOcc](../embodiedocc/README.md)，区分“空间压缩”与“时间记忆”两个问题。
