# MonoScene：从单目 RGB 学习三维语义补全

## 一分钟总结

**定位：理解 camera-only occupancy 的首批关键基线。** MonoScene 用单张 RGB 图像预测稠密三维语义场景。核心是先把多尺度二维特征沿视线放入三维，再让三维网络和场景关系先验消除歧义。对于习惯点云直接给出几何位置的读者，这篇最值得学习的是：图像语义如何进入三维，以及深度缺失后哪些输出依靠数据先验。[作者项目页](https://astra-vision.github.io/MonoScene/)

## 任务输入输出

输入为一张 RGB 图像与投影所需相机参数；输出为指定空间范围内的体素语义，包括 empty 类。论文在 NYUv2 和 SemanticKITTI 上评价，官方仓库另提供 KITTI-360 推理示例；后者不能被误写成同等的训练与定量评测结论。[官方说明](https://github.com/astra-vision/MonoScene)

## 方法步骤

1. 二维 UNet 提取多尺度图像特征。
2. **FLoSP（Features Line of Sight Projection）**：把体素中心投到图像，在不同尺度取特征并聚合。落在同一视线不同深度位置的体素可能获得相似图像证据，因此此步骤不是深度恢复的充分条件。
3. 三维 UNet 处理体积特征；**3D Context Relation Prior** 显式学习空间与语义关系，增强场景一致性。
4. 结合体素监督、场景级统计约束和局部视锥类别比例损失，预测完整语义体积。[论文方法 §3](https://arxiv.org/html/2112.00726)

## 给传统机器人感知工程师的概念解释

FLoSP 可以理解为“给候选三维位置查询图像证据”，而不是已经知道深度后的唯一反投影。同一个像素可能对应近处障碍、远处背景或遮挡区域，需要后续推断决定。视锥比例损失约束一个图像区域对应三维视锥中的类别分布；它提供统计监督，不给每一个体素新增真实测量。上下文先验让“像房间”的输出更容易产生，同时也意味着域外空间可能被先验错误补全。

## 实验应看什么

优先读 FLoSP、多尺度投影、3D 关系模块和损失的消融，并分别看 NYUv2 与 SemanticKITTI，确认结论是否跨场景成立。[原文消融入口](https://arxiv.org/html/2112.00726#S4)

自己的评价建议分成可见区、遮挡区、视场外，分别统计几何召回和误占据率。不要把“画面完整”作为几何准确的证据。对人形特别关注桌椅之间的窄间隙、门槛、薄桌面及近距离图像边缘；按距离分桶时也应保留类别分桶，避免地面占多数掩盖障碍漏检。

## 局限与人形迁移分析（本调研推断）

单目输入有尺度与遮挡歧义，换相机高度、俯仰角或镜头会改变图像与空间先验。人形头部运动明显，原始车载训练分布不能直接覆盖低头看脚、转头、弯腰和手臂遮挡。若已有 RGB-D 或双目，不必为了 camera-only 形式放弃可靠深度；可把 MonoScene 当作 RGB 语义与补全支路，并用几何测量约束预测。

它输出的是一帧条件下的场景预测，不是维护持久状态的 SLAM 系统。将连续帧结果融合时，还需要外部位姿、时间同步、动态对象处理和观测置信度。尤其不能把模型推断 empty 当成已经射线清空的 free，也不能把补出的可踩地面直接转为落脚点。

## 阅读与复现检查点

- 手算一个体素中心到像素的投影，检查 resize/crop 后内参及图像有效区。
- 用自己的标定参数画出体素视锥，确认轴方向和单位一致，再看预测好坏。
- 复现阶段先用单样本推理核对输出和标签 shape、empty/ignore 编号，再扩大数据规模。
- 官方 README 使用较老 Python/PyTorch/CUDA 组合；本轮只核验说明，未保证现代依赖兼容。[安装与评价入口](https://github.com/astra-vision/MonoScene)
- 做迁移实验时固定几何分辨率与有效 mask，加入 RGB-D 几何基线；比较的核心是语义补全实际增加多少可用信息。
