# EmbodiedScan：室内具身三维感知基准

## 一分钟总结

如果你的目标是室内人形 BEV/OCC，这是一篇应该尽早读的数据与任务论文：它把第一视角 RGB-D 观测、三维检测、语义占用和语言定位放到同一个研究框架里。它告诉你“要预测什么、怎样比较”，价值不只在一个网络结构。数据以已有室内扫描为基础，不能直接等同于人形走路实采数据。

## 详细介绍：任务和输入输出

论文整理 ScanNet、3RScan、Matterport3D 等室内来源，提供含位姿的第一视角 RGB-D 及多种三维标注。Embodied Perceptron 用多模态编码器与相应解码器处理检测、占用和语言相关任务；occupancy 的输出是空间栅格类别，不能拿检测的类别总数代替占用类表。[正文 §3–5](https://arxiv.org/html/2312.16170)

## 方法怎么理解

1. **先统一空间。** 多帧深度反投影后依靠相机位姿聚合，图像特征通过投影关联到三维位置。
2. **再融合模态。** RGB 提供外观语义，深度点云提供几何；不同任务使用稀疏或稠密特征融合与解码。
3. **最后定义任务协议。** 多视图和连续观察设置比较模型在不同观测量下的能力。占用标注来自三维语义信息的体素化，而非仅把检测框涂成实心体。[正文 §3–5](https://arxiv.org/html/2312.16170)

## 从轮式感知角度理解它

你可以把它看成“地图上的几何格子增加类别和可查询语义”，但实际工程要多问一步：网络看到的是当前单帧、历史观测集合，还是已经包含全场景信息的点云？这决定系统是否在线、是否有未来信息。已知位姿与预先整理的场景坐标也应计入方法假设。

## 实验该怎么看

先对齐输入模态和视图数量，再比较同一任务。关注 RGB、Depth、RGB-D 的相对变化和长尾类别，而不只看平均值。原论文的占用语义类表与 SliceOcc 报告的含 empty 设置在表述上不同，复现时必须核对 evaluator，不能根据“80/81”口头描述直接合并分数。场景坐标对齐方式也要纳入记录。

## 局限与人形迁移分析

**论文事实边界：** 基准支持室内第一视角感知，不能由此得出具有人形闭环落脚或全身避碰保证。

**本调研分析：** 它适合做室内语义占用的统一参照，但走路造成的模糊、躯干摆动、移动手臂和在线位姿误差需要额外测试。对于抓取，类别占用仍缺少精细接触面与可达性；对于行走，地板类别仍缺少支撑稳定性信息。

## 阅读与复现检查点

- 画出 RGB 与 depth 两条特征分支、投影坐标和输出网格。
- 明确原始数据许可、场景 split、类别映射和 ignore 规则。
- 在相同视图数量下重做 RGB/Depth/RGB-D 对照，避免模态和信息量同时变化。
- 检查连续设置是否允许只访问截至当前时刻的数据。
