## 一分钟总结

这项工作的核心价值是把传感器布局、采集、标注和融合网络作为整体设计。系统采用6相机与LiDAR，并强调将摆动传感器的观测变换到重力对齐的自中心坐标系。数据使用人佩戴同配置设备采集，以降低机器人采集成本；这与真实人形步态数据存在区别。[项目页](https://humanoid-occupancy.github.io/)

## 输入、输出与数据

输入是多相机图像、LiDAR及时间/位姿信息，输出语义体素。官网说明静态背景累积与动态目标分别处理，再按当前帧对齐、体素化；没有以Poisson重建填充全部表面。训练/验证按clip划分。[数据流程](https://humanoid-occupancy.github.io/) 因此研究前须弄清标签中的未观察区域如何处理，不能看到密集张量就假设每一格都有可靠真值。

## 方法详解

论文以PointPillar提供BEV几何query，图像特征提供key/value，通过带畸变投影的跨模态注意力融合；历史BEV先做ego-motion对齐，再拼接；最终以channel-to-height形成体素。输出为10 cm、200×200×24栅格。[HTML §3–4](https://arxiv.org/html/2507.20217v2)

对已有轮式感知背景，可把它分成四个可独立排错的环节：几何坐标统一、图像与点云对齐、时序特征对齐、BEV到高度维解码。网络结构并不能代替前面三步正确性。尤其roll/pitch变化会使静态物体在身体坐标中移动，需要先明确地图的重力轴和高度原点。

## 局限与人形迁移分析

**人戴与真机差异**：人戴设备模拟高度和视角，但稳头、人的运动轨迹、身体遮挡以及振动与机器人不同。应补录真实头颈运动、急转、搬箱和低头看脚片段；这是域差异评估建议，不是原文已证明的失败。

**分辨率与任务**：10 cm可作为周围结构起点，不能未经验证就用于精细抓取或足边安全。最好增设近脚/近手高分辨率几何分支，并以目标物理尺寸决定体素预算。

**时序**：历史越多不一定越好；可研究姿态不确定性、动态目标与自遮挡共同决定的融合权重。对学习者，先完成严格时序回放、单帧基线和准确坐标链，比立即增加Transformer层更有价值。

**标签**：累积点云有可见性偏置，未来观测参与离线标注本身不等于模型输入可以使用未来信息。训练输入和标签生成必须在代码中分开，避免时间泄漏。三维背景表面缺点也不自动代表free。

## 阅读与复现检查点

- 画出实际平台传感器位置和脚边/搬物盲区，不直接照搬六相机布局。
- 阅读§3.3，确认静态/动态标注与unknown定义。
- 分别验证静态和头部转动时的点云投影；检查畸变模型与图像是否匹配。
- 对齐1/2/3/4帧实验，保持训练和输入条件一致。
- 在代码正式释放前，可先用[几何地图](../nvblox/README.md)和已开源BEV网络建立自有回放基线；不虚构作者脚本或权重。
