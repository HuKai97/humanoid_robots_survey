# FoundPose：冻结视觉特征与经典 PnP 的组合

## 先读总结

**FoundPose 展示了不专门训练 6D 姿态网络，也能用基础视觉特征处理新 CAD 物体。** 查询只用 RGB；渲染模板中的深度帮助建立对象三维坐标，不意味着机器人需要深度相机。必须注意：官方仓库仅发布 coarse 流程，未包含论文的 featuremetric refinement。优先级 **P1**。[作者项目](https://evinpinar.github.io/foundpose/)、[官方代码范围](https://github.com/facebookresearch/foundpose)

## 身份与阅读深度

Evin Pınar Örnek、Yann Labbé 等，**FoundPose: Unseen Object Pose Estimation with Foundation Features**，ECCV 2024；预印本首发于 2023 年。本次阅读 HTML 方法、作者项目与 README；没有运行算法，也没有将公开实现等同于论文完整方法。[论文页](https://arxiv.org/abs/2311.18809)

## 输入输出、对象入库与训练

输入 RGB、内参以及带对象身份的 mask，需要目标三维模型。对象入库时渲染视角、提取特征并生成检索表示；输出模型到相机的 `R,t`。基础方法使用预训练 DINOv2，不要求对象或 6D 任务专属训练。接入额外学习式精修器后，应单独说明其训练前提。[作者项目](https://evinpinar.github.io/foundpose/)

## 方法步骤与关键表示

把 DINOv2 模板 patch 描述子与模型上的三维位置关联；在线先用 bag-of-words 检索少量候选模板，再匹配查询 patch 与模板 patch。模板深度将后者提升为三维对应，通过 PnP-RANSAC 得到候选。论文的特征度量优化用于减轻粗 patch 采样误差。[论文 HTML §3](https://arxiv.org/html/2311.18809v2)

**独立理解：** 检索回答“应与哪些参考视角比较”，局部匹配回答“图像哪个部分对应模型哪里”，PnP 才回答“物体在哪里”。把三步分开，便能针对错误定位排查：候选没检索到、描述子匹错，或正确对应分布不足，都可能导致相似的最终姿态错误。

它对传统机器人视觉的启示是，经典几何求解器并未失去价值。基础模型可以提供更强的跨外观描述，几何模块仍负责相机投影一致性。一个常见误解是“语义越强越适合位姿”：把两个相似杯子的把手都编码为同一语义，未必足以区分同一个物体上相邻表面点。姿态需要位置细节，而不只是类别信息。

## 实验与公开实现边界

论文比较不同特征与 BOP 多数据集结果，强调中间层描述子的作用。[作者项目](https://evinpinar.github.io/foundpose/) 官方仓库说明公开实现没有 featuremetric refinement，并提示公开渲染器与论文内部渲染器不同，单独给出部分数据集的实现结果。后续复现应以相应 coarse 配置为目标，不能直接宣称复现完整最终成绩。[官方 README](https://github.com/facebookresearch/foundpose)

## 局限与人形机器人启示

**我们的推断：** 低分辨率目标可能只对应少量 patch；严重遮挡会进一步减少有效匹配。对几何和纹理均对称的对象，图像本身也不提供唯一方向。CAD 准备、渲染模板和外部分割前端仍有成本，training-free 不等于零算力或零工程工作。

人形机器人上可用它研究 RGB 退化方案：当深度无效时，是否仍能提供可信粗姿态。但 RGB 与 RGB-D 的切换必须带置信度和失败识别，不应无条件沿用旧结果。还可把它作为“冻结特征+几何”对照，衡量复杂训练后端在具体任务上的真实收益。

## 学习与复现检查点

1. 复习图像检索、视觉词袋、2D-3D 对应、PnP 与 RANSAC，再读基础模型特征选择。
2. 后续先验证公开 coarse 流程；将特征度量优化与外接 MegaPose 精修分开记录。
3. 固定 mask，改变目标像素尺寸、遮挡率和模板数量，分析匹配约束何时不足。
4. 记录模板入库时间与显存，避免只比较在线网络前向时间。
