# FoundationPose：统一对象注册、精修与跟踪

## 先读总结

**面向人形机器人抓取与物体运动跟踪，FoundationPose 是优先理解和后续验证的 RGB-D 基线。** 有 CAD 时直接渲染；无 CAD 时先用参考观测建对象表示，后续共用精修和评分网络。新对象不用微调位姿网络，但无 CAD 分支仍需逐对象建模。优先级 **P0**。[作者项目](https://nvlabs.github.io/FoundationPose/)

## 身份与阅读深度

Bowen Wen、Wei Yang、Jan Kautz、Stan Birchfield，**FoundationPose: Unified 6D Pose Estimation and Tracking of Novel Objects**，CVPR 2024 Highlight；预印本首发于 2023 年。本次阅读 HTML 的方法、部分实验与跟踪说明，并核对官方 README；未运行模型。[论文页](https://arxiv.org/abs/2312.08344)

## 输入、输出和成本边界

查询输入为 RGB-D 和内参，注册时需要目标区域。先验二选一：CAD，或具有位姿信息的参考 RGB-D 观测。后者拟合对象神经场以获得可渲染几何与外观；这个逐对象优化不能省略。输出物体相对相机的位姿。通用位姿网络已通过合成数据训练。[论文 HTML §3.2、§4.1](https://arxiv.org/html/2312.08344v2)

## 方法步骤与表示

项目把估计拆成全局候选初始化、渲染比较精修、候选评分选择。神经对象表示为无 CAD 支路提供 RGB-D 渲染，使两条支路能接入同一后端。[项目管线](https://nvlabs.github.io/FoundationPose/) 跟踪时使用上一帧位姿渲染，与当前观测比较后更新；因而无需每帧重复全局候选搜索。[论文 HTML 跟踪说明](https://arxiv.org/html/2312.08344v2)

**独立理解：** “注册”解决不知道物体朝向时的大范围搜索，“跟踪”解决已有较好初值后的局部更新。两者的成功条件和计算量不同。用跟踪帧率来代表首次抓取等待时间会误导系统设计；只测试静止物体又会掩盖运动后离开精修有效范围的问题。

可以将渲染器看成一个可查询的物体观测模型：给它 `T_camera_object`，它返回相机应看到的表面。网络利用观测差异给出更新。对象神经场只是获得这种观测模型的一条路径；它不会自动解决外参、图像时间同步或机器人运动学误差。

## 实验证据与代码边界

论文分别评估有/无 CAD 的位姿估计与跟踪，包含 YCB-Video、LINEMOD/BOP 子集及 YCBInEOAT 动态操作序列；不同表的检测与初始位姿条件应分开阅读。[论文 HTML §4](https://arxiv.org/html/2312.08344v2) 官方仓库提供精修器和评分器的权重准备说明、模型自由分支入口及 ROS 实现链接；这些是复现入口，不代表本目录已完成运行。[官方实现](https://github.com/NVlabs/FoundationPose)

## 局限与人形机器人启示

**我们的推断：** 双手会遮挡目标，头部转动会引入模糊，RGB 与深度未同步会产生互相矛盾的表面观测。失跟后若继续局部更新，可能稳定地输出错误姿态。因此部署实验必须包含重定位、遮挡恢复与失败拒绝，而不只是连续平滑输出。

建议先采用有 CAD 分支隔离位姿模块误差，再研究参考重建分支。头部相机负责发现目标，腕部相机负责近距离观察是可研究的系统结构，但两者必须统一时间戳与坐标变换。抓取后对象与手之间的接触约束还可以形成额外先验；这些都是本调研提出的工程研究方向。

## 学习与复现检查点

1. 先读 MegaPose，再画出注册与跟踪的不同调用路径，区分精修网络和评分网络。
2. 后续复现分别统计首次注册延迟、持续跟踪延迟、失跟率及重定位时间。
3. 用静止物体测头部运动，再固定头部移动物体，以区分相机运动与目标运动影响。
4. 保留深度有效率、mask、渲染叠加和失败帧；为透明/反光物体单独建测试集。
5. 无 CAD 实验必须报告参考位姿来源、视角数、建模耗时和尺度获取方式。
