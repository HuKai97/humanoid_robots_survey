# PoseCNN（RSS 2018）

## 速读总结

**先学“把位姿拆开”和“对称性会改变正确答案”。** PoseCNN 面向已知物体，把中心定位、距离估计与旋转回归分开；是连接传统几何知识与学习式 6D 感知的好入口。[论文](https://arxiv.org/html/1711.00199v3)

学习优先级：**P1，理解概念优先**。建议接着看 PVNet 的关键点投票和 DenseFusion 的 RGB-D 融合。

## 任务边界、输入输出与先验

输入为 RGB 与相机内参，深度可用于后续 ICP；输出物体坐标系到相机坐标系的旋转和平移。对象的三维模型及训练对象集合已知，不属于拿到任意新物体就能直接使用的方法。官方仓库提供 YCB-Video 的训练、测试入口。[官方代码](https://github.com/yuxng/PoseCNN)

## 方法步骤与关键表示

1. 像素语义分割确定哪些像素属于目标。
2. 像素预测指向物体中心的单位方向，以 Hough 投票汇聚中心；结合预测深度和内参恢复平移。
3. 对目标区域特征回归四元数。ShapeMatch-Loss 用变换后模型点之间的最近邻距离处理形状对称。[方法 III](https://arxiv.org/html/1711.00199v3)

**我们的几何解释：** 这里的“中心”应理解为三维模型原点的投影，不是随手取检测框中点。设其像素位置为 `(u,v)`，相机光轴深度为 `z`，则 `t=z K⁻¹[u,v,1]ᵀ`。这说明单目网络仍需解决尺度：已知物体尺寸和训练分布提供了线索，内参本身不能凭空给出绝对距离。

再想一个圆柱：旋转后外观可能相同，直接惩罚四元数差会迫使模型学习无法从图像辨认的角度。对称性不是“标签标错”，而是观测对姿态的约束不唯一；理解这一点比记网络层数更重要。

**建议的小练习：** 从熟悉的检测框出发，分别标出框中心、可见区域质心和三维模型原点投影。遮住物体一侧后再画一遍，检查三者为何会分离。这个练习能帮助避免将普通目标检测的位置直接当作操作所需的物体坐标原点。

## 实验结论与可信范围

作者在 YCB-Video、OccludedLINEMOD 上报告遮挡和对称物体结果，也区分 RGB 预测与深度精修；该工作同时发布 YCB-Video。[项目页](https://rse-lab.cs.washington.edu/projects/posecnn/) 本笔记不引用未经逐项对齐的排行榜数字，更不将作者结果当作本地复现。

## 优点、局限与人形机器人启示

**我们的分析：** 分解结构容易定位故障：分割错、中心错、尺度错、朝向错可以分别检查。但一个合理的视觉姿态不保证抓取方向唯一；几何对称和任务对称也可能不同，例如容器外壳近似对称、开口或标签却影响操作。

**工程推断，非论文人形验证：** 头部相机观察桌面时，可先输出相机系位姿，再由带时间戳的外参转换到躯干和手臂坐标系。行走造成的相机运动、曝光模糊、手部遮挡和时间同步都需另外验证。若手伸过去时误差突然变大，应先检查遮挡与坐标链，而不是立即更换旋转损失。

## 阅读与复现检查点

- 画出 `object → camera → torso → end_effector` 坐标链，并明确每个变换方向。
- 对一个模型原点、单位和已知姿态做投影检查；分开评估旋转误差和深度误差。
- 用遮挡前后同一物体检查中心投票；对称对象用对称感知指标。
- 原仓库 README 使用较早的 TensorFlow/CUDA 环境；先核对依赖与数据格式，再决定是否移植。[官方代码](https://github.com/yuxng/PoseCNN)
