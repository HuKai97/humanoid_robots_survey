# FS-Net：用形状特征解耦旋转、平移与尺寸

## 先读总结

**优先级 P1。** FS-Net 把类别级姿态估计的重心放在深度点云形状上：先提取旋转敏感特征，再分别处理旋转、平移与尺寸。它适合帮助已有点云经验的工程师从传统配准转向学习式位姿估计，也适合研究延迟敏感的类别感知。[论文][paper]

本调研的选择建议：先学其任务分解与形状增强，再决定是否移植整套旧实现；这两部分较容易与现有 RGB-D 处理链结合。

## 任务边界与先验

输入是 RGB-D。RGB 用于检测物体框与类别，框内深度生成局部点云，再由三维网络处理前景和姿态。论文方法不以外部像素级掩码为必要起点，但绝不等于不需要定位目标。已学习类别及其尺寸分布属于先验，测试实例不要求精确 CAD。[论文][paper]

作者 README 提醒：发布训练实现的部分细节为效率作过调整，不能默认与论文完全一致；示例二维检测模型的适用类别也需检查。[代码][code]

## 方法拆解

1. 从 RGB 检测框确定点云处理区域。
2. 用三维图卷积自编码器进行前景分割和观测点重建，学习几何方向信息。
3. 采用互补的旋转解码分支，避免将所有姿态信息混在同一个预测头。
4. 将平移表示为相对观测点均值的残差，将尺寸表示为相对类别平均尺寸的残差。
5. 训练时使用 box-cage 形变增加类别内形状变化。[论文][paper]

**我们的解释：** 点云均值一般不等于物体真实中心，尤其物体只露出一侧时。平移残差就是学习“可见表面中心到物体中心”的偏差。尺寸均值同样只是起点；网络并没有因为类别已知就获得真实大小。旋转分支减少平移、尺度因素的干扰，学习目标因而更聚焦。

## 证据与局限

论文在类别级及实例级设定中进行了评测并强调效率；本笔记不跨硬件转述 FPS，也不把网络推理时间当作整机延迟。官方仓库有 demo、数据预处理与训练入口，但这些入口在本工作区均未执行。[代码][code]

**我们的分析：** 形状驱动有助于降低颜色变化干扰，却无法从缺失深度中凭空恢复辨识信息。透明杯、黑色塑料、薄工具、把手消失都可能让点云形状偏离训练分布。三维形变应与真实类别结构相容；任意拉伸可能造出不可能物体，并改变语义轴。类别平均尺寸对长尾实例也可能产生系统偏差。

## 人形机器人启示（工程推断，待验证）

若机器人需要在杯子、瓶子等有限类别上持续工作，可将 FS-Net 作为“检测加点云姿态”的学习基线，与 CAD 方法比较获取新物体先验的成本。部署时应把 RGB 检测、深度等待、点云裁剪、网络、坐标变换分别计时；头部或腕部相机只要一个环节排队，就可能使动作使用过时位姿。

建议将误差按距离与可见比例分桶，同时保留每类尺寸偏差。对于抓杯身任务，尺度误差影响夹爪开度；对于抓把手任务，类别框无法给出局部空隙，需要额外部件定位。上述关系是工程推断，不是论文的人形机器人实验结论。

## 学习与复现检查点

- 用可见半球点云验证“均值不等于物体中心”，建立对平移残差的直觉。
- 确认目标类别检测器可用，再比较姿态模块；避免把漏检算成网络姿态失败。
- 固定官方仓库提交及配置，标注与论文实现的已知差异。
- 在同一掩码/检测条件下比较形状增强前后，分别记录旋转、平移、尺寸；未执行。
