# GenPose：从单一答案转向位姿分布

## 先读总结

**优先级 P1。** GenPose 将部分点云对应的物体姿态看成一个条件分布：扩散模型生成候选，能量模型排序并剔除离群候选，随后聚合。它针对对称、遮挡造成的多解问题，而不是只提高一个确定性回归器的容量。[论文][paper]

对人形感知最值得学的是：观测不足时允许保留多个解释。一个杯柄被挡住，不应让控制器把任意猜出的朝向视为已知事实。这是我们的工程理解。

## 任务边界与先验

核心输入是分割后的部分三维点云，输出为旋转与平移；核心扩散变量不含物体三维尺寸。不需要测试实例 CAD 或显式类别形状模板，并不代表没有训练分布先验。论文的新类别结果有其具体范围，不能推广为任意类别零样本可靠。[论文][paper]

官方评测数据包含 Mask R-CNN 结果；tracking 目录还明确有手工对齐过的分割结果。这项条件必须随跟踪结论一起记录，不能当成完全自动的端到端跟踪表现。[代码][code]

## 方法拆解

1. 在观测点云条件下学习不同噪声水平的位姿 score，使候选逐步趋向合理姿态。
2. 采样得到多组旋转、平移候选。
3. 由单独的能量网络给候选排序，排除较不合理的样本。
4. 聚合保留候选作为最终输出；网络使用连续旋转表示。[论文][paper]

**我们的解释：** 这里“6D 旋转表示”指用六个数表达旋转，并非“6D 位姿多了六个自由度”；物体位姿仍是三维旋转加三维平移。另一个重要区别是候选分布与最终聚合结果：分布能表达多解，单一输出仍会压缩这种信息。若部署要利用多解，接口需保留候选及其关联，而不是只保存一个矩阵。

## 证据与局限

官方仓库将 score 与 energy 的训练脚本分开，并给出单帧和 tracking 评测入口；公开实现有 PointNet2/PyTorch3D 等依赖，未在本地验证兼容性。[代码][code]

**我们的分析：** 候选数量和采样步数决定计算开销，也影响覆盖低概率正确姿态的机会。能量排序分数不能未经验证就当作安全概率。若可行解之间差异很大，聚合可能抹掉模式差异；应检查旋转聚合方式与对称等价类，避免直接平均欧拉角。分割和缺失深度依然是上游瓶颈，生成模型不能替代传感器可观测性。

## 人形机器人启示（工程推断，待验证）

可将候选集用于主动观察：当多个高分姿态对应不同杯柄方位时，选择能区分这些姿态的腕部视角。在动作规划中，也可检查某个抓取是否对所有合理候选均可行；若仅对一个模式可行，继续观察的价值较大。

这一设计必须连同时间预算评估。站立晃动和手部遮挡会让输入持续变化，采样结果在生成结束时可能已经陈旧。建议记录观测时间、推理完成时间和执行时间，同时检查候选在新观测下是否仍成立。上述用途是待研究假设，并非本次已实现的闭环能力。

## 学习与复现检查点

- 先理解旋转流形、对称等价姿态及条件概率，再学习 score matching。
- 分别统计最优候选误差、最终输出误差、候选多样性；排查生成失败还是排序/聚合失败。
- 固定 mask、候选数、采样设置与随机种子，报告多次运行波动。
- 单帧和 tracking 分开评测，清楚披露手工分割关联条件；实验未执行。
