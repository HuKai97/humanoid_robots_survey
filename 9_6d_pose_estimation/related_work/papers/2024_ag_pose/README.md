# AG-Pose：让关键点适应不同实例的几何

## 先读总结

**优先级 P1，作为类别级路线的近年代表。** AG-Pose 学习少量随实例变化的关键点，再融合局部和整体几何，建立关键点到规范空间的对应，预测位姿和尺寸。它延续 NOCS 的规范坐标思想，但重点转向“哪些点值得建立对应”。[原论文][paper]

我们的阅读判断：它适合在 NOCS、FS-Net 之后学习，帮助理解同一类别外形变化很大时，为何固定点或单纯堆叠密集对应未必足够。

## 任务边界与先验

输入是 RGB-D 经实例分割得到的图像区域与点云，含类别标签和相机内参；输出旋转、平移、三维尺寸。测试无需精确实例 CAD，也不输入显式类别形状模板，但训练使用模型和姿态监督约束关键点。这与“不使用形状训练数据”完全不同。[原论文][paper]

官方数据处理流程引用 DPDN 的预处理及 DualPoseNet 的分割结果，因此评测不是仅把一张任意现场图像直接交给姿态网络。[代码][code]

## 方法拆解

1. 联合提取像素外观和点云几何特征。
2. 用可学习查询吸收实例信息，产生关键点及对应特征；监督其分散且靠近物体。
3. 汇聚关键点邻域的局部几何，以及关键点之间的整体结构。
4. 预测关键点的 NOCS 坐标，再通过回归头输出位姿和尺寸。[原论文][paper]

**我们的解释：** 稀疏并非只为省计算，而是让一组有代表性的结构承载对应关系。瓶身一小片平面可能难以辨认，结合它与瓶口、底部的相对位置才更有意义。但自适应关键点不自动等于人类定义的抓取部件：某个点有助于确定姿态，并不表示它适合机械手接触。

## 版本区别、证据与局限

**当前官方仓库明确是扩展版实现。** README 列出新增的点云重建网络、HouseCat6D 实验和 DINOv2 图像骨干实验。原 CVPR 论文、当前仓库配置、当前 README 的结果必须分开记录；不能把扩展版 DINOv2/HouseCat6D 数字标成原论文结果。[代码][code]

本笔记只以原 CVPR 方法说明主路线，不抄录未经同协议核验的性能差值。**我们的分析：** 关键点可视化很直观，却不能单凭图上分布均匀就证明对应准确。遮挡会改变可见几何，关键点可能换位置甚至换语义。若连续两帧输出稳定，仍应检查它是否只是在继承类别偏置；若输出跳变，应定位到分割、深度还是关键点选择。

## 人形机器人启示（工程推断，待验证）

对于长尾杯子和工具，可用关键点作为诊断界面：观察失败时关键点是否落在手部、背景或缺失深度边界。机器人可通过改变腕部视角获取更多区分性几何，再比较姿态是否一致。这里应先评测跨视角可重复性，不能默认自适应关键点已经具备时序身份。

与操作接口对接时，仍需显式建立部件、接触面或任务坐标。若关键点只服务于整体位姿，抓把手、插孔等任务还应检验相应局部几何。少量关键点便于传给下游模块，但需要连同可见性和观测时间保存，避免控制使用过时结构。
