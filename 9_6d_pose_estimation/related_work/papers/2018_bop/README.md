# BOP — 统一 6D 位姿评测的入口

## 先读总结

这篇的价值在于回答“两个方法的结果到底能否比较”。它建立统一数据和评测体系，并关注遮挡、对称性造成的位姿歧义。对工程学习者，先掌握它比先记住某个榜单分数更重要。**BOP 不是一个位姿网络，2018 年的实验排名也不是今天的排名。**

## 题录与证据

- 全名：BOP: Benchmark for 6D Object Pose Estimation。
- 年份/会场：ECCV 2018；优先级 P0。
- [原论文摘要](https://arxiv.org/abs/1808.08319)、[官方出版与报告入口](https://bop.felk.cvut.cz/home/)、[官方 Toolkit](https://github.com/thodan/bop_toolkit)。
- 补充阅读：[BOP Challenge 2024 报告（CVPRW 2025）](https://arxiv.org/abs/2504.02812)、[2024 任务定义](https://bop.felk.cvut.cz/challenges/bop-challenge-2024/)。
- 阅读深度：原论文摘要、官方协议、工具说明及后续报告摘要；未逐表复核原论文所有方法。本轮无下载、无实验。核验日 2026-09-29。

## 论文做了什么

原工作把不同场景的数据组织到统一接口，给出处理姿态歧义的评估方式，并提供持续评测平台。[原论文](https://arxiv.org/abs/1808.08319)

学习时可以把其贡献拆成三层：**输入契约**决定方法可以知道什么；**错误定义**决定什么算正确；**汇总协议**决定如何从对象与帧得到最终结果。这是本笔记对评测体系的解释，不是另一个指标。

例如旋转对称物体可能产生不同旋转矩阵，但可见形状一致。直接用欧拉角相减惩罚它，会将不可观测的差异当成算法错误。反过来，若任务要求标签朝前或把手可抓，仅靠形状等价也不够，需要额外任务指标。

## 从 2018 读到后续协议

后续 BOP 任务逐步区分训练见过/未见过对象、给定身份的定位/需要识别身份的检测、CAD/参考视频 onboarding。BOP 2024 的 model-free 仍允许参考视频，其数据条件与“完全无对象参考”不同。[挑战报告](https://arxiv.org/abs/2504.02812)

BOP 2024 的 6D detection 用 MSSD/MSPD 评估，不直接套用经典 localization 的三项 AR 平均；具体 evaluator 及输入格式见该赛道页面。[官方任务与评估入口](https://bop.felk.cvut.cz/challenges/bop-challenge-2024/)

参考视频的姿态权限也要区分：BOP 2024 static onboarding 提供全部参考帧 GT pose，dynamic onboarding 仅提供首帧 GT pose。[官方 onboarding 定义](https://bop.felk.cvut.cz/challenges/bop-challenge-2024/)

## 怎么用于本项目

我们建议每次比较先填一行：对象先验、训练对象、图像模态、mask 来源、初始化、是否 refinement、运行时间覆盖范围。任何一栏不同，都先解释差异，再报告成绩。假如方法 A 使用 GT mask，方法 B 使用自动检测，二者端到端分数差不能直接归因于姿态模块。

对固定实验集，保留逐对象、逐序列结果，不只保留平均值。对人形操作，再加入头部运动、手部遮挡、掉跟踪和抓取容差；BOP 精度可作为感知模块检查，但无法单独证明操作成功。

## 局限与阅读检查点

基准只覆盖其提供的数据与任务约束；家庭、工业、第一视角和你自己的相机仍可能有分布差异。不同年份新增的数据或评估器不能不加说明地拼接。

建议练习：找一个对称物体，解释 ADD、ADD-S 与对称感知误差为何不同；再对同一预测检查不同单位或变换方向造成的错误。正式运行前固定 toolkit commit、targets 和对称定义。具体公式及输出要求见 [本项目评测协议](../../../experiment/evaluation.md)。
