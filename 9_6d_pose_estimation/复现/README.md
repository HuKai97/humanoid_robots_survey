# Baseline 复现计划

状态：未开始。当前完成的是文献调研，不是可运行代码交付；不需要现在就同时搭建所有环境。

## 默认主线：RGB-D + CAD

**第一选择 FoundationPose。** 目的是跑通“相机观测 → 对象位姿 → 连续跟踪 → 机器人坐标”的链路。先读 [官方仓库](https://github.com/NVlabs/FoundationPose) 和本库对应笔记，记录依赖版本，再决定环境方案。对象 mask、CAD 尺寸、原点定义、RGB-D 注册和内参是进入推理前的检查项。

**第二选择按问题决定。** 想评估分割/新物体初始化，看 SAM-6D；想评估有 CAD 的高频局部跟踪，看 ICG；想学习实例训练与稠密几何，看 GDR-Net。三者承担不同角色，不能直接把结果放成一张无条件排行榜。

## 其他输入条件

| 可用条件 | 候选 | 首先验证 |
|---|---|---|
| RGB + CAD | MegaPose、FoundPose、GigaPose | 模型尺寸、模板准备、检测、是否叠加其他精修 |
| RGB 参考视频、无 CAD | OnePose++、Gen6D | SfM/参考位姿质量、对象尺度、纹理与视角覆盖 |
| RGB-D 视频、无 CAD | BundleSDF | 连续 mask 来源、对象坐标系、在线建模成本 |
| 单 RGB-D 参考 | Any6D | 生成模型、尺度对齐、准备耗时、遮挡背面误差 |
| 已知类别、新实例 | NOCS、FS-Net、GenPose | 类别标准坐标、训练数据、实例划分与尺寸指标 |

## 不宜直接作为首个复现目标的情况

代码只有项目网页、未发布完整算法，或者公开实现与论文不完全一致时，先缩小“要复现的具体配置”。截至检索日，FoundPose 仓库缺论文完整 featuremetric refinement，6DOPE-GS 项目页代码仍标 Coming Soon，FreeZe 项目 Code 链接的实现可用性需再核实。不要将它们写成“已验证可一键运行”。细节和证据在单篇笔记中。

## 最小验收顺序

1. 固定仓库 commit、权重和环境；记录下载内容与许可（后续执行时进行）。
2. 跑官方最小示例，保存原输入与叠加结果；明确人工输入。
3. 验证一个已知变换的合成/标定场景，确认米/毫米、轴方向、裁剪内参。
4. 在小型冻结验证集运行，区分初始化与跟踪；按评测协议保留全部失败。
5. 扩展到实际对象和运动相机，追踪前端、几何、标定与时延问题。
6. 满足离线验收后再接抓放实验；新硬件与软件适配单独记录。
