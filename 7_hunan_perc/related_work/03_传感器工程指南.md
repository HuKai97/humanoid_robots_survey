# 相机、LiDAR、深度与 IMU：人形感知的工程基础

> 以下以通用测量模型、已核查文献和工程推导为基础，不是特定机器人的安装或性能承诺。全部练习尚未执行。

## 1. 每种传感器究竟测到了什么

| 传感器 | 原始量 | 可用于哪些感知任务 | 常见失效与必要检查 |
|---|---|---|---|
| RGB 相机 | 曝光期间积累的光强/颜色 | 语义、纹理、实例、运动线索 | 模糊、曝光变化、反光、滚动快门、遮挡 |
| LiDAR | 不同时刻沿射线获得的距离/回波字段 | 度量表面、障碍、局部几何 | 扫描运动畸变、盲区、细物体稀疏回波、材质相关缺失 |
| 双目深度 | 左右图像匹配的视差 | 稠密度量深度 | 纹理不足、重复纹理、遮挡、双目同步与矫正误差 |
| 主动双目/结构光/ToF | 依设备机制推算的深度 | 近场表面、物体、落脚几何 | 光照、反射、透明、多径/干扰等影响因机制而异，不能混成一种噪声 |
| IMU | 角速度与比力 | 短时旋转、重力对齐与运动补偿的约束 | 偏置、振动、饱和、温漂、时钟误差；不直接测语义或无漂移位置 |

不同深度设备的限制应查具体硬件文档；“深度相机”这个名称本身不足以决定噪声模型。数据资源入口见 [dataset.md](../dataset.md)。

## 2. 写清楚坐标约定，再画网络结构

本资料定义 `T_A_B` 为把 B 系的点变到 A 系的 4×4 齐次变换：`p_A_h = T_A_B p_B_h`，其中下标 h 表示补上末项 1 的齐次坐标。三维形式是 `p_A = R_A_B p_B + t_A_B`。该命名仅供本项目解释，接入其他库时必须逐一核对约定。

同一时刻，LiDAR 点到相机的变换为：

```text
p_C = R_C_L p_L + t_C_L # p_C 与 p_L 为三维列向量
u_h ~ K p_C             # u_h 为像素齐次坐标；只对去畸变针孔模型、正深度点成立
```

若相机在头部、LiDAR 在躯干，固定的是各传感器到所在刚体的安装变换；两刚体之间的关系依赖关节角 `q(t)`：

```text
T_B_C(t) = T_B_H(q(t)) T_H_C
T_C_L(t) = inverse(T_B_C(t)) T_B_L(t)
```

其中 B 为参考身体坐标，H 为头部坐标；如果 LiDAR 也安装在活动部件上，`T_B_L(t)` 同样需展开。IMU 测到头部还是骨盆运动必须写清楚，不能只写“使用机器人 IMU”。跨刚体插值还要用到关节时间戳。

这些是刚体运动学推导；标定方法入口为 [Kalibr](papers/2013_kalibr/README.md) 和 [iKalibr](papers/2024_ikalibr/README.md)。

## 3. 同步至少有四个层次

1. **时钟关系**：传感器时钟到主机时钟可能需要 `t_host = a * t_sensor + b`，其中 b 是偏移、a 对应速率差；实际是否需要取决于硬件。
2. **采样语义**：图像时间表示曝光起点、中点还是终点？点云是首点还是末点？滚动快门每行还有不同采样时刻。
3. **数据关联**：找最近帧只是匹配策略，不会让它们变成同时采集。
4. **有效数据年龄**：控制器使用结果时距原始观测过了多久？应统计解码、队列、预处理、融合、推理与通信的总延迟及 p95。

Kalibr 官方教程明确要求检查时间戳质量；CReF 的实机设置也处理相机与系统时间关系。学习网络不会消除这些输入条件。[Kalibr 教程](https://github.com/ethz-asl/kalibr/wiki/camera-imu-calibration)、[CReF 实验](https://arxiv.org/html/2603.29452v3)

一个量纲检查：假设焦距 600 像素、垂直于视线的角速度分量为 1 rad/s、时间错位 20 ms，近主光轴、小角度且主要为俯仰或偏航旋转时，像素错位约 `600 × 1 × 0.02 = 12 px`。在 2 m 距离处，相同角度对应约 4 cm 横向误差。绕光轴旋转不适用这个中心像素近似。这是理想化估算，不是任何设备的实测数据，且未计平移、畸变和场景动态。

## 4. IMU 在非 SLAM 感知里做什么

使用右手坐标，定义 `R_W_I` 将 IMU 向量变到世界系，则简化测量模型为：

```text
gyro_meas = omega_I + bias_g + noise_g
acc_meas  = transpose(R_W_I) * (acc_world - gravity_world) + bias_a + noise_a
```

这里的 `acc_world` 是 **IMU 传感器原点**在世界系的线加速度；若改用基座或质心加速度，还需处理旋转杆臂项。加速度计测的是比力，因此静止放置也会有重力相关读数；运动时也不能直接把它归一化当作重力方向。IMU 在本项目中主要提供短时运动约束、稳定的参考方向以及运动状态接口；偏置与噪声模型可参考 [Kalibr 官方说明](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)。

对 LiDAR，按每点时间把观测变到参考时刻的通用形式是：

```text
p_Lref_h = inverse(T_W_L(t_ref)) * T_W_L(t_point) * p_Lpoint_h
```

这要求短时位姿或运动模型，且时间戳、外参方向正确。陀螺仪有助于旋转补偿，但**仅靠角速度无法恢复完整平移补偿**。平移、动态物体和活动关节需各自处理。这里把所需运动视作外部接口，不要求实现 VIO/LIO 或 SLAM。

## 5. 深度转点云的前提

针孔模型下，若 Z 是光轴方向的度量深度：

```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
```

必须确认设备给的是 Z-depth 还是沿射线的 range；确认单位是 m、mm 还是带 scale 的整数；确认 RGB 与 depth 的分辨率、内参、畸变和外参。改变分辨率或 crop 后不能继续使用旧 K 而不做相应变换。

双目理想模型 `Z = f B / disparity` 说明尺度来自焦距和基线；小视差误差在远距离会放大。单目预测的相对深度并不天然满足该尺度关系。详细对照见 Depth Anything V2、Metric3D v2、FoundationStereo 的单篇笔记。

无效深度应有单独 mask。零值、最大距离填充和“没有返回”都不应无条件理解为自由空间；玻璃、黑色物体、遮挡与真空旷区域可能给出相似缺测。

## 6. 人形特有的三个工程模块

**自身过滤。**根据同一时刻关节状态把机器人几何投影到相机或点云，标出头、手臂、腿等自身区域。误用旧关节状态会误删外部障碍。先保留被删数据用于审计，再讨论过滤阈值。

**多层近场表示。**脚底支撑几何与躯干/头部碰撞几何分开输出。高程适合支撑面，但悬空横杆需要三维表达。最近的 LiDAR 人形工作正面向薄与悬空结构，说明此类输入值得单独测。[稀疏结构论文](https://arxiv.org/abs/2608.29769)

**质量与退化。**每个模态都应报告缺测、数据年龄、有效视场与状态；融合模块必须能观察这些标志。只用全零张量伪装正常输入，会把“无观测”和“观测为空”混淆。退化时采取什么动作由控制策略决定，感知侧负责清楚报告边界。

## 7. 建议的输出接口（设计建议，非现有实现）

```text
timestamp_capture / timestamp_reference / timestamp_publish
frame_id / sensor_ids / calibration_version / pose_source
validity_mask / source_mask / age_ms / confidence_or_covariance
ground_height / support_region / local_3d_obstacles
object_class / object_geometry / object_pose_if_available
```

类别置信度、几何方差和传感器健康度是不同量，不应折成一个没有定义的“confidence”。补全几何要保留 inferred 标志。输出坐标系和参考时刻应能被下游直接解释。

## 8. 排错顺序

先检查单位与坐标方向；再检查原始采样时间与相机/点云内部时间；再看投影和自身过滤；再按距离、角速度、材质检查误差；最后才判断融合网络是否需要更换。对照要同时包含单模态、正确对齐融合和人为扰动融合，避免把数据处理收益误归因给网络结构。
