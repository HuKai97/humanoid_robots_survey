# RPL: Learning Robust Humanoid Perceptive Locomotion on Challenging Terrains

- 首次公开：2026；作者：Yuanhang Zhang 等；论文版本：arXiv v1，2026-02-03。
- 优先级：P0；定位：多深度相机、本体历史、自遮挡与双向行走。
- 具身：Unitree G1人形；实机为前后两台ZED 2i深度相机。
- 核查日期：2026-09-29；状态：调研完成，实验未执行。

## 先读总结

RPL研究前后视野可能同时看到不同地形时，人形如何稳定行走。它先训练能访问理想局部高度图的地形专家，再把多个专家蒸馏为融合深度和本体历史的学生。感知侧的特色是按速度命令调节不同相机特征、通过侧边遮挡增强避免过度依赖地形宽度，并模拟身体运动造成的自遮挡与传感器延迟。它与多相机感知工程高度相关。必须注意：真实实验使用前后两相机，四方向相机是仿真支持，论文明确未展示真实复杂地形侧向行走。[论文](https://arxiv.org/abs/2602.03002)｜[作者项目](https://rpl-humanoid.github.io/)

## 研究问题与输入输出

当机器人前进、后退或搬运物品时，各相机对当前任务的重要性不同；手臂和负载也会遮住地形。RPL学生把多路深度、关节与机体角速度/重力等本体历史、任务命令输入策略，形成下游动作。外部高程真值属于教师训练条件，不是部署时的额外传感器。[论文第III节](https://arxiv.org/html/2602.03002v1#S3)

多台深度相机是多视角；再加本体历史才形成跨物理模态组合。论文不使用LiDAR作为核心学生输入，因此不能作为激光雷达与相机融合已经优于单传感器的证据。

## 方法机制：任务条件下选择信息

深度经过CNN编码。DFSV根据命令速度与相机朝向关系缩放各路特征，再进行融合；RSM对深度图两侧做随机遮挡，帮助适应未见的地形宽度。教师由不同地形专家组成，学生经动作监督蒸馏。深度仿真对静态地形与运动中的机器人网格进行射线求交，并模拟时延、噪声和丢失。[方法](https://arxiv.org/html/2602.03002v1#S3)

机制解释：前进时，后相机看见的地形不一定对下一步最重要，但也未必完全无用。按命令调节特征相当于注入任务相关先验，能减少无关视野干扰；它不是基于传感器实际置信度的统计融合。若前相机突然失效，仅凭速度方向并不能知道该相信后视记忆还是停止，这构成一个值得扩展的问题。

RSM也不应理解成越强越好。宽地面上遮挡侧边可以减少背景依赖，但稀疏落脚点可能刚好在侧边。这个例子提醒感知工程师：数据增强是否合理取决于任务可观测性，不能直接从图像分类复制裁剪规则。

## 训练监督与开源状态

先让地形专家学会利用特权高度图，再用学生实际观测进行DAgger式蒸馏；因此学生会经历不同于专家理想观测的分布。项目页展示DFSV和RSM消融，强调类似训练损失不意味着同样的分布外表现。[项目消融说明](https://rpl-humanoid.github.io/)

截至核查，作者项目仍标注Code Coming Soon，不能声称官方训练代码已可用。学习实验应定位为概念实现；等代码发布后，再对照真实数据预处理和延迟配置。[代码状态入口](https://rpl-humanoid.github.io/)

## 实验证据与边界

论文与项目展示G1在楼梯、斜坡、离散支撑面上的前后行走，以及负载相关实验。实机使用前后两台相机；四方向相机属于可扩展仿真设置。作者局限明确指出未展示真实侧向地形行走，且没有显式主动观察策略。[实验与局限](https://arxiv.org/html/2602.03002v1#S4)

这些边界对方案选型很重要：双向可用不等于全向已验证，携带负载的行走也不等于自主识别、抓取、搬运全部环节都由同一模型完成。项目视频说明存在加速播放，学习时应看正常速度和连续片段，不能凭演示播放速度估计感知与动作延迟。[作者展示说明](https://rpl-humanoid.github.io/)

## 局限与人形感知启发（推断）

值得借鉴的核心是“相机视野、运动方向、身体遮挡一起设计”。传统轮式平台相机常稳定朝前，而人形在转身、后退、下蹲和搬运时有效视野不断变化。传感器布局应由任务空间决定，不能只增加相机数量。

可以为每路图像增加年龄、有效像素比例和遮挡率，并与方向权重分开记录。方向相关性回答“有用吗”，质量估计回答“可靠吗”，两者不应混为一个数。再进一步，可研究深度与LiDAR在同一局部坐标中的互补，但必须对齐时间，特别是在躯干快速转动时。

局部地形输出与任务相关潜变量各有用途。前者便于故障分析，后者便于直接服务策略。感知团队可以先确定下游真正需要的是落足支撑、近场障碍还是完整体积空间，再选择是否保留显式地图。

## 轮式背景需要补什么

补浮动基座本体历史、自遮挡射线建模、多教师蒸馏和支持面概念；已有多相机标定、时间同步与采集驱动知识可直接复用。不必学习全局SLAM才能开展本篇相关工作，但应懂关节运动如何改变相机相对机器人身体的几何关系。

## 最小学习实验（设计，未执行）

1. 用简单仿真前后深度相机生成四种组合：两侧平地、前楼梯后平地、前平地后间隙、两侧不同地形。
2. 固定一个局部可落足区域预测任务，对比单前视、多视拼接、按命令方向缩放三种融合。命令包括前进、后退和静止，不直接尝试训练全身运动。
3. 单独测试前相机掉帧、后相机滞后一帧、摆臂遮挡和地形宽度变化；分开报告输入相关性与传感器质量。
4. 设置有无RSM对照，并在侧边存在唯一支撑块的测试场景中检查增强是否伤害有效信息。

验收：不同方向和故障条件的几何误差表、置信度与可见区域可视化，以及推理延迟分布。该实验是感知接口验证，不是RPL复现。
