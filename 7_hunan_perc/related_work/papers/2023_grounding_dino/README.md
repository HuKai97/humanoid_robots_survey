# Grounding DINO：把文字目标落到图像框

## 先读总结

Grounding DINO输入图像和名称或描述，返回相关目标框。它对人形感知的价值是快速指定当前要观察的物体，并作为分割、深度裁剪和位姿估计的入口。它属于视觉与语言融合，不是视觉、LiDAR、IMU的传感器融合，因此在本路线中作为补充能力。接入机器人后，最应关注目标是否找对、框中是否混入背景、分数是否稳定，以及运动和遮挡时何时重新检测，不能把二维框直接当成可执行抓取位姿。学习它也有助于厘清语义理解与度量几何之间的接口。[论文](https://arxiv.org/abs/2303.05499)

## 定位与输入输出

首次公开2023；优先级P2。输入是RGB和文本，输出框、词语匹配分数及短语。官方接口区分框筛选与文本筛选阈值，建议用句点分隔类别。文本token不严格等于自然语言的词，调试时应保留映射。[官方仓库](https://github.com/IDEA-Research/GroundingDINO)

输出含义应限定为某个图像区域与文本相关。原模型不提供米制距离、物体坐标轴或动作可达性，也不读取IMU或LiDAR。

## 方法流程与核心机制

图像、文本分别编码，在三个位置融合：特征增强时双向交换信息；查询选择时优先选与文本相关的图像位置；解码时同时参考视觉与文字，逐步修正框。训练结合框监督和对象—文本对齐。可理解为检测过程中持续使用文本，而不是先做固定类别检测再换标签。[全文第3节](https://arxiv.org/html/2303.05499)

Grounding DINO基于DETR路线的检测器DINO；DINOv2是自监督骨干。二者共享部分命名，不是同一个模型简单加文字分支。

## 训练数据与监督

预训练结合检测、短语定位和图像描述类数据，不同配置的数据组合不同。开放词汇不代表训练从未见过任何相关概念。阅读零样本COCO等结果时，应检查对应模型是否使用COCO或相关指代表达数据；正文讨论了数据混合与泄漏边界。[全文实验部分](https://arxiv.org/html/2303.05499)

## 实验证据与边界

检测基准与指代表达基准分别评估跨类别检测和语言定位，类别名称输入的成绩不等于复杂空间指令理解成绩。官方提供与SAM组合的入口，但组合仍需独立评估；原论文没有证明人形双臂遮挡和快速头动下的完整系统成功率。[官方实现](https://github.com/IDEA-Research/GroundingDINO)

## 工程迁移判断

以下为原创建议。可在低频语义分支运行检测，把框交给SAM2得到mask，再用对齐深度提取目标表面。不要简单取框中心的单个深度：杯把、空洞、背景和无效值都可能使它不在目标上。应检查mask内深度分布，并明确输出是可见表面位置还是物体中心。

LiDAR投影也要检查遮挡，同一像素可能覆盖前后景点，细腿与把手尤其明显。人形头部和腕部相机的外参随关节状态变化，需要同一时间的运动学变换；不能直接沿用固定车顶相机的静态外参假设。IMU可帮助划分运动程度，但接到外围不等于原网络已融合惯性。

建议记录图像时间戳、相机编号、文本版本和阈值，让失败能归因于提示、视觉、标定或同步。目标不存在时也必须允许输出空集合，否则开放词汇系统很容易产生看似合理的误检测。

## 局限与应补知识

补DETR查询、跨注意力、区域—词语对齐、开放集评估和阈值校准。相似度分数不天然等于正确概率，候选文本变化可能改变结果。多实例、罕见部件、动作含义应单独测试。“能拿的杯子”还涉及可达性与碰撞，语言框不能独立完成判断。

对已有轮式感知经验的人，最值得补的不是另一套框评估脚本，而是指代对象与动作对象的一致性。例如检测到整个抽屉，对控制而言可能需要把手；这要求明确层级，不宜让后处理自行猜测。

## 最小学习实验（建议，未执行）

准备60张头部视角图像，覆盖无遮挡、多实例、遮挡、模糊，并包含目标不存在的场景。人工框目标，为相同目标准备类别名、属性短语、近义词三种提示。固定模型，扫描两个阈值，统计漏检、误检、错实例与空场景误报。

再仅对检测正确的样本加入真实深度，比较框中心深度与mask内稳健统计的3D误差。分别记录检测失败和几何失败，避免综合成功率掩盖原因。阈值只在开发集选取，相邻帧不跨开发与测试。产出应包含失败图片、提示字符串、阈值及几何参考定义。该实验判断它是否适合当前前端，不是训练新模型。

阈值选择还应考虑业务代价：漏掉远处无关物体与抓错近处目标的后果不同。可以分别绘制目标存在和目标缺席两组的分数分布，检查是否真能找到稳定的工作区间。
