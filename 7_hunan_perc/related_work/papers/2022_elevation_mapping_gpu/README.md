# Elevation Mapping for Locomotion and Navigation using GPU

## 先读总结

这篇工作把点云变成可供足式机器人使用的局部高程表示，并把融合、清理和地形分析放到 GPU 上处理。对轮式感知工程师，它连接了熟悉的点云与代价地图和人形的新需求：落脚区域、台阶边缘、坡度与近场地形。值得学习的不只是加速，而是未知区域、陈旧障碍、姿态误差和过滤器如何改变地形。本调研只研究外部位姿已提供时的局部感知表示，不研究 SLAM。它的主要实机证据来自四足机器人，迁移到人形需要另行验证。

## 问题、输入与输出

输入为深度传感器点云和外部位姿；输出是机器人附近的高程及相关层，可再提取法向、可通行性与平面。原文在 ANYmal 等四足实验中使用 LiDAR 或多深度相机，不能写成已在人形平台验证。[原文](https://arxiv.org/html/2204.12876)

## 具体机制

把观测变换到统一局部坐标后，根据测量不确定性更新栅格高度；同时处理高度漂移、可见性清理和旧层残留，最后生成给规划或控制使用的地形特征。GPU 的意义是让大量点与栅格运算并行，减少处理积压。当前仓库还包含后来的 MEM 语义扩展；那不是这篇 2022 论文的全部原始贡献。[官方实现](https://github.com/leggedrobotics/elevation_mapping_cupy)

## 如何理解 2.5D：原创学习推导

一个水平网格位置存一个地面高度，意味着它无法同时完整保存“桌面、桌下地面、横梁”这类多层结构。删除高处点可能让脚下地图更干净，却可能把头部或手臂会撞上的东西删掉。对于人形，建议将落脚高程与身体碰撞几何分别表达，共享传感器但不要强行共享唯一高度值。

加权更新也有一个重要前提：新旧观测应指向同一物理区域。若姿态或时间有误，两块不同地形被落到同一个单元，即使统计融合公式正确，结果仍然错误。因此应在接入地图前验证时间与坐标链。

## 实验能说明什么

原文通过模块对比、运行时间与足式任务展示该表示的实用性。这里不搬用其设备上的运行频率作为你平台的承诺。地图大小、分辨率、点数、GPU 拷贝和输出频率都会影响端到端数据年龄。网络或核函数的单次耗时不等于控制器拿到的数据有多新。

## 局限和人形迁移判断

高程适合描述地面，但不是任意三维环境的完整表达。平滑会削弱台阶边缘，补全可能把未知区域误成支撑面；这些处理必须保留有效性与来源。仅几何也无法保证接触后的承载能力或摩擦。你可以把这一框架当作易调试的基线，再与直接深度特征路线比较，而不是先假定端到端一定更优。

## 需要补的知识

二维代价地图与高程图的区别、栅格分辨率的量纲、测量不确定性、射线可见性、未知与自由空间、局部坐标系和位姿插值。不需要自行实现 SLAM。

## 最小学习实验（建议，未执行）

构造台阶、桌下空间与凹坑三段有真值的短序列；固定外部位姿，比较原始高程、平滑高程、补全高程。分别统计台阶边缘偏移、未知区域误填率和地面高度误差，并可视化从俯视图看不出的悬空障碍。第二轮才引入已知姿态扰动，隔离表示误差与上游误差。
