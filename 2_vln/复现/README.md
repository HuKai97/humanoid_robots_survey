# 复现计划：从一条可重放轨迹开始

> 当前只有计划，没有安装环境、下载数据、运行模型或实机测试。按 research-workflow 的顺序，先复现基线，再依据失败建立研究假设。

## 选择顺序

| 候选 | 为什么值得复现 | 开始前必须解决的事项 |
|---|---|---|
| VLN-CE 官方 baseline | 任务接口与 evaluator 清楚，适合第一次理解完整闭环 | 论文与当前 README 成绩/版本可能不同；固定依赖、数据和配置 |
| ETPNav | 理解在线拓扑图与连续路径执行 | 全景 RGB-D、位姿和 waypoint 预测器的来源；额外预训练依赖 |
| NaVid 官方可用权重 | 理解视频输入与动作解析，接近当代 VLM 导航 | 公开权重训练策略和数据已发生变化；单独记录训练口径 |
| StreamVLN | 长程历史与推理资源的关系 | token pruning 等模块的深度/里程计依赖，模型与仿真资源需求 |
| InternNav / DualVLN | 进入物理具身与双系统导航 | 精确区分 RGB DualVLN 与 RGB-D NavDP*，选择一个官方配置 |
| NaVILA | 语言导航到腿式运动接口 | 高层、低层、benchmark 是不同组件；确认机器人适配与权重 |

优先建议：**先读 VLN-CE 的接口和评测，再按硬件选一个可运行基线；第二个基线选择与第一个不同的动作/记忆结构。** 不要同时维护六套环境。上述官方链接、具体限制和阅读范围见 [文献索引](../related_work/README.md)。

HumanoidVLN 的资源目前依作者承诺待发布；TANGO 官方代码可用性本次未核实。它们适合先阅读和设计问题，不能作为已具备资源的默认复现入口。

## 最小复现的验收顺序

1. 在报告中写清论文版本、仓库 commit、依赖和权重。先比较官方配置，不自行升级依赖或替换视觉编码器。
2. 确认场景能渲染、任务能 reset、相机参数正确；用一个合法动作检查位置和观察确实变化。
3. 只运行一条 episode，保存指令、图像、模型输出、解码动作、实际位移、终止原因和时间戳。
4. 逐项检查传感器坐标系、角度单位、深度单位、动作步长、STOP 逻辑和距离指标。
5. 固定小子集，运行官方 evaluator，产出完整日志。指标合理后才扩展到完整验证集。
6. 按失败类型归档：语言/地标、记忆、目标选择、动作解析、局部避障、执行误差、停止、超时。
7. 对照原论文与官方 README 的相同配置；未达到参考成绩时，先解释差异再改变模型。

## 从仿真转向人形的接口清单

导航层与控制层需共同约定：路点坐标系、速度范围、动作持续时间、命令频率、停止与超时处理、执行失败的反馈形式。主模型的推理速度与机器人低层控制频率分别记录；两者不是同一个数。

先使用机器人已有的可验证行走接口。在仿真检查相机高度、晃动、身体尺寸和延迟对导航的影响，再逐步走向实际平台。每次只替换一个模块，避免同时修改导航、定位和步态后无法判断收益来源。

## 环境现状

本次没有检查用户 GPU/机器人设备，也没有测试仓库安装可行性。官方 [Habitat-Lab](https://github.com/facebookresearch/habitat-lab) 与 [Isaac Lab](https://github.com/isaac-sim/IsaacLab) 的当前状态已查询，但下一次安装必须以所选论文配置为依据。

复制 [复现报告模板](复现报告模板.md) 建立方法目录；所有真实指标按 [评测约定](../experiment/evaluation.md) 写入。
