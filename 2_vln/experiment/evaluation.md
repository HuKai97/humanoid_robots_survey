# 评测约定：先固定条件，再看成绩

> 状态：调研阶段拟定的评测协议 v0；尚未运行实验。正式复现前，按所选 baseline 的官方配置填写精确版本并冻结为 v1。下面的项目指标是本项目建议，不冒充社区统一的人形 VLN 标准。

## 1. 第一轮评测范围

建议主任务为 R2R-CE 的官方 val-unseen；初期固定一个有 scene ID 清单的调试子集，完整验证后再评估完整 split。子集结果必须写“调试子集”，不能当成整套 benchmark 成绩。val-unseen 可用于研究迭代，最终泛化结论应在未用于调参的测试场景上确认。

第二阶段根据资源选择 VLN-PE 或可获得的人形物理基准。不要直接将它与 R2R-CE 的成功率作同条件比较。RxR-CE 可用于更长指令/跨数据评估，但须说明训练是否使用 RxR；REVERIE/SOON 属于不同任务，另设结果表。[VLN-CE 官方](https://github.com/jacobkrantz/VLN-CE)、[RxR 官方](https://github.com/google-research-datasets/RxR)

## 2. 每个结果必须绑定的配置

| 项目 | 必须保存的内容 |
|---|---|
| 数据 | 数据版本、split、scene IDs、episode IDs、样本数、过滤原因 |
| 模型 | 代码 commit、checkpoint 标识、训练数据、随机种子、精度/量化 |
| 观察 | RGB/深度/位姿来源，相机高度/FOV/分辨率/帧率，是否全景 |
| 先验 | 是否预扫描地图、使用真值定位/候选点/语义标注、是否跨 episode 保留记忆 |
| 动作 | 离散动作、路点、速度或关节目标；步长、频率、最大步数/时间 |
| 执行 | 仿真器和版本、身体参数、控制器版本、是否瞬移/运动学执行/物理执行 |
| 计算 | GPU、推理端/本地/远端、预处理、通信、排队和执行延迟 |
| 结束 | STOP 判定、距离阈值、超时、碰撞/跌倒/人工介入处理 |

记录训练时的额外信息与测试时可用信息，尤其避免把 ground-truth pose、ground-truth semantic mask 和预先已知连通图当作真实传感器输出。

## 3. 指令导航的基础指标

对第 i 条任务，令成功指示为 S_i，最短可行路径长度为 L_i，实际路径长度为 P_i。路径单位使用米。

- **SR**：成功任务数/总任务数。R2R 及常见 R2R-CE 采用接近 3 m 的目标邻域，但严格不等号、距离定义、STOP 条件以对应官方 evaluator 为准；新的人形近目标任务不得直接照搬该距离。
- **SPL**：`mean(S_i * L_i / max(L_i, P_i))`。失败为零；成功但绕路会下降。退化零路径样本按官方评测器处理。
- **NE**：停止位置到目标的导航距离；明确使用场景可行路径距离还是欧氏距离。
- **OSR / Oracle Success**：路径中是否曾进入目标邻域，有助于发现“到过但没停”的问题。它不代替最终 SR。
- **nDTW / SDTW**：评价预测路径与参考路径的顺序和几何相似性；SDTW 还考虑成功条件。长指令和明确要求途经点时很有用。

指标依据：[R2R](https://arxiv.org/abs/1711.07280)、[SPL/导航评测建议](https://arxiv.org/abs/1807.06757)、[nDTW 原论文](https://arxiv.org/abs/1907.05446)。统一注明是 `[0,1]` 还是百分数，不能把 0.35 和 35 混在同一列。

**教学例子**：最短路径 10 m，实际走了 20 m 且成功，该 episode 的 SPL 为 0.5；若另一条路线更短但跳过指令要求的地标，SPL 可能很好，所以还需要 nDTW 或明确的指令遵循评估。

REVERIE/SOON 另报其官方目标定位/grounding 指标，不用导航 SR 掩盖指错物体的情况。

## 4. 人形阶段增加的项目指标

| 维度 | 推荐记录 | 必须提前定义 |
|---|---|---|
| 稳定性 | 每 episode 跌倒率、恢复次数 | 跌倒的姿态/接触判据，恢复是否算成功 |
| 碰撞 | 发生碰撞的 episode 比例；碰撞事件次数；身体部位 | 连续接触如何合并为事件；接触阈值；足地正常接触如何排除 |
| 执行 | 局部目标到达率、速度跟踪误差、任务耗时 | 坐标系、时间窗口、成功容差 |
| 停止 | 最终距离、越过目标距离、错误 STOP | STOP 对应下发命令时间还是实际静止时间 |
| 计算 | 观察到命令的端到端延迟 P50/P95、推理/通信分项 | 是否包含预处理、排队、网络；执行与推理是否异步 |
| 干预 | 急停、人工辅助、重置次数及原因 | 人工介入后不得继续记为无人辅助成功 |
| 泛化 | 分身体、相机高度/视角、场景与语言类型报告 | 哪些配置参与训练或调参 |

“无碰撞且未跌倒的导航成功率”可作为项目附加复合指标，但同时报告原始 SR、碰撞率、跌倒率，不能改变论文官方成功定义后沿用原名称。这些指标来自本项目部署需求；物理问题背景参考 [VLN-PE](https://arxiv.org/abs/2507.13019)、[HumanoidVLN](https://arxiv.org/abs/2608.12860)。

## 5. 对照实验与不确定性

先保存官方 baseline 配置。涉及新模块时，必须与“去掉该模块”的同输入同控制器配置比较；若使用 oracle 目标/定位，它是诊断参照，不是可部署成绩，也不一定构成严格数学上界。随机/打乱指令等对照先在仿真进行，并保持终止条件一致。

初期只改一项变量，如相机俯仰扰动、动作延迟或历史长度。不同训练随机种子原则上至少 3 次并报告均值和离散度；资源不足时明确只有单次。确定性固定权重评测仍需记录任务样本数；实机重复次数须预先确定。场景很少时按场景分组报告，不能把高度相关的连续帧或重复指令当成独立样本虚增置信度。

## 6. 每版保存的材料

```text
experiment/v1_baseline/
  config.yaml          # 数据、模型、传感器、控制、版本
  episodes.jsonl       # 每条任务的原始指标与终止原因
  metrics.json         # 汇总及分组结果，保留样本量
  trajectories/        # 路径、动作与时间戳
  visualizations/      # 地图叠加、目标与停止位置
  failure_cases.md     # 固定失败集 + 本次新失败
  runtime.md           # 硬件与耗时口径
```

至少保留固定的 5–10 条诊断样例（规模允许时），加一条成功样例；从首个错误观察或动作开始解释失败。所有结果追加到 [results.md](results.md)，不删除失败实验。
