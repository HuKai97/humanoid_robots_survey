# StreamVLN：在线导航中的长记忆与低延迟

**论文**：StreamVLN: Streaming Vision-and-Language Navigation via SlowFast Context Modeling。首次提交 **2025-07-07**，已查 v2 更新于 2026-07-09；摘要与官方仓库确认 **ICRA 2026**。优先级 **P1**。核查日期：2026-09-29。

## 先读总结

StreamVLN 关注“机器人持续看视频时，怎样保留路线历史又及时输出动作”。它用快速更新的近期对话和较慢更新的历史记忆处理连续视觉流，并复用 KV cache 减少重复计算。原作者实机部署是 **Unitree Go2 四足机器人**，不是人形；后续 HumanoidVLN 将它纳入人形物理仿真比较。这是可迁移的导航上层，不是独立的人形运动控制器。[摘要](https://arxiv.org/abs/2507.05240) [官方代码](https://github.com/InternRobotics/StreamVLN)

## 问题、输入与输出

路线越长，历史视频越多。全部重算会增加推理延迟，只保留最新一帧又可能忘记“这是第二个路口”。模型以 LLaVA-Video 为基础，将视觉、语言和动作交错组织成在线多轮上下文，预测导航动作。机器人动作仍需执行层落实，而不是大语言模型直接维持身体平衡。[论文 HTML](https://arxiv.org/html/2507.05240v2)

## 方法如何工作

快速上下文保留滑动窗口中的近期交互，以较细时间粒度响应；慢速记忆压缩已见场景，让上下文规模不随路线无限增长。作者利用三维体素空间识别重复的视觉 patch，裁掉重复 token，同时缓存可复用的注意力键值。[项目页](https://streamvln.github.io/)

**传感器口径必须读清**：3D token pruning 要把图像 patch 反投影到共享空间，使用 depth 与 odometry。论文表格脚注明确这两项用于裁剪。主模型输入以 RGB 图像为主，不等于整个实现完全不需要额外几何信息；与严格 RGB-only 方法比较时必须标出开关和来源。[HTML §III 与表 I 脚注](https://arxiv.org/html/2507.05240v2)

## 实验到底证明了什么

原文评估 VLN-CE，并在走廊、卧室、办公室进行实机比较，每个场景、每种方法 20 次试验；仓库公开 Go2 部署说明。官网还提供多类环境的视频。证据支持流式记忆在该部署中兼顾指令跟随和计算效率；它没有直接给出人形步态、跌倒恢复或全身避障能力。[论文实验](https://arxiv.org/html/2507.05240v2) [部署入口](https://github.com/InternRobotics/StreamVLN)

仓库记录过历史帧参数传递的评测修复，以及数据版本切换和不同用途权重。复现时应保存 commit、checkpoint、R2R 数据版本、history 参数；不能拿修复前后两套配置当算法差异。

## 局限与人形迁移分析

**本调研分析**：少算几次不一定等于闭环更可靠。需要测从相机采集到命令执行的整链延迟，而不只报告模型前向时间。人形相机周期性摆动可能把同一地点呈现为很不同的图像，也可能让反投影受姿态误差影响。可在复现后控制记忆长度、几何误差和延迟，观察错误来自遗忘还是错误保留；这是待验证设计。

## 初学者阅读与复现入口

先理解 Transformer 的 KV cache 与滑动窗口，再画“新帧如何进入快上下文、何时进入慢记忆”。随后核对训练和部署权重的区别。与 NaVid 比较历史压缩方式，与 JanusVLN 比较显式几何裁剪和隐式几何记忆。先进行官方仿真评测，部署资源由后续硬件条件决定。
