# ETPNav：连续环境中的在线拓扑规划与避障执行

**论文：** ETPNav: Evolving Topological Planning for Vision-Language Navigation in Continuous Environments，Dong An 等。**年份：** arXiv 首发 2023；作者官方仓库标注 TPAMI 2024。**优先级：P0。** 本次范围：arXiv HTML v3 的任务、方法、实验章节及官方仓库 README；未运行实现。

## 先总结

ETPNav 将 VLN-CE 拆成航点预测与建图、语言条件规划、低层避障执行。它适合作为理解分层导航的代表基线。但论文明确使用模拟器真实位姿，不能把“没有预先环境地图”写成“已经解决真实机器人定位”。[正文 §III](https://arxiv.org/html/2304.03047v3)

## 输入输出与假设

输入为语言、12 个水平朝向的 RGB-D 视图及真实位姿；高层输出拓扑子目标，低层输出前进、转向和 STOP。节点分为当前、已访问和尚未访问的 ghost 节点。测试时地图在线建立；训练时仍使用数据和专家信息。[正文 §III](https://arxiv.org/html/2304.03047v3)

**学习解释：** “没有预先地图”“没有专家监督”“没有准确定位”是三件独立的事。复现和论文对比应逐项标注，不能用一个 map-free 标签把它们混在一起。

## 方法步骤

1. 从深度预测附近候选航点，按空间位置将重复预测合并到拓扑图。
2. 跨模态图 Transformer 对齐地图与指令，挑选远程目标，再规划经过已知节点的路径。
3. 控制器先转向再前进；遇到位置不变的卡住情况时，通过 Tryout 尝试其他朝向。[正文 §III-A–C](https://arxiv.org/html/2304.03047v3)

官方仓库提供 R2R-CE / RxR-CE 实现和训练资源入口，使用较早版本的 Habitat；这些条件需要在复现时固定。[官方实现与发表信息](https://github.com/MarSaKi/ETPNav)

**学习解释：** 高层决定目的地，低层负责到达，这种分工让失败更容易诊断。但如果航点本来就在障碍内部，规划器再强也无济于事；反之，子目标合理而控制器卡住，也不应被误诊为语言理解错误。

## 实验与证据

原文 Table II 的 **R2R-CE test-unseen** 结果为 **SR 55%、SPL 48%**。这是全景 RGB-D、真实位姿及原文环境设置下的完整系统结果。本文不采用摘要“提升 10% / 20%”作为跨方法结论，因为必须先明确指标、split 和百分比口径。[正文 Table II](https://arxiv.org/html/2304.03047v3)

## 局限与人形机器人的关系

**事实边界：** 论文评估 R2R-CE 与 RxR-CE 仿真导航；未提供人形实机 locomotion 验证。不同 benchmark 对身体半径和碰撞滑动的设置不同，不能仅凭同为 CE 就直接比较。

**本项目分析：** 可供人形系统借鉴的是模块接口：语言规划器输出位置子目标，locomotion 控制器跟踪该子目标。真正部署还需验证单前视相机如何补全全景、位姿漂移如何破坏节点合并、子目标是否符合身体通行条件，以及发生卡住时哪些恢复动作可执行。Tryout 在圆柱模拟器里有效，不等于双足机器人能照样安全原地试探。

## 初学者阅读与复现准备

先学 VLN-CE 和 DUET，再读本篇 Figure 1 与 §III。后续优先评估作者 checkpoint，按失败层级记录：航点、节点合并、目标选择、低层执行、STOP。必须保存 `sliding` 设置和位姿来源。

一个合适的第一轮研究练习是保留语言规划器，分别引入受控位姿扰动或限制视野，观察性能如何变化；应在 baseline 能稳定复现后再实施。当前只是待验证问题，尚无实验结果。官方仓库历史依赖也需先做可用性检查，而非直接安装到现有环境。
