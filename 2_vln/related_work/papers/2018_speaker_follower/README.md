# Speaker-Follower：用“描述路线”帮助“跟随指令”

**论文：** Speaker-Follower Models for Vision-and-Language Navigation，Daniel Fried、Ronghang Hu 等。**年份：** 2018 首发，NeurIPS 2018。**优先级：P1。** 本次范围：论文 HTML 方法、实验和搜索附录重点；作者项目页、官方代码 README。未审计全部实现，也未运行模型。

## 先总结

Follower 根据指令选择路线；Speaker 根据路线生成指令。作者让 Speaker 一方面合成训练数据，另一方面为候选路线重新打分，再结合全景动作空间改善导航。这是理解 VLN 数据增强、路径级推理和搜索评测的重要起点。[作者项目页](https://ronghanghu.com/speaker_follower/)

## 背景、输入输出与假设

任务仍是 R2R 的图上导航。输入为指令与沿途视觉观测；输出为图节点路线及停止动作。全景动作空间允许模型直接考虑周围可达方向，但可达候选仍来自模拟器，不能将其等同于机器人自主发现自由空间。[正文 §3](https://arxiv.org/html/1806.02724)

**学习解释：** 设有两条路线都经过“门”，但只有一条继续经过沙发。逐步 Follower 可能过早选错门；Speaker 会判断哪条完整路线更可能被人描述为当前指令。关键概念是改变条件概率的方向，而不是给机器人增加语音合成器。

## 方法分三步理解

1. 先用人工路线—指令对训练 Follower 和反向的 Speaker。
2. 在训练环境采样新路线，用 Speaker 配上合成指令，扩充 Follower 的训练集。
3. 推理时让 Follower 搜索候选路线，再融合 `P(指令 | 路线)` 与 `P(路线 | 指令)` 选择路线。[正文 §3.1–3.3](https://arxiv.org/html/1806.02724)

官方仓库说明增强数据沿用 R2R 格式，并采用先混合原始与增强数据训练、再在人工数据微调的流程。[官方实现 README](https://github.com/ronghanghu/speaker_follower)

**学习解释：** 第二步增加覆盖面，第三步帮助消歧，是两个不同用途。做消融时不能把二者合并成一个“用了 Speaker”的开关，否则无法判断收益来自数据量还是决策方式。

## 实验与证据

论文附录 Table C.1 中，R2R **val-unseen** 的完整系统 SR 为 **54.6%**，移除 Speaker 路径评分但保留搜索的变体为 **43.7%**。这一组对比支持路径重评分有贡献；它不是无搜索、单次在线策略之间的比较。[正文附录 C](https://arxiv.org/html/1806.02724)

## 局限与人形关系

**事实边界：** 候选搜索与最终路线评测涉及不同推理设置，论文另给出满足 challenge 要求的顺序执行版本；读分数必须同时读轨迹生成协议。没有人形实机证据。

**本项目分析：** 实体机器人试走错误分支会消耗时间和电量，不能把仿真里免费比较多条候选路径的收益直接迁移。为人形系统设计语言生成数据时，还应检查“穿过窄门”等指令是否有身体可通过的路径。语义通顺不等于运动可执行；Speaker 能扩充语言样本，却不能自动提供机器人可达性标注。

## 初学者阅读与复现准备

先画两个箭头：“指令 → 路线”“路线 → 指令”，再阅读 §3 的条件概率和附录搜索说明。官方代码基于较早的 PyTorch 与 Matterport3D Simulator；本次没有安装这些历史依赖。[官方仓库](https://github.com/ronghanghu/speaker_follower)

未来优先做三项诊断：固定数据仅改变搜索；固定搜索仅添加增强数据；把实际走过的探索路程计入评测。对每种设置保存 SR、SPL、轨迹长度和搜索预算，避免把最终选中路径误当机器人全部执行成本。
