# NaVILA：把语言导航接到腿式机器人上

**论文**：NaVILA: Legged Robot Vision-Language-Action Model for Navigation。首次提交 **2024-12-05**，arXiv v2 为 2025-02-17；作者项目页确认 **RSS 2025**。优先级 **P0**。资料核查日期：2026-09-29。

## 先读总结

NaVILA 是进入人形 VLN 很合适的桥梁：它把任务分成“看图、理解指令、提出下一段移动要求”和“用腿稳定完成移动”两层。上层输出带距离、角度的中层语言动作，下层 locomotion 策略执行。论文包含四足和人形实机，因此与人形 VLN 直接相关；它也说明上层可迁移，并不意味着下层步态控制器能够原封不动跨机器人复用。[论文摘要](https://arxiv.org/abs/2412.04453)

## 问题、输入与输出

用户说“穿过走廊，在桌子附近停下”，与驱动关节的命令之间相距很远。NaVILA 的上层读取语言指令及第一视角 RGB 历史，生成类似“前进某段距离”“向右转某个角度”的空间动作。下层结合环境感知与机器人状态完成运动；Go2 的视觉 locomotion 使用由 LiDAR 点云生成的高度图，因此上层 RGB 输入不代表全栈 RGB-only。这里的 VLA 输出不是逐关节力矩；导航决策与接触、平衡控制有不同时间尺度。[HTML 方法部分](https://arxiv.org/html/2412.04453v2)

## 方法如何工作

上层由 VLM 适配而来，训练资料结合模拟导航、真实人类游览视频及问答数据；中层空间语言让这些不同来源能够共享动作表示。下层采用视觉 locomotion 强化学习，并在物理模拟器中学习运动与避障。作者还建立 VLN-CE-Isaac，将导航模型放到真实接触动力学中评测，而不只让一个抽象代理按指定步长平移。[作者项目页](https://navila-bot.github.io/)

**理解方式（本调研分析）**：这套接口相当于把“想去哪里”和“怎样迈步”拆开。对初学者，最值得画清楚的是每层的输入、输出、更新频率和失败时谁负责重试，而不是先背网络模块名字。中层动作如果距离估计偏大，下层即使不摔倒，也可能越过应当转弯的路口。

## 实验到底证明了什么

论文在 R2R-CE、RxR-CE 与物理模拟环境中评估，并给出 Unitree Go2、Booster T1 的实机任务；正文说明 T1 使用相同上层 VLA，无须为该人形重训上层。项目页另展示 Unitree G1。应分别记录“论文内定量实机平台”和“项目补充演示平台”，不能把视频演示自动算作与正文同规模的评测。[HTML 实验部分](https://arxiv.org/html/2412.04453v2) [项目展示](https://navila-bot.github.io/)

本笔记不抄跨平台 SR 排名：人形与四足的身体尺寸、相机高度、可通行空间不同，仅共用语言模型不足以保证公平比较。现有证据支持层次系统可部署，不能推出任意新身体、楼梯或长时间开放环境都可靠。

## 局限与可迁移问题

**本调研分析**：中层语言接口简单、便于调试，但表达弯腰、收臂等全身几何调整的能力有限；导航正确而局部运动失败，以及语言误解而稳定走错，是两种不同错误。后续应固定上层权重，分别测试身体尺寸、相机晃动、动作执行误差；这些只是复现后值得验证的问题，尚非创新结论。

## 初学者阅读顺序与复现入口

先看系统图，再追一条“观察→中层动作→下层执行→新观察”的闭环；之后看真实机器人实验，最后看训练细节。建议先读 VLN-CE，再读本文，再读 VLN-PE。作者分别维护 [VLA 代码](https://github.com/AnjieCheng/NaVILA) 和 [locomotion 代码](https://github.com/yang-zj1026/legged-loco)；阅读时不要把两者依赖混为一套环境。
