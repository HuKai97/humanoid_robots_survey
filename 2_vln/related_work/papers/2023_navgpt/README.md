# NavGPT：Explicit Reasoning in Vision-and-Language Navigation with Large Language Models

**检索日期：2026-09-29｜优先级：P1｜类别：零样本 LLM、离散图 VLN。** 首次 arXiv：2023；正式发表：AAAI 2024。作者：Gengze Zhou、Yicong Hong、Qi Wu。[官方仓库](https://github.com/GengzeZhou/NavGPT)

## 先读总结

NavGPT 将视觉场景、候选移动方向和历史压缩成文字，再让 LLM 输出解释与下一步动作。它适合学习语言模型如何参加导航决策，以及把视觉转成文字会丢失什么。作者明确承认其零样本 R2R 性能仍落后于经过训练的专用模型。[论文摘要](https://arxiv.org/abs/2305.16986)

## 问题、输入输出与训练

任务是在 R2R 的离散导航图上跟随路径指令。系统输入包括多方向视觉观测、候选节点信息和历史；LLM 实际读取的是这些信息的文字化版本。输出是可执行的候选 viewpoint ID 或停止决定，而不是人形关节命令。导航阶段不训练新参数，但依赖已经预训练的视觉模型和商业 LLM。仿真提供的候选连通性与深度信息也是系统条件，不能将它描述为单目 RGB 自主避障。

## 核心机制

1. 用图像描述模型将多方向观测翻译成文字，并补充物体与空间线索。
2. 组织指令、合法候选节点、当前朝向以及历史为统一提示。
3. LLM 给出导航解释及动作，解析器提取合法动作并推进模拟器。
4. 将新的观测和动作加入历史；过长历史用摘要压缩，循环直到停止。

这里的文字解释为调试提供线索，但“解释合理”与“动作正确”需要独立评估。[HTML 正文 §3](https://arxiv.org/html/2305.16986)

## 实验事实与证据边界

论文在 R2R 未见环境中比较 GPT 模型与监督式方法，并分析视觉描述粒度、历史摘要带来的影响。本文不摘录未逐表核对的分数。官方 README 给出 GPT-4 验证入口及少量样例运行方案；仓库支持自定义 LLM。2026 年重新调用同名服务未必等同论文时期模型，应记录实际版本、提示、返回与费用；本次未发起任何付费 API 调用。[官方复现说明](https://github.com/GengzeZhou/NavGPT#-r2r-navigation)

## 局限与人形 VLN 关系（分析）

误差会串联：图像描述漏掉门，历史摘要忘掉已经转弯，语言决策就可能重复探索。候选图使模型不必处理连续空间中“眼前到底能不能走”的问题。用于人形时，可借鉴子目标管理和失败解释接口，但需要实测观测噪声、执行延迟及可达性验证；它没有提供双足平衡或楼梯跨越的证据。迁移讨论应始终标明控制层还缺什么。

## 初学者学习与后续复现

先读一条完整 episode：原指令、观测文字、候选列表、选择结果、最终轨迹。手动给错误分四类：视觉遗漏、指令顺序、历史遗忘、动作解析。建议先阅读已发布示例与 prompt，再用极小固定集合比较描述格式；替换 LLM 属于新配置，不可把分数直接称为原文复现。后续若对比 NavGPT-2，应注意后者经过任务训练，两者的数据和训练条件不同。

阅读自测：如果两条走廊的文字描述相同，模型还剩下哪些定位依据？如果删去历史后仍选对动作，这条样例是否真的考察了长程记忆？这些问题能帮助你判断展示案例支持了多强的结论。
