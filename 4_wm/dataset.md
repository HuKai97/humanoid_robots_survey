## 当前默认选择建议

先用一个能重复采样、重置和闭环执行的小仿真任务。偏控制选 DMControl；偏三维感知选一个 ManiSkill 操作任务。等数据流、动作索引和评测跑通，再使用人形地形环境或真实日志验证任务特有问题。这是循序渐进的工程建议，不代表操作结果已验证人形能力。

不要一开始合并多个机器人数据集。相同长度的动作向量可能分别表示末端位置增量、关节位置、速度或力矩，坐标系和控制频率也会不同；简单归一化无法消除这些语义差异。

## 将来每条轨迹需要记录的字段

| 字段 | 应记录的内容 |
|---|---|
| 标识 | dataset_version、episode_id、scene_id、object_id、robot_id、terrain_id、采集策略 |
| 时间 | 每类传感器原始时间戳、动作发出时间、动作实际执行时间（若可得）、同步方法 |
| 观测 | RGB/深度/点云及有效掩码；相机内外参；关节状态、IMU；可得的接触信息 |
| 动作 | 单位、坐标系、控制周期、归一化、夹爪编码、目标或实际执行量 |
| 标签 | 奖励/终止/成功；仿真真值只作指定监督或上界，不泄漏部署输入 |
| 处理 | 裁剪、缩放、深度单位、点采样、坐标变换、插值、缺失值规则、代码版本 |
| 划分 | 固定 split manifest、按哪种泛化维度划分、相邻轨迹/场景去重方式 |

## 数据验证顺序

1. 先可视化一个 episode 的图像、动作、位姿和时间戳，人工检查动作作用对应哪次观测变化。
2. 用已知刚体变换检查点云坐标，避免米/毫米、相机系/世界系混淆。
3. 检查训练统计量仅用训练集计算；部署不可得的未来帧、成功标签和接触真值不进入被测方法输入。部署时合法提供的目标图像、目标位姿或任务指令可以作为条件，但各对照必须一致，并标明来源。
4. 先生成完整轨迹级 split，再切训练窗口；跨窗口重叠不能跨集合。
5. 同一真实场景若有重复采集，按场景或采集批次整体划分；具体维度与声明的泛化目标一致。

数据实体将放 `DataSet/`；清单与处理脚本应小而可追溯。每次新增数据都更新本文件，当前目录中没有数据实体。
