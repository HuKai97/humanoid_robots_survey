# OccWorld：让三维占据感知继续预测未来

## 元数据与阅读范围

- 标题：OccWorld: Learning a 3D Occupancy World Model for Autonomous Driving。
- 作者：Wenzhao Zheng、Weiliang Chen、Yuanhui Huang、Borui Zhang、Yueqi Duan、Jiwen Lu。
- 首发 2023-11-27；ECCV 2024。
- 类别：三维语义占据时序预测、场景与自车轨迹联合建模。**自动驾驶跨领域方法参考，不是人形机器人证据。**
- 核验日期：2026-09-29；证据等级 **B+：HTML 方法/实验 + 官方项目与 README**；方法以已读 v1 为准，无本地复现。
- 优先级：P1；若你原来做占据、BEV、多传感器感知，优先级可提高。
- 来源：[摘要](https://arxiv.org/abs/2311.16038)、[HTML](https://arxiv.org/html/2311.16038v1)、[项目](https://wzzheng.net/OccWorld/)、[代码](https://github.com/wzzheng/OccWorld)。

## 30 秒总结

传统占据感知回答“哪些三维位置现在被什么占着”；OccWorld 将历史占据压缩成 token，再预测后续占据和自车轨迹。它提供从三维感知走向时空预测的典型结构。但其原始主干是联合预测自车与环境演化，不能直接等同于“自由输入任意人形关节动作就能模拟后果”的反事实控制模型。[论文摘要](https://arxiv.org/abs/2311.16038)

## 方法拆解：表示、预测、使用

场景 tokenizer 通过重建式训练把占据压缩为离散 token；时空 Transformer 学习场景 token 和自车 token 的下一步演化，再解码成未来占据与轨迹。论文关注历史场景与历史自车运动，不直接学习油门/转向执行器动力学；它假定有合适的底层控制器。这个任务定义很重要，因为“预测轨迹”与“闭环执行后仍能保持安全”存在中间环节。[HTML 第 3 节](https://arxiv.org/html/2311.16038v1)

项目区分使用真值占据与不同感知模块输出占据的设置，并在 Occ3D 做未来占据评估、在 nuScenes 做运动规划评估。这个分层设计很适合研究感知误差会怎样传到未来预测：可以先替换上游感知，保持后端不变，再替换后端，保持输入不变。[官方项目](https://wzzheng.net/OccWorld/)

## 相对传统感知的变化

你可能熟悉 voxel、BEV、语义点云的精度评价。进入世界模型后，关键问题变为：相同的当前占据能否对应不同未来；模型有没有足够历史来判断速度；被遮挡区域是否用合理的不确定性表达；模型改变后的未来是否改变规划动作。单时刻 mIoU 高，并不保证对象交互、速度和长时占据可靠。

**本调研的判断：**占据适合表达空间阻挡和可通行性，却不自动包含摩擦系数、接触力和物体是否可推动。对人形而言，一块地面“有占据”甚至“语义为地面”仍不足以决定能否落脚；还需坡度、可承载性、足端接触状态等。因而直接把自动驾驶占据网络改名为人形世界模型，无法建立完整研究论证。

## 实验证据与局限怎样读

论文报告未来占据和轨迹指标，并讨论较长预测时域的性能下降；这些是数据集回放式评估。不能据此声称已验证真实闭环碰撞安全。不同感知监督设置的比较也不能简单归因为世界模型结构，必须同时看输入质量、监督量和任务设定。[实验 HTML](https://arxiv.org/html/2311.16038v1)

对移动人形，相机高度和俯仰会随步态改变，基座在三维中运动，手臂还会遮挡视野。训练中若总是平稳的汽车视角，学到的占据时序规律未必能解释这些变化。把“视角导致的可见性变化”与“物体真的移动”分开，正是视觉里程计、动态 SLAM 和时序融合经验能发挥作用的地方。

## 建议的小实验：动态占据是否真的帮助决策

不要首先重训完整自动驾驶模型。先选局部室内模拟场景，设一个行进中的相机和少量移动障碍。用同一份历史深度构建局部占据，对比保持上一帧、恒速外推、学习时序占据三种预测；再将同一个局部规划器接在三者后面，保持可用传感器与计算预算一致。用真值位姿和带误差位姿分别做实验。

评估分为运动区域 IoU、未来占据精度、漏报碰撞率、可行路径完成率、保守绕行代价及端到端时延。若学习模型只提高静态占据均分却没有降低动态碰撞，研究论点不成立；若保守地把未知区域全部设成障碍就能同样安全，应进一步比较通行效率。人形扩展应从局部避障或落脚前的风险预测开始，再谈全身控制。

## 资源和复现建议

官方仓库提供训练、评估、可视化、配置及预训练入口，说明了训练 tokenizer 后再训练预测器的流程，并给出评估显存环境示例。它们是作者的配置说明，不是本次实测。[官方 README](https://github.com/wzzheng/OccWorld)

最有价值的阅读顺序是先看任务定义和自车 token，再看感知输入分组，最后看指标计算。需要核实碰撞指标是否使用未来真值、评估是否闭环、预测失败是否会回馈到下一步观测。若以后据此立题，还应补查机器人局部地图预测、动态避障和足步规划已有研究；本卡仅提供跨领域桥梁。
