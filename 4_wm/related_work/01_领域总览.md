# 人形机器人世界模型：从传统感知走进来

调研日期：2026-09-29。本文给出概念框架和选读理由；具体论文事实、版本与证据边界见各论文卡。这里的研究建议是综合分析，不是已验证结果。

## 先读这五个判断

1. **你已有的感知经验可以直接复用。**标定、时间同步、几何表示、状态估计和不确定性，决定世界模型得到什么历史，以及能否正确区分自运动与外部变化。
2. **入门核心是“动作改变未来”。**判断可用于反事实规划的前向世界模型，关键是：能否在给定状态/观测历史和候选动作后，预测可用于决策的结果。预测对象可以是图像、特征、三维状态、接触或奖励。本库也收录联合预测未来与动作的模型，以及利用预测训练辅助策略的工作；它们不一定提供任意候选动作查询接口。
3. **世界模型不是统一架构。**RSSM、Transformer、扩散模型、点云预测和概率动力学都可能承担这一角色；名字不是充分条件。
4. **人形难点不仅是视觉语义。**部分可观测、相机随身体运动、接触切换、平衡、连续高维动作和实时预算，使机械臂或视频结果不能直接外推。
5. **建议先做小规模“感知表示 + 动作条件预测 + 闭环评测”。**完成一个可诊断的基线，比立即预训练通用视频模型更适合当前学习阶段。这是依据现有背景与资源未知所作的路线建议。

## 1. 从你熟悉的系统理解世界模型

传统机器人栈通常已经有“感知 → 状态估计/建图 → 规划 → 控制”。世界模型并不使这些概念失效；它把一部分状态表示和转移规律从数据中学出来，并允许在内部比较动作的未来后果。

令 `o_t` 是观测，`a_t` 是动作，`s_t` 是真实但未必完全可见的状态。可以把系统抽象为：

```text
历史图像、深度、IMU、关节状态、接触与历史动作
                    ↓ 估计/编码
          当前状态表示或 belief state
                    ↓ + 候选动作序列
          动作条件的未来状态/特征预测
                    ↓ 奖励、目标距离、碰撞/接触代价
          规划，或在想象轨迹中训练策略
                    ↓ 执行一步/一段动作
          新观测校正状态，进入下一轮
```

其中可以保留传统估计器，也可以端到端学习，并非必须二选一。[PlaNet](papers/2019_planet.md) 适合理解估计和在线规划，[Dreamer](papers/2020_dreamer.md) 适合理解在模型中训练策略，[PETS](papers/2018_pets.md) 则与系统辨识/MPC 更接近。

感知主要回答“现在什么在哪里、机器人处于什么状态”；动作条件模型进一步回答“如果我采取这个动作，什么会怎样变化”。不过传统感知也包含跟踪、预测和滤波，所以这不是绝对学科分界。研究中应具体写明模块功能，不靠标签划界。

## 2. 四个容易混淆的对象

| 对象 | 常见输入/输出 | 可以做什么 | 单靠它还不能说明什么 |
|---|---|---|---|
| 感知/建图模型 | 图像或点云 → 深度、位姿、地图、语义 | 提供结构化状态 | 未必预测动作带来的环境变化 |
| 视频预测/生成模型 | 历史/文本 → 未来视频 | 学视觉时序与生成先验 | 未必响应可执行机器人动作，也未必物理正确 |
| 动作条件世界模型 | 历史 + 动作 → 未来状态/观测/奖励 | 模拟候选行为、训练策略或评估策略 | 未必足够实时、校准或可迁移 |
| 策略/VLA | 图像、语言、状态 → 动作 | 直接产生控制 | 并非必然显式建模行动后果 |

实际方法可以跨多行：例如 WAM 联合建模未来与动作，预测辅助策略则把未来预测用于学习表示。分类用于澄清接口，不是互斥的论文标签。

[3D Diffusion Policy](papers/2024_3d_diffusion_policy.md) 在本库作为三维策略对照；[ConceptGraphs](papers/2023_conceptgraphs.md) 作为场景表示对照。这类工作有价值，但不能因使用三维或基础模型就统一算作动作条件世界模型。关于 VLA，也可参考开发团队对 [π0 策略](https://www.physicalintelligence.company/blog/pi0) 的定位。

## 3. 四条主线与阅读顺序

### A. 基于模型的强化学习：学会“怎样用预测做决策”

World Models → PlaNet → Dreamer → DreamerV3；旁支读 PETS、TD-MPC2、MuZero。

要学会区分三种使用方式：执行时搜索动作；训练时生成想象经验；用预测性表示直接辅助策略。只问网络是不是 Transformer 会错过真正的算法区别。MuZero 和 TD-MPC2 还说明，世界模型可以不重建图像。[经典论文卡](papers/2018_world_models.md)、[TD-MPC2](papers/2024_tdmpc2.md)

### B. 机器人视频模型：从“看到未来”到“产生可执行动作”

Visual Foresight、UniPi、UniSim、GR-1、IRASim、Cosmos、DreamZero。

阅读每篇时先找动作进入模型的位置：直接条件、逆动力学、联合动作/视频预测，还是仅生成数据后另训策略？再看评估到底是视觉分数、策略排序还是机器人闭环。这条路线适合学习大规模视觉先验，工程规模与细粒度物理可靠性需要单独评估。[路线论文索引](03_论文比较表.md)

### C. 特征和三维世界模型：与你的背景最接近

DINO-WM → V-JEPA 2 的动作条件部分 → PointWorld；用 OccWorld 学习时序占据表示，用 3D Diffusion Policy 和 ConceptGraphs 理解表示/策略对照。

关键问题是：预测对象是否保留几何和交互所需的信息？特征预测可减少像素生成负担，但不自动保证米制几何、接触精度或跨视角一致。三维模型容易利用几何先验，也需要承担深度噪声、遮挡和坐标系误差。[交叉研究详解](04_感知与世界模型的交叉研究.md)

### D. 人形与腿足：检查身体、接触和实时条件

DWL/WMR 帮助理解状态重建与策略；HWM 研究人形数据上的动作条件视觉预测；Puppeteer 与 MoSim 展示仿真控制/动力学路线；CAP、DWMP 属于需要持续跟进的感知控制工作。

这些名字下的系统差别很大。DWL 的去噪状态学习不等同于 Dreamer 的多步想象；HWM 中的 EVE 带轮式底座；Puppeteer 的仿真人形结果也不等同于实体机器人。每条能力主张都要附平台与任务条件。[比较表](03_论文比较表.md)

## 4. 人形机器人为什么需要额外问题定义

下表是本调研的任务分析，用于设计实验，并非声称所有现有方法均失败于这些情况。

| 特性 | 对世界模型的影响 | 感知背景可以贡献什么 |
|---|---|---|
| 相机随头部/躯干运动 | 图像变化可能来自自运动而非场景变化 | 位姿补偿、坐标变换、稳定参考系 |
| 遮挡和有限视场 | 单帧不能判断脚边/身后状态 | 记忆地图、belief state、多传感器融合 |
| 多种接触模式 | 动力学在落脚、滑移、抓握时变化 | 接触估计、事件条件、物体/表面状态 |
| 高维耦合动作 | 手臂行为可能影响平衡 | 层级动作接口、全身状态建模 |
| 传感器与执行延迟 | 预测起点可能已经过时 | 时间同步、延迟建模、外推补偿 |
| 错误代价高 | 平均误差掩盖少数关键失效 | 风险校准、分层评测、失败诊断 |

这里最容易形成具体研究问题的是：**状态表示是否在闭环所需的时刻保留了必要信息？**例如，平滑但滞后的地形估计，在离线指标上很好，却可能错过落脚窗口。反之，某些视觉误差很大但不影响接触和任务，可以不作为首要优化对象。

## 5. 如何判断一篇论文值不值得深入

逐项填写：输入是什么、动作定义是什么、预测什么、训练标签从何来、模型在哪个阶段被使用、实体平台是什么、泛化到哪些未见因素、是否公开足够资源、算力和时延在哪里测。

特别检查三类反例：打乱动作后预测是否几乎不变；把背景换掉性能是否大降；开环预测更准确但闭环没有改善。它们分别提示动作被忽略、表示依赖捷径，以及指标与控制目标脱节。这里只给出诊断思路，需要按具体模型设计实验。

## 6. 适合你的首轮选择

- 偏 SLAM/定位：优先研究自运动补偿、动态/静态分离、地图记忆及不确定性传播。
- 偏点云/三维感知：优先研究动作条件点云/局部占据预测、接触区域精度、遮挡鲁棒性。
- 偏融合/状态估计：优先研究本体—外感知融合、不同频率的时间建模、感知可信度与预测误差的关联。

共同第一步是在一个公开仿真任务上建立可重复数据和固定评测，再决定要加什么模块。具体十二周路线见 [学习路线](02_十二周学习路线.md)，候选课题见 [交叉研究](04_感知与世界模型的交叉研究.md)。
