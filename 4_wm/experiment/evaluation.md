# 标准化评测协议草案 v0

状态：**未运行；任务和硬件尚未选定，协议未冻结。**以下规定要报告什么、如何避免不公平比较；确定环境后填写具体配置并冻结为 v1，之后改动必须记录理由。不得将此草案当作已完成实验。

## 1. 先确定研究声明

最小问题：在给定动作序列下，几何/融合信息是否改善未见场景或传感器扰动中的多步预测，并在相同决策器与预算下提高闭环任务表现？替换前向预测器时固定规划器；若研究预测表征辅助 PPO/actor，则固定策略架构、训练算法、奖励与预算，不能强加不存在的在线规划器。

只能声明已覆盖的具身和任务。机械臂推物实验不能直接证明人形落脚；仿真人形不能写成真实机器人验证。

## 2. 冻结清单

实验前写出：环境/任务版本、机器人与动作接口、输入模态、动作频率、传感器频率、训练数据量、预训练来源、训练计算预算、预测时域、规划预算、成功/碰撞/终止规则、全部测试场景、种子与可视化轨迹 ID。

建议初次正式比较使用训练种子 `0, 1, 2`，按资源再扩大。每个训练所得模型、每个任务/条件分别评测 30 个 episode（草案建议），各方法共享预先固定的场景与初始状态种子。逐训练种子报告结果；不能把 3×30 个 episode 当作 90 次独立训练重复。测试环境种子与训练种子分别登记，不能临时挑成功轨迹。小样本真机试验必须报告分子/分母和不确定性，不能用少量成功演示替代统计结论。这些数值是项目设计建议，不来自论文性能承诺。

## 3. 数据划分与泄漏检查

- 完整 episode 分组后再切窗口，不能让相邻帧跨训练和测试。
- 若主张场景、物体、地形或机器人泛化，在该维度留出，并记录训练/测试交叉表。
- 预处理统计、超参数选择和早停只用训练/验证集；测试集只按预先确定协议评估。
- 特权状态、未来观测、目标接触标签只用于明确声明的监督或 oracle，不得暗中流入被比较方法的部署输入。
- 给每个训练样本检查动作和状态时间关系，重点核验 action chunk 与观测是否错位。

## 4. 按研究声明选择并冻结的对照

下表是对照菜单：公开基线、简单基线和与主张直接相关的消融应优先；oracle 仅在有可靠参考时使用，并记录参考误差。资源不足时缩小任务或主张，明确缺少的对照，不把所有复杂对照设为入门跑通的前提。

| 对照 | 目的 |
|---|---|
| 当前状态保持/简单外推 | 排除任务几乎静态也能预测好的假象 |
| 简单动作条件 MLP/线性动力学 | 确定复杂模型是否必要 |
| 选定公开基线、相同数据与适用的规划器/策略训练设置 | 确保贡献不是控制器或数据量变化 |
| 可靠参考状态 oracle（可得时） | 估计感知误差造成的差距；记录参考误差，不作可部署方法 |
| 同参数量/同训练预算的无几何模型 | 区分结构收益与容量收益 |
| 去掉历史/几何/本体/接触辅助的对应消融 | 检查每个新增组件的作用 |

动作置零或打乱可作诊断，但有分布外混杂。若要论证反事实响应，应在可重置仿真中从相同初始状态执行不同真实可行动作，比较预测差异与实际差异。

## 5. 预测、闭环、计算三层指标

| 层次 | 指标 | 解读要求 |
|---|---|---|
| 状态/几何预测 | 多步位姿/速度误差、点云距离、局部占据 IoU 或任务相关距离 | 按具体输出选主指标；同时单列接触区域/近身区域，别让背景主导平均 |
| 特征/视频预测 | 特征误差、必要时图像/视频质量指标 | 只作辅助，不能替代控制证据；同一编码器下比较 |
| 接触事件 | precision/recall、F1、事件时间误差 | 记录类别不平衡，不能只报全帧 accuracy |
| 不确定性 | 区间覆盖率、预测似然（若有合法分布）、风险分数校准、错误检测 AUROC/AUPRC | 明确预测事件和概率语义，不将任意距离称概率 |
| 闭环 | 任务成功率、碰撞/跌倒率、完成时间；人形另加落脚误差/速度跟踪等 | 报试验总数与分场景结果；任务奖励仅作辅助解释 |
| 计算 | 训练预算、峰值显存、推理 p50/p95/p99、端到端延迟 | 包括感知、预测、搜索、通信；动作块刷新率不等于底层伺服频率 |

主指标先选一个，与研究问题一致，例如测试扰动下闭环成功率；其余作为同时报告的诊断和约束。不能看完结果再换主指标。预测时域既记录步数也记录秒数，避免不同频率下比较同样“10 步”。

## 6. 必须输出的图和失败分析

固定 5–10 条轨迹 ID，跨方法看同一时刻；画多步误差曲线、干扰强度—闭环成功率曲线，以及预测/真实接触事件时间线。若研究不确定性，增加置信度—实际错误关系图。机器人视角与世界坐标可视化要同时保留，便于发现参考系错误。

失败分析至少区分：感知起点错、转移预测错、规划目标错、动作执行偏差、延迟、分布外接触。不能只贴最佳生成视频。

## 7. 实验记录格式

每次输出到 `experiment/<版本名>/`：配置、split manifest、metrics.json、逐种子结果、可视化、failure_cases.md。版本使用 `v001_<问题>_<改动>`，例如 `v001_depth_dropout_baseline`；时间戳另作元数据。

完成后追加 [results.md](results.md)。失败和中止运行保留状态与原因，不补写未运行数字。若几何误差改善但闭环没有收益，结论应如实限制在预测层面。
