# 评测协议草案

状态：**用于后续首个基线的预注册草案，尚未选择具体模型/平台，因此未冻结；没有实验结果。**一旦开始正式对比，先填写具体配置，再固定协议。更改协议必须保留旧版并写原因。

## 1. 数据与测试条件

- 首选官方支持的仿真组合，任务集、环境版本、checkpoint、相机、图像裁剪与动作归一化全部记录。
- 跟随要复现论文的官方划分；新增泛化测试按任务/对象实例/场景/采集批次分组，整个 episode 不跨划分。不随机打散连续帧后划分训练测试。
- 若测试预训练模型，检查目标benchmark数据是否已进入预训练；已见过的数据不能宣称零样本泛化。
- 测试集不用来选超参数或选checkpoint；适配和调试用单独开发集。
- 泛化维度分别报告：视觉外观、对象、空间关系、任务组合、机器人形态。一次变化多个因素时说明无法单独归因。

## 2. 执行与统计

- 固定并公布任务列表、seed列表、初始状态列表、每任务试验次数、最大步数和时间预算。数量在训练/比较开始前确定；本轮不编造预算。
- 使用相同任务/初始条件配对比较策略。调试性小样本结果不作正式排名。
- 每回合保存 success、终止原因、步数、总耗时、人工干预、碰撞/跌倒（适用时）。超时和失稳按预先定义计入失败，基础设施错误单列并保留。
- 若官方主指标是 task progress 或 normalized score，保存原始子任务得分并按其定义汇总，不转换为成功率。完整成功与阶段进度分别定义和报告。
- 报每任务成功/总次数和跨任务宏平均，同时给不确定性。单任务可用二项比例区间；跨任务/seed相关结构用对应分层重采样，不能把相邻帧当独立样本。
- 报策略推理、预处理、传输、控制的时间口径及端到端延迟分位数；注明同步/异步、动作预测长度和实际执行长度。

## 3. 对照与必需输出

| 对照 | 用途 | 限制 |
|---|---|---|
| 未修改官方 baseline | 证明执行链路成立 | 先对齐版本与适配 |
| 动作回放/脚本/专家（环境允许时） | 检查环境与成功判定 | 只是参考，不自动是公平上界 |
| 去掉语言、打乱语言或替换指令 | 检验语言是否真正影响行为 | 仅适用于语言条件策略；原版ACT和纯运动控制记不适用；固定其余条件 |
| 去掉关键模块 | 检验设计增益 | 数据量、算力与推理预算尽量对齐 |

每版输出：逐回合原始记录、分任务表、置信区间、性能—延迟图、固定诊断案例及新增失败案例。固定案例用于排查，正式测试集仍保留其完整代表性。

## 4. 人形附加条件

分别记录任务完成、站立稳定、移动进度、碰撞、跌倒、人工干预与恢复情况。写清是否固定底座、外部支撑、特权状态、外部定位，以及高低层控制器版本。上肢任务完成不能独自证明全身能力。

## 5. 保存与版本

每次实验保存在 `experiment/v<序号>_<改动>/`，包含 `config`、`metrics.json`、逐回合结果、图和 `failure_cases.md`。最终摘要追加到 [results.md](results.md)，失败或作废记录仍保留。
