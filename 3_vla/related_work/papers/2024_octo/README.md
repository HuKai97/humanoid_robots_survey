# Octo：便于适配新传感器与动作空间的通用策略

## 先读总结

1. Octo 把任务与观察转成 token，用共享 Transformer 和扩散动作头学习通用策略。[S1][S2]
2. 支持语言指令或目标图像，并可微调到新传感器、动作空间。[S2]
3. 结构设计的重点是可适配接口，不只是参数规模。[S3]
4. 学它可以补齐“如何把预训练策略接到自己的机器人”这部分知识；预训练域中的开箱使用与新身体微调应分开报告。

## 问题是什么

实验室可能多一个腕部相机、少一种状态传感器，或者使用关节位置而不是末端位姿。一个固定输入输出接口的预训练模型，换设置时常要改动大量结构。Octo 试图保留共享知识，只调整需要改变的输入编码或输出头。

## 方法：模块化 token 与扩散动作头

**语言/目标图像 + 观察历史 → 模态 tokenizer → 带掩码的 Transformer → readout token → 小型扩散头 → 动作块**。[S3]

语言由预训练编码器处理，图像形成 patch token；缺失模态通过掩码排除。观察只读取当前及过去信息。readout token 汇总任务和观察，而动作头根据该表示去噪得到动作序列；多轮去噪在较小动作头内完成，不需要每轮都重新运行整个 Transformer。[S3]

**解释性推导**：缺相机与“相机看到一张黑图”含义不同，前者应告知模型信息不存在。改变动作维度时也不仅是补零，还要处理新输出头及真实控制语义；结构允许适配，不代表没有数据就能理解全新传感器。

## 数据与监督

项目报告约 80 万轨迹，来自 OXE 的 25 个数据集；模态和语言标注并不完全相同。[S2] 训练采用条件扩散监督；新平台微调同样依赖目标域示范。[S3] 这与互联网 VLM 上直接进行动作 token 自回归微调不同，不应因为都带语言输入就忽略预训练差异。

## 实验证据与局限

作者在 9 个真实机器人设置中研究预训练域执行及新任务适配，包括加入力/力矩输入和改用关节动作的情形。[S1][S2] 支持的结论是共享策略可作为有价值的初始化；不证明任意身体、场景和动作接口均可直接零样本控制。

局限分析：语言理解受模型与数据覆盖影响；扩散采样仍有成本；不同数据集的动作规范和采样权重会影响结果。全身人形中接触约束与稳定性仍需单独设计和评估。
