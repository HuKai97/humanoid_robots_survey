# SayCan：让语言规划同时考虑机器人能否做到

## 元数据与阅读状态

- **完整标题**：Do As I Can, Not As I Say: Grounding Language in Robotic Affordances
- **作者 / 年份**：Michael Ahn 等，2022。
- **定位**：P1；语言规划与技能可行性结合；轮式移动机械臂，**不是端到端人形全身 VLA**。
- **入口**：[论文摘要](https://arxiv.org/abs/2204.01691)｜[官方项目](https://say-can.github.io/)｜[官方代码](https://github.com/google-research/google-research/tree/master/saycan)。公开演示版本是仿真桌面环境，不能等同于完整真机系统开放。
- **本轮阅读**：2026-09-29；摘要、项目方法与更新、官方博客、代码入口；未下载论文，未全文精读或运行实验。

## 先读总结

1. LLM 判断某个技能是否有助于任务，价值/可行性函数判断机器人在当前状态能否完成它。[S1][S2]
2. 系统把两个分数结合后选择已有技能执行，再继续规划。[S2]
3. 输出主要是技能选择；具体控制由预训练策略承担，并非 LLM 直接产生全部运动命令。[S1]
4. 它适合建立“会说”“能做”“做成”是三个不同问题的研究习惯。

## 问题是什么

面对“饮料洒了”，语言模型可能建议找吸尘器，但机器人也许没有吸尘器，或者根本无法使用。自然语言步骤听起来合理，不代表当前身体与环境允许执行。SayCan 把物理可行性放进每一步选择中。

## 方法：两种评分相乘

每个候选技能有一条文字描述、一个执行策略和一个状态相关的可行性评分。语言模型根据总任务与已完成步骤，评估各技能描述的合适程度；可行性函数评估当前状态下技能成功的可能性；组合分数选择技能，再执行并更新历史。[S2][S3]

可以用简化式理解：

`选择分数(技能) ≈ 语言相关性(技能 | 任务、历史) × 可执行性(技能 | 当前状态)`。

这是对架构的教学简写；两个学习分数不能不经校准就理解为严格独立且完全准确的真实概率。执行器仍需处理图像到动作的映射，规划器只在可用技能集合中选择。

**原创解释例子**：假设“拿纸巾”的语言相关性高，但纸巾被遮挡导致可执行性低；系统可能先选择移动或寻找技能。不过，如果所有候选技能都不合适，乘分本身也不会发明新的运动技能。

## 数据与监督

论文依赖已有语言模型与预训练低层技能及其价值函数，而不是仅输入一个提示就获得全部机器人能力。[S1] 因而复现需要分别准备技能训练、成功信号和语言接口。官方项目 2022 年更新引入 PaLM，并公开了仿真桌面版本；这些更新应与最初版本区分记录。[S2]

## 实验证据与局限

作者在移动操作任务上验证长时序自然语言指令执行。[S1] 项目明确区分计划选择正确与实际执行成功，二者不能混成一个“准确率”。[S2] 对初学者而言，这种分解比记住一个总成功率更有价值：计划对了仍可能抓取失败；抓取策略优秀也无法修复错误的目标选择。

局限分析：能力受技能库覆盖限制；价值函数失准会使规划选择不可执行动作；一次技能失败后如何判断完成状态、是否重试，需要额外设计。论文没有证明双足平衡、接触力调节或无技能库的全身通用控制。

## 联系与学习检查

[RT-1](../2022_rt1/README.md) 可作为技能执行层的相关路线；[PaLM-E](../2023_palm_e/README.md) 将连续感知接入语言模型；[RT-2](../2023_rt2/README.md) 则把动作直接纳入模型输出。三者不能仅凭“都有语言”划成同一种系统。

阅读问题：技能分数来自哪里？技能失败是否进入下一轮上下文？如何区分语义错误与动作错误？可行复现先用官方仿真桌面示例理解评分接口，并构造“语言合理但物理不可行”的小测试。需记录所用语言服务与原论文差异；本轮没有实际运行。
