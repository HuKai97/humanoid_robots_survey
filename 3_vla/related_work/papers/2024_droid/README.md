# DROID：把真实场景多样性带入训练

## 先读总结

- DROID 是真实机械臂示范数据集，不是人形策略模型。
- 核心思路是统一采集设备，再让不同机构和采集者覆盖多种环境。[S1][S2]
- 作者报告的数据规模约 76k 条轨迹、350 小时、564 个场景；任务数量存在版本口径差异，应核对原文版本。[S1][S2]
- 学习重点是采集规范、相机标定、语言标注与跨场景测试，不能把视觉场景多样性当成跨身体迁移。

## 元数据与阅读范围

完整标题：DROID: A Large-Scale In-The-Wild Robot Manipulation Dataset。Alexander Khazatsky 等，2024。核验论文摘要、官方项目、官方策略学习仓库；未逐表复核全部结果，未运行。检索：2026-09-29。

**版本提醒**：本轮 arXiv 摘要为 84 个任务，项目页为 86 个任务；不将两者混成统一版本。项目还记录了后续语言标注和相机标定更新，做实验必须记录实际下载的数据版本。[S1][S2]

## 研究问题与详细方法

在干净实验室里成功，不代表在办公室或家庭里也成功。DROID 尝试降低多地采集的组织门槛：使用一致的 Franka Panda、外部和腕部相机、遥操作设备，再把整套装置移动到不同场景采集。这样保持动作平台相对一致，同时扩大背景、对象、视角与交互分布。[S2]

训练样本按 episode 组织，每一步可包含外部图像、腕部图像、机器人状态、动作和语言。官方项目给出 TFDS 读取入口，策略学习代码提供训练与评估流程。对初学者来说，可把它理解为“许多带任务说明的操作录像，加上每一刻机器人实际怎样动”的联合记录，而不是只有 RGB 视频。[S2][S3]

这里的关键系统工作是让来自不同地点的记录仍可被共同训练：字段一致不代表相机姿态完全一致，所以标定和元数据同样重要。模型可以用这类广泛数据与目标任务数据联合训练，检验额外经验能否帮助目标场景。[S1][S3]

## 证据与限制

作者在其选定的真实任务和场景上比较联合训练，报告性能与对干扰物、对象变化的鲁棒性收益。[S2] 这属于特定评估条件下的作者结果，不能推导出 DROID 对所有机器人、所有算法都优于其他数据。

数据规模与任务分布不是均匀覆盖；不同采集者习惯也会形成偏差。仅记录成功示范，可能缺少失败后的纠正轨迹。人形研究若使用它，还要解决动作空间与身体结构不一致的问题。

## 如何连接 VLA 学习

与 BridgeData V2 一起看，可以区分场景覆盖和技能覆盖；与 OXE 一起看，可理解同平台多场景和多平台混合的差别。它也是学习“数据版本改变为什么会改变结果”的例子：语言、标定更新都可能影响模型输入。

## 阅读问题与后续动手

以下为建议：先检查一条轨迹在各相机中的同一事件是否同步，再问动作对应的是状态变化、目标位置还是控制命令。设计测试时按场景/采集批次分组，记录任务重叠。对比两种数据混合策略时固定总训练步数，否则数据收益可能与算力增加混在一起。
