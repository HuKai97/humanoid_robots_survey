# Open X-Embodiment / RT-X：跨机器人数据与迁移

## 先读总结

1. Open X-Embodiment（OXE）是数据协作与统一存储资源；RT-1-X、RT-2-X 是在混合机器人数据上训练的模型。[S1][S2]
2. 数据资源规模不等于单个模型实际训练规模：论文实验混合使用 9 种机器人，而集合涵盖 22 种身体。[S3]
3. 统一格式不等于完全统一物理意义：坐标系、绝对/相对量与控制方式仍可能不同。[S3]
4. 对人形方向最重要的启发是“数据如何对齐、如何检验正迁移”，而不是直接把机械臂动作拼成人形关节动作。

## 问题是什么

不同实验室可能使用不同机器人、相机、动作单位、语言标注和存储格式。数据总量增加之前，首先要解决“是否能被同一个训练管线读取”和“同样长度的向量究竟表示什么”。否则混合数据可能只是把不兼容标签放在一起。

## 方法：先统一容器，再做粗粒度接口对齐

数据以 RLDS episode 格式组织；episode 是一段连续执行，内部包含逐步观察与动作。[S4] RT-X 保留两条架构：RT-1-X 是机器人 Transformer，RT-2-X 是 VLM 动作 token 路线。[S2]

方法段描述选取代表相机视角，调整图像尺寸，构造末端平移、旋转和夹爪的 7 维动作并按数据集归一化；**未把所有坐标系和绝对/相对位置、速度定义严格统一**。因此同一个归一化数值需要根据具体身体及数据统计反解码。[S3]

**解释性推导**：存储统一解决“读得进来”，动作语义对齐解决“学到的是同一件事”。这是两个层次。人形数据若再加入双臂、腰、脚步与支撑状态，必须额外说明哪些标签可共享、哪些需要身体专属接口。

## 数据与监督

项目介绍百万级轨迹、22 种身体的数据资源；集合持续扩展，不能将页面上机构、实验室和数据集数量当成同一统计口径。[S2] 论文方法段明确实验只用其中 9 种身体的混合；两种模型均以离散动作交叉熵训练，RT-2-X 还混入原 VLM 数据。[S3]

## 实验证据与局限

摘要报告跨机器人经验可以产生正迁移。[S1] 方法与实验说明同时提示容量问题：小模型在某些大数据域会欠拟合，混合数据并非对每个域自动有益。[S3] 因而研究问题应是“哪些数据、何种模型容量、何种目标域获得改善”，而不是仅比较数据总量。

局限分析：多数操作数据不能覆盖人形的足地接触、跌倒与动态平衡；统一格式本身也不保证示范质量、语言标注质量或评估划分一致。公开 RT-1-X checkpoint 不代表 RT-2-X 的全部权重和训练资源同样开放。[S4]

## 联系与复现检查

[Octo](../2024_octo/README.md) 和 [OpenVLA](../2024_openvla/README.md) 都利用 OXE 子集，但采样和清洗方案不同。不要把它们称为“使用完全相同训练数据的纯架构比较”。

可行学习练习：先阅读官方可视化/数据加载 notebook，画出 episode 和 step schema；给每个动作字段记录单位、坐标系、绝对或增量、控制频率、夹爪开闭定义。以后加载一个小样本时再检查图像与动作时间对齐。本轮只保留入口，没有下载数据。

阅读问题：混合数据是否会压倒小数据域？目标机器人的数据是否已经在预训练集中？所谓零样本究竟是新任务、新对象还是新身体？
