# OpenVLA-OFT：微调配方也能决定 VLA 是否好用

## 论文与阅读状态

- **原题**：Fine-Tuning Vision-Language-Action Models: Optimizing Speed and Success。
- **作者/机构**：Moo Jin Kim、Chelsea Finn、Percy Liang；Stanford。
- **首次提交**：2025-02-27；RSS 2025；[元数据](https://arxiv.org/abs/2502.19645)。
- **原文**：[HTML v1](https://arxiv.org/html/2502.19645v1)；[官方项目](https://openvla-oft.github.io/)；[官方代码](https://github.com/moojink/openvla-oft)。
- **核验日期**：2026-09-29。阅读深度：HTML 微调设计、实验表、项目 FAQ 与仓库结构；非逐页精读，未运行。

## 先读总结

1. 预训练预测离散 token，不要求微调一直用相同输出。
2. OFT 组合并行解码、动作块、连续动作与 L1 回归。
3. 不能只与未经优化的原始 OpenVLA 比较。
4. 具体 LIBERO 与 ALOHA 成绩不是跨平台统一排名。

## 详细介绍

### 问题从哪里来

机器人等待模型依次生成多个数字，会令控制循环停顿；一次预测一段动作能缓解等待，但串行生成更长序列又可能变慢。需要同时考虑“输出多少动作”和“怎样解码”，并区分吞吐量与单次推理延迟。

### 方法 pipeline

从预训练 OpenVLA 出发，输入图像、语言，可加入腕部视角与本体状态；将待预测动作位置作为并行输入槽，改变注意力掩码，经动作 MLP 输出连续动作块，用 L1 损失及 LoRA 微调。作者比较解码、表示与训练目标；LIBERO 完整 OFT 配置四套任务平均 97.1%，仅部分改动的结果不同。[原文设计及表 I](https://arxiv.org/html/2502.19645v1#S4)

**教学理解**：L1 按绝对差让预测靠近示范；它与从噪声逐步生成不同。应先做受控比较，不能由架构名字判断强弱。

### 实验支持范围与局限

官方区分 OFT 与加强双臂 ALOHA 语言条件的 OFT+；真机验证涉及四类操作。项目明确提醒 L1 不会普遍优于 diffusion，多模态动作分布可能需要更强表达力。[官方实验与讨论](https://openvla-oft.github.io/)

本笔记的判断：97.1% 不是“真实世界机器人成功率”，相机输入也影响公平性。报告加速时，要区分生成延迟、每秒输出动作数、实际控制刷新率；长动作块提高吞吐，不意味着每个动作都使用最新视觉。

### 人形及相关工作

它是人形上肢策略的候选动作头，适合研究 VLM 表征究竟贡献什么。ALOHA 双臂实验不是双足人形实验，未证明平衡与步态控制。相对 FAST，OFT 不以压缩自回归 token 为核心；相对 π0，它用简单连续回归检验复杂动作生成是否必要。

## 精读问题与复现路线

按消融画四列：串行/并行、单步/动作块、离散/连续、L1/diffusion。检查提升是否同时改变相机输入。再问：示范有绕物体左侧和右侧两种轨迹时，L1 会产生什么行为？这是待实验验证的问题。

官方仓库将 LIBERO 和 ALOHA 指南分开，适合先学模拟评测接口，再考虑真机。[代码入口](https://github.com/moojink/openvla-oft)

微调节省可训练参数不等于显存需求很低；按官方具体输入配置评估资源，避免照抄通用硬件数字。本轮没有安装环境或复现成绩。

可设计的阅读产出是给同一任务写一张输入和输出对照表，把动作单位、参考坐标系、预测长度、执行长度和评测次数全部列清，再决定是否需要新增算法。
