# OpenVLA：开放的 VLM 到动作模型与微调路径

## 元数据与阅读状态

- **完整标题**：OpenVLA: An Open-Source Vision-Language-Action Model
- **作者 / 年份**：Moo Jin Kim、Karl Pertsch、Siddharth Karamcheti 等，2024。
- **定位**：P0；开放 VLA 基础模型，单机械臂与移动操作机器人评估，**不是人形全身 VLA**。
- **入口**：[论文摘要](https://arxiv.org/abs/2406.09246)｜[官方项目](https://openvla.github.io/)｜[官方代码](https://github.com/openvla/openvla)。本篇讲原始 OpenVLA；后续 OFT 配方不能混作原论文方法。
- **本轮阅读**：2026-09-29；摘要、项目、HTML v2 的方法与部分实验、README；未全文精读、未下载论文/权重或运行实验。

## 先读总结

1. OpenVLA 将预训练 VLM 微调为动作 token 预测器，并提供权重和训练代码。[S1][S2]
2. 视觉编码融合 DINOv2 与 SigLIP，连接 Llama 2 骨干；原始模型采用离散动作自回归输出。[S2]
3. 开放微调路径比单纯刷新某个成功率更适合初学者学习。[S4]
4. 原论文也展示从零训练的 Diffusion Policy 在部分窄任务上更强；不能得出“大 VLA 总是胜过小策略”。[S2]

## 问题是什么

闭源 VLA 证明了路线，却难以让普通实验室给自己的相机、机器人和任务做适配。OpenVLA 希望把预训练模型、数据管线和微调方法变成可研究的资源，同时保留较强的视觉语言先验。

## 方法：视觉特征到动作 token

链路是：**RGB + 指令 → 双视觉编码器 → 投影到语言嵌入 → Llama 2 → 动作 token → 反离散化/反归一化 → 控制器**。[S2]

原论文将每个连续动作维度离散为 256 档，区间由训练数据分位数确定；用词表末尾低频 token 表示动作，训练仅在动作 token 上计算交叉熵。[S3] 输入图像和文本提供条件，标签是示范动作，不是让机器人解释自己“为什么想这样动”。

**解释性推导**：错误的反归一化统计会把正确 token 变成错误运动幅度。因此模型前向通过不等于部署正确。自回归逐个产生动作维度也可能限制延迟，尤其当未来需要输出长动作块时；后续工作改变解码方式正是研究方向之一。

## 数据与监督

项目报告以约 97 万条 OXE 机器人轨迹训练 7B 模型。[S2] 这不是“从零用机器人数据训练全部视觉语言知识”；模型建立在预训练 VLM 之上。仓库支持 RLDS 数据与 LoRA 等微调方式，并说明代码许可和基础模型权重许可要分别查看。[S4]

## 实验证据与局限

论文评估已有机器人平台上的直接使用，以及在新 Franka 设置上的微调。[S1][S2] 项目明确显示：多对象、多指令适配是模型优势之一，但部分单一指令任务上专门训练的 Diffusion Policy 更好。[S2] 因而模型大小、语义覆盖和精细动作精度不能用一个排名概括。

局限分析：原始接口的视觉、状态与动作时序信息有限；离散化精度和推理速度需结合目标任务检查。其机械臂泛化结果不提供双足稳定性证据。训练集包含某机器人数据时，相关测试不能被描述成“从未见过该身体”。

## 联系与复现检查

先读 [RT-2](../2023_rt2/README.md) 理解动作 token，再读 [OXE](../2023_open_x_embodiment/README.md) 与 [Octo](../2024_octo/README.md) 理解数据混合和接口选择。

后续可先做离线动作预测检查，再考虑官方 LIBERO 微调/评测路径。必须记录原始 OpenVLA 或 OFT、checkpoint、依赖版本、图像处理、动作统计键、数据划分及闭环成功判定。官方明确提醒 BridgeData 在预训练中出现，训练 token 准确率很高不能作为新任务泛化证据。[S4]

阅读问题：模型在何处获得语义知识？为什么只监督动作 token？LoRA 节省的是哪部分训练资源？离线动作误差与闭环成功率为何可能不一致？本轮只做研究整理，没有下载、安装或跑分。
