# OpenHLM：从接口、预训练和数据共训构建全身 VLA

## 元数据与阅读状态

- **作者**：Yingdong Hu, Haodong Zhu, Boyuan Zheng, Yihang Hu, Tong Zhang, Zunhao Chen, Junming Zhao, Ruiqian Nai, Yang Gao。
- **年份/状态**：2026-06-20 首发；官方仓库标注 CoRL 2026。分类：真实全身人形 VLA 与系统消融。优先级：P1。
- **来源**：[arXiv](https://arxiv.org/abs/2606.22174) · [HTML](https://arxiv.org/html/2606.22174v1) · [项目](https://openhlm-project.github.io/) · [官方代码](https://github.com/OpenHLM-project/OpenHLM)。

## 先看总结

1. 核心不是提出一个更大的模型，而是逐项研究怎样把已有 VLA 接到完整身体。
2. 高层输出包含腿关节目标，因而能表达仅有底盘速度命令难以表达的任务。
3. π₀.₅ 预训练、遥操作接口与便宜的人类数据共同影响最终表现。
4. 网页使用的 task progress 是任务进度，不能改写为整条任务成功率。

依据[摘要](https://arxiv.org/abs/2606.22174)与[项目评测](https://openhlm-project.github.io/)。

## 方法：背景与具体动作定义

如果高层只能控制手臂与行走速度，它无法明确告诉脚抬多高、如何踩踏物体。OpenHLM 检查遥操作接口到底允许哪些身体动作，随后用同样的接口监督 VLA。对于新手，这是把“动作表示限制能力”变成具体实验的例子。

系统在 Unitree G1 上使用图像、语言和本体状态，π₀.₅ 适配后的动作向量为 **34 维**：29 个身体关节目标、根部 roll/pitch 与 yaw 角速度共 3 维，以及 2 个夹爪维度。项目提到的 32 维对应身体命令，不能漏算夹爪。目标轨迹交给 SONIC 跟踪器执行，仍不是 VLA 直接输出电机力矩。[HTML §3 及附录 C](https://arxiv.org/html/2606.22174v1)

## 数据和实验支持

工作比较不同遥操作接口、预训练初始化、动作生成方式，并用固定站立遥操作及 HuMI 人类示范做异构共训。项目展示多种语言条件全身任务，报告预训练与数据配方的受控比较；其一项重要观察是离线动作误差与闭环任务表现可能不一致。[项目](https://openhlm-project.github.io/)

作者明确说明主要实验平台是 G1，其设计结论能否推广到其他人形和更多环境尚不确定；便宜数据共训也没有完全消除与全身遥操作的差距。[HTML 局限](https://arxiv.org/html/2606.22174v1)

## 对学习与研究的价值

**本调研解释**：这篇很适合作为“怎样做有解释力的消融”的学习材料。先固定系统接口，再改变一个关键变量，有助于判断收益究竟来自预训练、动作表示还是示范收集方式。单纯比较两个整套系统往往无法回答这个问题。

它也提醒读者，全关节动作与身体稳定性并不冲突：高层可以产生完整参考轨迹，低层负责动态执行。不过接口表达能力增大后，学习难度和目标不可行性也可能增大。需要同时观察任务进度、跌倒、碰撞、跟踪误差与控制延迟，而不是仅优化动作 MSE。

## 联系、阅读问题与候选复现

对照 [WholeBodyVLA](../2025_wholebodyvla/README.md) 的上肢加运动命令接口，以及 [HOMIE](../2025_homie/README.md) 的上下肢分工。阅读时逐项问：这个任务是否从接口定义上就能完成？对比组的示范时长、数量和任务覆盖是否一致？论文报告的是平均进度、部分阶段完成还是完整成功？

官方项目提供代码、数据和模型入口；这使其成为值得检查的候选基线，但本轮未验证安装和资源完整性。[代码仓库](https://github.com/OpenHLM-project/OpenHLM)

复现门槛高。建议从离线单批数据的状态/动作维度与模型推理核对开始，再检查控制器支持和机器人部署。可以先在仿真固定任务做接口消融；没有全身硬件时不应承诺复现原实机成绩。正式实验需固定版本和闭环评价协议。
