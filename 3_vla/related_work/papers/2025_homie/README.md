# HOMIE：低成本遥操作与人形行走、下蹲控制

## 元数据与阅读状态

- **论文**：HOMIE: Humanoid Loco-Manipulation with Isomorphic Exoskeleton Cockpit。
- **作者**：Qingwei Ben, Feiyu Jia, Jia Zeng, Junting Dong, Dahua Lin, Jiangmiao Pang。
- **年份/发表**：2025；RSS 2025。分类：遥操作硬件、RL 运动控制、模仿学习数据；**不是通用 VLA**。优先级：P0。
- **来源**：[arXiv](https://arxiv.org/abs/2502.13013) · [HTML](https://arxiv.org/html/2502.13013v1) · [项目](https://homietele.github.io/) · [官方代码](https://github.com/InternRobotics/OpenHomie)。
- **核验**：2026-09-29；阅读摘要、项目、HTML 方法与仓库结构；非全文精读，未下载论文、未运行代码。

## 先看总结

1. 同构外骨骼直接给上肢关节命令，脚踏板给行走与身体高度命令。
2. RL 下肢策略在上肢变化时维持运动和平衡，并不依赖动作捕捉先验。
3. 同一接口可以用于人类遥操作，也可以作为自主模仿策略的输出接口。
4. 很适合理解人形 VLA 到底控制了哪部分身体、哪些动作交给底层。

前三点见[项目](https://homietele.github.io/)；第 4 点为本调研建议。

## 从需求到方法

桌面机械臂移动手臂即可完成不少任务，人形机器人还要靠移动和下蹲扩大工作空间。HOMIE 要同时解决“操作员如何发出准确命令”和“身体如何稳定执行”。同构意味着控制装置的结构与被控机械臂对应，减少从手部末端位置反解关节角的负担。

原文主流程中，操作者给出前后速度、偏航速度和躯干高度，同时提供上肢关节目标。下肢策略接收这些命令及本体状态历史，如关节角/速度、躯干角速度和重力方向，输出下肢关节动作，经 PD 层执行；上肢目标直接下发。因此动作接口是“上肢关节+运动/高度命令”，不是高层直接输出全部腿部关节。[HTML §III](https://arxiv.org/html/2502.13013v1)

训练以逐步增大上肢姿态变化、设计高度跟踪奖励、利用对称性为关键；训练环境涵盖 Unitree G1、Fourier GR-1，项目明确展示 G1 实机遥操作与后续模仿学习任务。[项目训练/部署说明](https://homietele.github.io/)

## 结果范围与开源边界

作者比较外骨骼与视觉/IK 遥操作接口，并验证所采示范可用于自主模仿。遥操作任务的丰富度，不能直接作为一个自主策略掌握相同全部任务的证据。GR-1 仿真展示也不能自动写成 GR-1 实机验证。[项目实验分类](https://homietele.github.io/)

代码仓库包含 RL、硬件、部署与 MuJoCo 相关目录；仓库后续新闻还指向不同的新控制版本。研究原论文时应固定原版配置，另行记录升级，不能用新控制器复現结果冒充旧论文。[仓库](https://github.com/InternRobotics/OpenHomie)

## 与 VLA 的关系与局限

**本调研解释**：以后可用 VLA 替代操作者，让图像与语言产生这里的上肢和底盘命令。这种分层可以降低动作维度；代价是底层接口预先决定了高层能表达的动作。比如需要脚直接操作物体时，只有移动速度和高度的接口可能不够，应先检查任务可表达性。

“低成本”描述的是论文遥操作装置，不是整台人形、传感器、算力或人员成本。无需 MoCap 先验也不代表无需训练、仿真或硬件适配。上述是成本与实验范围的阅读边界。

## 阅读问题与候选复现

对照 [HumanPlus](../2024_humanplus/README.md) 的视觉人体重定向，和 [OpenHLM](../2026_openhlm/README.md) 的全关节高层接口。读后应解释：上肢变化如何影响下肢？动作标签是否保存操作员指令还是机器人实际状态？训练奖励能否与任务成功率区分？

候选复现门槛中等到高：先在仿真验证高度/速度跟踪，再考虑遥操作及 VLA 连接。最小实验可以固定上肢动作扰动，测量下肢跟踪与跌倒情况；这比一开始复现完整家庭任务更可控。本轮未运行任何控制器或实机。
