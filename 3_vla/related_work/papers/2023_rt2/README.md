# RT-2：让视觉语言模型直接生成机器人动作

## 先读总结

1. RT-2 把机器人动作编码成 token，使 VLM 的“下一个 token 预测”可以输出控制指令。[S1]
2. 训练同时保留视觉语言任务和机器人轨迹，作者称之为 co-fine-tuning。[S1]
3. 主要证据是语义知识帮助选择对象、理解新指令与关系；不能据此宣称互联网图片教会机器人任意新运动。[S2][S3]
4. 它是理解 OpenVLA、后续连续动作 VLA 的关键历史节点；受开放资源限制，不适合作为第一次完整复现对象。

## 问题是什么

纯机器人示范可能教过“拿起”，却没有覆盖所有物体名称和语义关系。互联网视觉语言训练可以提供“哪个东西像工具”“哪个标志对应指令”的知识。问题是如何把这类知识接到真实动作，而不只是让模型描述一个计划。

## 方法：把动作放进语言输出空间

项目展示的流程是：**当前图像 + 任务文本 → 预训练 VLM → 动作数字 token 序列 → 解码为连续控制量 → 执行并更新图像**。实例基于 PaLM-E 或 PaLI-X；机器人训练样本包含图像、指令与对应时刻动作。[S2]

同一个输出接口在视觉问答样本上生成文字，在机器人样本上生成动作编码。Co-fine-tuning 在加入机器人示范时继续使用视觉语言数据，使训练不完全被动作任务取代。[S1]

**解释性推导**：这类似给已有模型增加一种输出“语言”，但控制成功还依赖 token 与坐标系、动作范围、底层执行器正确对应。若模型知道哪个是锤子，却没有覆盖合适的抓取姿态，语义判断正确也可能执行失败。这里“端到端”指观测到动作的模型学习，不意味着没有底层控制软件。

## 数据与监督

训练结合已有机器人轨迹与互联网视觉语言任务；监督目标把动作当作序列标签。[S1] 官方博客说明使用 RT-1 的机器人示范，并展示符号、物体类别等知识迁移。[S3] **解读边界**：这些证据不足以证明网络数据可以赋予任意未示范的新运动技能。 本笔记不把互联网预训练规模和机器人 episode 数量混为一谈，也不填未经本轮核验的数据混合比例。

## 实验证据与局限

摘要报告约 6000 次评估，涉及新对象、符号、相对大小及位置等语义泛化。[S1] 项目同时比较模型规模与从零训练、微调、共同微调，支持预训练与训练配方在这些评测中的作用。[S2] 结果不是“在任意环境通用”：任务范围、动作接口和原机器人示范仍限定能力；大模型推理延迟也必须进入控制系统设计。

展示“先输出文字推理再输出动作”只说明该形式可用于部分任务，不能把文字解释等同于可靠的物理计划，更不能直接外推到人形平衡、接触力约束或跌倒恢复。

## 联系与学习检查

与 [PaLM-E](../2023_palm_e/README.md) 对比：后者主要输出文本决策并依赖技能策略，RT-2 则把低层动作作为模型输出。与 [RT-1](../2022_rt1/README.md) 对比：两者都用动作 token，但预训练路线不同。与 [OpenVLA](../2024_openvla/README.md) 对比开放资源与微调接口。

阅读问题：新语义任务是否需要全新运动？共同微调如何影响知识遗忘？策略延迟与机器人控制周期如何衔接？复现准备可以先用开放 VLA 学习同类接口；不要把运行第三方小模型报告为 RT-2 原模型复现。本轮未运行实验。
