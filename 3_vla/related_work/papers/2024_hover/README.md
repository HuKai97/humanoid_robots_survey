## 先看总结

1. 不同高层策略可能输出手的位置、关节角或身体速度；HOVER 让一个控制器支持多类接口。
2. 先获得全身运动跟踪教师，再用命令掩码与策略蒸馏训练学生。
3. 实验对象包含真实 Unitree H1，但评测主要是运动跟踪和模式切换。
4. 它能成为 VLA 的执行层，不能独立解释图像或语言任务。

依据[项目](https://hover-versatile-humanoid.github.io/)与[实验设置](https://arxiv.org/html/2410.21229v1)。

## 初学者应理解的问题

“让机器人向前走”和“让右手到达这个点”属于不同的命令空间。如果每一种命令都对应一套单独策略，任务组合和切换就变复杂。HOVER 的思路是先用完整运动参考教会身体协调，再在训练学生时隐藏部分命令，让模型学会在不同可见目标下行动。

输入由本体感知、活动命令和掩码构成；命令可包含运动学位置、局部关节角和根部状态。通过模式及稀疏掩码组织学生训练，以 DAgger 从教师动作学习。部署时输出 19 维关节位置目标，PD 控制器负责转为电机执行。[项目训练图说明](https://hover-versatile-humanoid.github.io/)；[HTML 方法](https://arxiv.org/html/2410.21229v1)。

**本调研解释**：掩码表示“当前要求跟踪哪些变量”，并非给模型读一句自然语言。若以后把 VLA 接上来，VLA 需要按同样规范提供目标，并明确未指定变量由谁决定；不能把掩码机制当成语言理解机制。

## 训练来源、实验和边界

运动参考来自重定向的 AMASS。作者在仿真中比较多种控制配置，并在 19 自由度 Unitree H1 上做定量站立运动跟踪和定性行走/切换实验。这个证据支持多命令接口可复用，不等价于日常长序列操作任务已经解决。[HTML 实验设置](https://arxiv.org/html/2410.21229v1)

官方仓库说明其实现是用于训练 OmniH2O/HOVER 控制器的 Isaac Lab 扩展，并指向 human2humanoid 获取其他细节。论文初始实验环境与后续开源实现可能不同，复现时应固定提交和依赖版本。[代码 README](https://github.com/NVlabs/HOVER)

## 对人形 VLA 的启发与局限

**本调研分析**：高层输出空间与低层可控空间必须一致。例如高层同时要求手到桌边、身体继续远离桌子，就可能产生相互冲突的命令；单个控制器能够接收这些字段，并不意味着任意组合都可行。值得研究的不是“是否使用大模型”，而是如何限制、检测和修正不可达目标。

对本项目而言，HOVER 适合用于认识全身控制接口与语义决策的分工。它的主要局限边界是未直接解决场景语义、抓取接触规划和语言泛化；这不是对方法失败的判断，而是任务定义的范围。

## 阅读问题与候选复现

与 [OmniH2O](../2024_omnih2o/README.md) 比较输入目标；与 [HOMIE](../2025_homie/README.md) 比较是否固定上下身分工。读后应回答：教师知道什么、学生不知道什么？不同模式在哪里切换？全身轨迹为什么能监督仅有一只手目标的学生？

复现门槛中高，但仿真模块可以先于实机。建议先选择一个已有模式，确认坐标系、单位及目标定义，再比较切换前后误差和失衡率。无需先训练一个 VLA 才能研究这个问题。本轮没有安装环境、训练或测量性能。
