## 先看总结

1. 跨机器人数据不仅图像不同，状态和动作字段也不同；HEX 显式处理身体部位对齐。
2. 用统一本体状态预测器学习身体动态，再与视觉语言信息融合生成动作。
3. 有天工人形实机实验，但训练中出现某机型不等于在该机型上完成实机评测。
4. 高层代码与数据入口开放，不代表整套低层控制和采集系统开放。

依据[摘要](https://arxiv.org/abs/2604.07993)与[仓库](https://github.com/Open-X-Humanoid/HEX)。

## 背景与模型流程

初学者可以从一个数据问题进入：两个机器人都有“手臂”，但关节顺序、数量、身体状态字段可能不同。如果简单拼接数据，同一位置的数字可能代表完全不同的物理量。统一表示的任务，是让共享模型知道数据对应哪个身体部位，哪些字段缺失。

HEX 结合 Qwen-VL、按身体部位对齐的状态表示、Mixture-of-Experts 本体状态预测器及 flow-matching 动作头；历史视觉用紧凑 token 表示，未来状态信息与视觉语言信息融合。训练使用异构人形轨迹。高层部署时直接预测臂、手和腰部动作，腿部则由接收高层命令的 RL 全身控制器生成。[摘要](https://arxiv.org/abs/2604.07993)；[官方部署说明](https://github.com/Open-X-Humanoid/HEX)。

## 数据和证据边界

论文 v1 的训练数据包含多种双足与轮式构型，实机评价在天工 2.0/3.0 上进行，覆盖常规任务和长序列搬箱等。部分来源具有身体状态，却只有上肢动作标签；因此“使用全身状态”不能偷换成“每条轨迹都有全身动作监督”。[HTML 实验设置](https://arxiv.org/html/2604.07993v1)

仓库在核验日列出了预训练、微调、检查点和数据入口，同时明确说明天工系列的数据采集流程与低层 RL 控制器因商业限制未公开。README 中的最新任务数据与 v1 论文统计可能不同，应分别保留版本，不混写成同一实验。[官方仓库](https://github.com/Open-X-Humanoid/HEX)

## 对人形 VLA 的意义与局限

**本调研分析**：HEX 的重要学习点是把状态建模当作跨构型迁移的一部分，而不只关注图像和语言大模型。这有助于提出可测量问题：相同数据和动作头下，身体结构对齐是否改善迁移？改善来自额外预测任务，还是仅来自更多参数？

统一状态表示不能自动消除动力学差异。相同手臂目标在不同机器人上仍可能需要不同跟踪器；一个共享模型若依赖固定低层接口，其跨构型结论必须结合接口适配成本阅读。此段为研究分析，不是论文已验证的失败结论。

## 联系、阅读问题与候选复现

与 [HAF](../2026_haf/README.md) 比较“先预测身体动态”和“按身体依赖分阶段生成”的选择；与 [HOMIE](../2025_homie/README.md) 对照高低层命令匹配。读后应回答：哪些状态有监督、哪些动作缺标签？输出给下肢的是命令还是关节角？跨构型测试是否真有未见机型？

候选复现门槛高。离线模型推理、公开数据格式检查可以先做；完整天工实机复现还缺公开低层与采集流程。换用 G1 控制器属于适配实验，要重做接口和闭环验证，不能直接继承原论文数字。本轮未实施这些实验。
