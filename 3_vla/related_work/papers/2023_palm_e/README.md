# PaLM-E：把传感器观测接入语言模型

## 元数据与阅读状态

- **完整标题**：PaLM-E: An Embodied Multimodal Language Model
- **作者 / 年份**：Danny Driess、Fei Xia 等，2023。
- **定位**：P1；具身多模态理解与高层规划，**不应标成直接输出人形全身动作的 VLA**。
- **入口**：[论文摘要](https://arxiv.org/abs/2303.03378)｜[官方项目](https://palm-e.github.io/)。本轮未核验到官方完整训练代码/模型权重入口。
- **本轮阅读**：2026-09-29；摘要、官方项目方法与演示说明、官方技术博客；未下载论文，未全文精读或运行模型。

## 先读总结

1. 模型让图像、连续状态与文字共同成为语言模型输入，而不必先把所有观察手工写成文字。[S1]
2. 不同模态被映射到相同维度的嵌入空间，再由语言模型产生文本。[S2]
3. 机器人应用主要是产生子任务/计划，由低层语言条件策略执行；这与直接生成关节或末端动作有层级差异。[S3]
4. 对人形研究的价值是理解“语义决策”和“身体执行”之间的接口，不能用规划演示替代全身控制证据。

## 问题是什么

只读文字的模型不知道杯子现在是否被拿走、抽屉是否关上。如果每次都由人把场景写成文本，感知误差和信息丢失会成为瓶颈。PaLM-E 尝试让语言模型直接使用连续的视觉与状态表示，并在执行过程中根据新观察更新决策。

## 方法：多模态句子

项目描述的核心流程是：**图像/状态 → 对应编码器 → 与文字 token 同维度的连续向量 → 交错组成输入序列 → PaLM 自回归生成文本**。[S2]

可以把输入理解为“请根据〈图像向量〉和任务描述，决定下一步”。这些视觉向量不是必须能翻译成某个汉字的离散词，而是供注意力机制读取的特征。机器人执行环节再把文本子指令交给低层策略；新图像到来后可以重新规划。[S3]

**解释性推导**：这种拆分允许高层以较低频率讨论“先开抽屉”，同时低层处理“手向哪里移动”。但是，若技能库里没有开抽屉行为，高层写出这一步也无法完成任务；若传感器无法看清接触，高层模型规模再大也不能自动补足观测。

## 数据与监督

论文把机器人序列规划、视觉问答、图像描述等任务联合训练；使用预训练语言模型并训练模态编码，使视觉语言任务知识有机会迁移到具身任务。[S1] 官方博客还描述使用专家任务运动规划器生成的训练数据。此处监督的重点是文本完成/决策，而非把所有任务都表述成统一全身力矩标签。[S3]

## 实验证据与局限

作者报告多个具身任务之间以及视觉语言数据对机器人任务的正迁移。[S1] 官方展示包含轮式机器人取物、桌面推物，以及根据反馈进行多步决策。[S2] 这些结果支持感知接入和混合训练路线；不等于任意机器人零样本迁移，也不证明机器人执行层已经摆脱专门训练。

局限分析：文本决策与低层动作之间仍可能存在目标解释误差；长任务中错误可逐步积累；需要单独评估识别、规划与技能执行。闭源大型基础组件让从头复现门槛较高，故优先学习架构思想，而不是把它设为入门跑分基线。

## 联系与学习检查

与 [SayCan](../2022_saycan/README.md) 对照两种 grounding：一个强调技能成功可行性打分，一个强调连续感知进入语言模型；与 [RT-2](../2023_rt2/README.md) 对照输出从文本子任务变为动作 token 的变化。

阅读问题：输入连续向量与输出动作 token 是否一回事？演示成功究竟来自规划器还是执行器？可行学习练习是画出三级接口：任务文本、子任务文本、控制动作，并在每条连线上写出反馈和失败信号。以后复现开放替代模型时，要标明只是结构性实现，不是 PaLM-E 原模型重现。
