## 先看总结

1. 先解决机器人如何跟随人的姿态，再利用跟随过程采集自主操作数据。
2. 把低层运动技能与高层视觉决策分开，是理解后续人形 VLA 的好入口。
3. 有真实人形自主任务证据；“能从视觉做任务”仍不等于“能理解自由语言”。
4. 对初学者最有价值的是完整数据闭环，而不是某一个成功率数字。

以上定位依据[项目说明](https://humanoid-ai.github.io/)；第 4 点是本调研的学习建议。

## 问题背景与方法

人类动作视频无法直接充当机器人的电机命令：两者的肢体长度、关节数量和执行能力不同。HumanPlus 先把人体动作重定向为机器人姿态，再在仿真中学习跟踪这些姿态的控制策略。训练的动作来源包括 AMASS；部署时，外部 RGB 相机估计操作者身体和手部动作，转成机器人姿态目标，由低层控制器维持运动。机器人自身相机同时记录任务示范。[方法说明](https://arxiv.org/html/2406.10454v1)

自主阶段的高层输入是第一视角双目 RGB，并结合机器人状态；输出是身体、手部的目标姿态序列，由运动控制层执行。Humanoid Imitation Transformer 通过监督模仿学习任务技能，并加入视觉特征的未来预测。完整流程可以读成：**人体动作→姿态重定向→低层跟踪→采集机器人视觉/动作对→视觉技能策略→相同低层接口**。[HTML](https://arxiv.org/html/2406.10454v1)

## 证据支持什么

作者在定制的 33 自由度真实人形平台上展示了操作、起身与行走相结合的技能，项目报告的自主任务包括整理物体、折衣、打字等。这说明遥操作数据能够支持所设任务的自主执行；不能据此推导开放世界任务泛化、任意语言理解或任意人形的零样本迁移。[项目实验说明](https://humanoid-ai.github.io/)

开源仓库提供低层控制与模仿学习相关入口，并说明实机模仿部分基于 ACT/Mobile ALOHA，人体和手部估计分别参考 WHAM、HaMeR。机器人硬件、标定和控制接口仍是系统复现的一部分。[仓库 README](https://github.com/MarkFzp/humanplus)

## 对人形 VLA 的意义与局限

**本调研解释**：VLA 可以替换这里的视觉技能层，把语言作为目标输入；但底层姿态控制和数据同步不会因此自动消失。阅读时要区分“任务理解错误”“姿态目标不可达”“低层跟踪失败”，它们需要不同的实验定位。

本研究给后续全身 VLA 提供数据与控制桥梁，但原系统的语言接口、跨任务语义组合不是其主要证据。相机姿态估计噪声、身体映射偏差、示范覆盖和硬件特性均可能影响迁移；这些是复现时要测量的因素，不能只凭演示视频判断稳定性。

## 联系、阅读问题与复现门槛

先对照 [HOMIE](../2025_homie/README.md) 的同构外骨骼，再看 [HOVER](../2024_hover/README.md) 如何统一不同目标接口。建议画出高低层信号流，并回答：高层预测的动作和保存的数据标签是否一致？部署时延是否改变了标签与观测的对应关系？没有语言输入时怎样选择不同任务？

**候选复现**：中高门槛。无硬件时先读数据格式、重定向及仿真跟踪模块；有硬件后再做视觉模仿。最小学习实验应固定一个任务，记录动作误差、完成率与失败类型。这里没有完成任何复现，也不承诺一个通用显存或训练时长。
