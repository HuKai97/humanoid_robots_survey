## 先看总结

1. 人形穿过狭窄通道，不仅要规划地面路径，还要安排手臂、躯干和腿的位置。
2. 输入图像历史、本体状态与自然语言，预测完整身体参考轨迹。
3. 全部导航训练数据来自仿真合成，作者报告向 G1 实机的零样本迁移。
4. “零样本”特指没有真实导航训练数据，不代表模型从未使用预训练或运动控制先验。

依据[摘要](https://arxiv.org/abs/2609.09158)和[方法](https://arxiv.org/html/2609.09158v1)；最后一点是术语边界。

## 背景与数据生成

把机器人简化成地面上的圆盘，规划器可能认为一条路径能通过；真实人形的手、头或躯干仍可能撞上障碍。TANGO 把身体形状和姿态加入语言导航问题，而非只输出二维路径点。

数据流程包含全局路线规划、运动学身体动作生成、面向障碍的动作编辑和 RL 跟踪，以得到能执行的导航监督。模型读取前向及下视 RGB 历史、关节本体感知和指令，输出动作块。每步目标包含 **29 维关节角+6 维根部旋转表示**，下发给低层运动跟踪器。因此“29 自由度机器人”不意味着动作标签只有 29 个数，也不是直接预测力矩。[HTML §3.1–3.2](https://arxiv.org/html/2609.09158v1)

## 实验支持与发布状态

摘要报告仿真视觉语言导航、复杂障碍穿行的对比，并在 Unitree G1 上测试真实室内穿行。这个结果支持所测环境中身体适应与语言导航的组合；它不能证明抓取、灵巧手操作或无限长家庭任务已经解决。[arXiv 摘要](https://arxiv.org/abs/2609.09158)

论文说明拟开放数据流程、数据、VLA、权重及部署系统；本轮项目地址访问失败，也未核实可运行官方代码，因而只记录“发布计划”，不记为“完整开源”。[HTML 发布说明](https://arxiv.org/html/2609.09158v1)

## 对人形 VLA 的意义与局限

**本调研分析**：TANGO 说明全身 VLA 的目标可以是导航，而不仅是双手操作。它与 [WholeBodyVLA](../2025_wholebodyvla/README.md) 的区别，需要落到接口上：高层是否直接决定腿部参考姿态，还是只给移动命令；两种选择服务的任务约束不同。

仿真合成轨迹的覆盖决定了训练可见的障碍组合，编辑器和跟踪器也可能筛掉难例。读数据生成论文时应关注“多少候选被过滤，以及失败样本长什么样”，而不只看留下的成功轨迹。此处是建议检查的偏差来源，不是已证明本论文存在的问题。

## 阅读问题与候选复现

建议同时记录导航目标误差、完整成功、路径效率和身体碰撞；地面路径正确但上肢碰撞，应被看作不同失败类型。与 [HOVER](../2024_hover/README.md) 比较底层跟踪责任，与 [OpenHLM](../2026_openhlm/README.md) 比较全关节动作表示。

关键问题是：训练监督记录运动学参考还是实际跟踪状态？图像历史如何与动作块时间对齐？零样本实机测试改变了哪些视觉和动力学条件？这些细节决定能否把作者的方法移植到新场景。

复现门槛高且代码可得性待核验。最小学习项目可先在已有仿真中对比二维可通行与全身可通行判断，再考虑训练 VLA；完整复现还依赖场景、动作合成和控制器。本轮仅建立学习与追踪入口。
