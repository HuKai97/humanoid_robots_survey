# 人形机器人 VLA 调研综述

> 适合先读结论，再沿链接进入逐篇笔记。检索截止：2026-09-29。本文为基于一手网页材料的结构化调研，详细证据和阅读深度见每篇笔记；不是全文精读集，也不是穷尽性系统综述。

## 先读总结

1. 学习主线是：**动作学习 → 视觉语言知识迁移 → 通用机器人策略 → 人形全身接口与控制 → 可复现评测**。按照概念依赖阅读比按发布日期刷论文更有效。
2. 人形 VLA 的关键难点之一是把高层语义动作与可稳定执行的身体控制连接起来。论文标题、机器人外形和“全身”宣传都不能代替接口与实验核验。
3. 数据来源、动作表示、执行闭环和评测协议常与网络结构同样重要。不同benchmark的成功率不能拼成统一排名。
4. 对零基础学习者，先完成一个机械臂仿真基线，再研究人形接口，通常能更清楚地区分模型问题、数据问题与控制问题。这是学习建议，不是必须遵守的技术路线。
5. 2026 年已有更直接的人形 VLA 和评测工作，但新预印本的证据成熟度、开放资源和独立复现情况不同，应该分层阅读。

## 1. 本领域研究对象到底是什么

本文把“视觉、语言条件到机器人动作”作为 VLA 主线，同时保留三类必要背景：语言规划/具身理解、视觉动作学习、人形低层控制。这样既能看到 VLA 从哪里来，也能理解它怎样真正执行。

不宜用一个二元标签包住所有论文：SayCan 研究技能选择；PaLM-E 研究具身多模态语言模型；ACT、Diffusion Policy 主要研究动作学习；HOVER 等研究身体控制。它们对人形 VLA 很重要，但不是同一种模型。各自输入输出见对应解析。

人形实验还应分成：固定或稳定身体的上肢操作、轮式移动操作、双足全身移动操作、仅仿真的人形任务。真实人形身体也不自动说明高层策略学习了所有自由度。

## 2. 从动作学习到通用 VLA

### 2.1 先理解动作怎样被学习

[ACT](papers/2023_act_aloha/README.md) 用动作块组织精细操作学习；[Diffusion Policy](papers/2023_diffusion_policy/README.md) 用条件生成模型表达多种可行动作。这条线的核心问题是连续动作的连贯性、多模态性和误差累积，而不是语言模型规模。

阅读时建议固定同一个例子：“绕开杯柄，把杯子提起来”。一个平均轨迹可能穿过杯子，而两个不同方向的轨迹都能成功；动作分布比单点预测更自然。但生成的动作仍需要及时反馈，不能只看离线动作误差。

### 2.2 语言理解怎样接到行为

[SayCan](papers/2022_saycan/README.md) 把语言模型的任务相关性与技能可行性结合，展示高层规划与已有技能如何协同。[PaLM-E](papers/2023_palm_e/README.md) 则把传感信息纳入语言模型。二者有助于理解“会描述计划”与“会生成连续控制动作”的区别。

[RT-1](papers/2022_rt1/README.md) 展示从大规模真实机器人示范学习多任务策略；[RT-2](papers/2023_rt2/README.md) 将动作编码为 token，进一步把预训练视觉语言知识接到动作预测。这里重要的是知识迁移方式，不是“互联网知识已经替代机器人经验”。语义选对物体和物理抓取成功仍是两件事。

### 2.3 数据共享与开放模型

[OXE/RT-X](papers/2023_open_x_embodiment/README.md) 让多机器人数据共享与迁移成为可研究的问题；[Octo](papers/2024_octo/README.md) 与 [OpenVLA](papers/2024_openvla/README.md) 提供不同的开放通用策略路线。

尤其要留意动作统一的含义：统一数组结构不等于统一坐标系、单位和绝对/相对语义。OXE 笔记记录了这一限制。跨身体共享可能发生在视觉、语言或行为表征层，部署到新硬件需要核对接口；是否需要目标域示范和微调，取决于预训练覆盖及平台差异。

### 2.4 连续动作、效率与更大范围泛化

[π0](papers/2024_pi0/README.md) 将视觉语言表征与连续动作专家连接；[FAST](papers/2025_fast/README.md) 研究高效动作 token 化；[OpenVLA-OFT](papers/2025_openvla_oft/README.md) 与 [SmolVLA](papers/2025_smolvla/README.md) 从训练/推理配方和资源效率提供实践入口。[π0.5](papers/2025_pi05/README.md) 把关注点进一步推向开放世界泛化；[Gemini Robotics](papers/2025_gemini_robotics/README.md) 提供另一条大型具身模型路线。

这些工作不能只按“离散”与“连续”简单判优：数据、骨干预训练、动作块长度、输入相机、推理并行化和执行方式都可能影响结果。π0.5 原论文与当前 openpi 配方亦有版本差别，详见笔记。评估资源效率时，应测完整闭环，而不仅是模型一次 forward 的耗时。

## 3. 通用策略如何走向人形

### 3.1 先解决身体执行和示范采集

[HumanPlus](papers/2024_humanplus/README.md) 连接人类动作学习、身体控制与自主技能；[OmniH2O](papers/2024_omnih2o/README.md)、[HOVER](papers/2024_hover/README.md)、[HOMIE](papers/2025_homie/README.md) 提供理解全身控制与遥操作的不同入口。这些工作说明，仅有高层模型还不够，身体参考如何映射到关节、接触和平衡是系统核心。

把人的视频用于机器人学习，还必须面对形态差异：人的骨长、手部结构和支撑方式与机器人不同。**运动重定向并不自动保证动态可执行**，控制器或训练目标还要处理接触和稳定性。详细机制依论文而异，不能把所有系统概括成相同的“人类视频直接训练”。

### 3.2 人形 VLA 的证据有层次

[GR00T N1](papers/2025_groot_n1/README.md) 是理解人形基础策略与分层模型的入口；它的实验范围、训练资源和当前仓库后续版本必须分开。[HumanVLA](papers/2024_humanvla/README.md) 把具身视觉语言与全身运动连接，但本次核验的实验是在物理仿真人形中，不能写成真机验证。

[WholeBodyVLA](papers/2025_wholebodyvla/README.md) 更直接研究真实人形移动操作。它在概念上重要，但本次核验的官方资源页不等于可用训练代码仓库，不能仅凭一个GitHub链接判断可复现性。

### 3.3 2026 年值得跟踪的分支

- [HEX](papers/2026_hex/README.md)：关注全身协调和身体表征；公开高层材料不代表低层控制也完整公开。
- [OpenHLM](papers/2026_openhlm/README.md)：关注开放人形移动操作策略与接口；任务进度指标不要改写为完整成功率。
- [HAF](papers/2026_haf/README.md)：从分阶段动作生成与后训练适配研究协调；早期 HAF-VLA 页面与完整 HAF 论文属于不同版本口径。
- [TANGO](papers/2026_tango/README.md)：本轮纳入的9月新预印本，应优先核验方法与数据假设，暂不作成熟基线排名。
- [DreamZero](papers/2026_dreamzero/README.md)：世界动作模型方向，联合未来观察与动作的建模值得了解；它是相邻路线，不能不加区分地归为同一种VLA架构。

以上是调研选择，不是对学术影响力或SOTA的结论。企业发布另见 [人形发布观察](HUMANOID_RELEASES.md) 与 [近期模型更新](RECENT_RELEASES.md)，不与论文证据混写。

## 4. 数据与评测应该怎样选

[BridgeData V2](papers/2023_bridgedata_v2/README.md) 和 [DROID](papers/2024_droid/README.md) 适合学习真实机器人数据；OXE适合研究跨来源混合。[LIBERO](papers/2023_libero/README.md) 适合建立受控任务与迁移评估意识；[SIMPLER](papers/2024_simpler/README.md) 追问仿真排名能否代表真实行为。

[RoboCasa](papers/2024_robocasa/README.md)、[RoboCasa365](papers/2026_robocasa365/README.md)、[BEHAVIOR-1K](papers/2024_behavior_1k/README.md) 把问题推进到更丰富的日常环境与长任务；[SIMPLE](papers/2026_simple/README.md) 则直接面向人形移动操作的仿真学习与评测。

| 你想验证的问题 | 更合适的起点 | 必须补充的检查 |
|---|---|---|
| 语言/对象/空间变化影响 | LIBERO | 任务划分、语言对照、预训练重叠 |
| 真实数据训练策略的仿真行为 | SIMPLER | 视觉与动作校准、真机相关性范围 |
| 场景、任务与数据规模 | RoboCasa / RoboCasa365 | 版本、预算、场景重叠、生成数据筛选 |
| 长时程家庭活动 | BEHAVIOR-1K | 子任务进度与完整成功分开报告 |
| 人形移动与操作的耦合 | SIMPLE及对应人形论文设置 | 身体形态、高低层控制、跌倒与干预 |

这里是研究问题与工具的匹配建议，不是各平台性能排名。

## 5. 横向读论文的统一问题

1. **输入**：只有单帧图像和语言，还是多视角、历史、本体状态？训练时有无部署不可得的特权信息？
2. **输出**：动作 token、连续动作块、末端位姿、关节目标、底盘命令或潜变量？维度之外的物理含义是什么？
3. **监督**：真实示范、人类视频、动作捕捉、仿真专家、在线RL各占什么角色？
4. **执行**：高层和低层怎样同步？输出几步、执行几步？超时、接触失败或模型卡顿时发生什么？
5. **泛化**：新物体、新场景、新任务、新语言和新身体分别怎样划分？是否真的未进入训练？
6. **证据**：实际测了哪些平台与任务？报告成功、进度还是归一化得分？有多少回合、什么不确定性？
7. **可复现性**：代码、权重、训练数据、环境资产、机器人控制器分别是否开放，版本是否对得上？

这七问比只看摘要里的“泛化”“通用”“端到端”更适合作为读书报告骨架。

## 6. 可以开始研究的具体切口

以下是依据本轮文献提出的**待验证候选问题**，不是已确认的空白或创新：

- 在固定数据和推理预算下，改变动作块实际执行长度如何影响扰动恢复？
- 同场景替换语言指令时，策略是否真正跟随目标，还是依赖任务/场景先验？
- 人形高层策略的失败有多少来自坐标系、动作范围和低层跟踪误差，而非语义判断？
- 在相同训练步数下，增加场景多样性还是重复更多相似轨迹更有价值？
- 高层策略与低层控制器的版本变化，是否改变模型之间的相对排名？

这些问题应在复现 baseline、检查近邻工作之后缩小范围。具体记录位置是 [brainstorm.md](../brainstorm.md)，真正的实验结果只进入 [experiment/results.md](../experiment/results.md)。
