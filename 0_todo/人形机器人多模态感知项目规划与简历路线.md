## 1. 背景与项目选择原则

### 1.1 当前经历可以怎样衔接

传统轮式机器人感知经验可以迁移到三维几何、检测分割、传感器标定、坐标转换、定位接口、实时部署和现场问题定位。进入人形机器人领域后，值得继续补充的能力包括：身体运动下的稳定感知、头部与腕部等可动传感器的几何关系、近身及足部环境理解、语言语义与三维空间关联，以及视觉与接触信息结合的操作状态判断。

当前两项工作可以成为起点：

- 巡检障碍物检测可以扩展为地形感知、动态目标跟踪、语义地图和主动异常复核。
- 跑道线检测可以扩展为姿态补偿、地面几何恢复、时序跟踪、低延迟输出和与奔跑控制的联合验证。
- 如果公司已有稳定机械臂、手和操作团队，可以从巡检中的按钮、柜门和把手切入操作感知。

建议形成“运动中的三维感知主线＋一个语义或操作拓展方向＋共同的数据和部署能力”。项目数量由资源决定，两个完成度高的主项目加一个清晰的小项目，通常比多个尚无评测的原型更容易组织成连贯的个人技术经历。这里是项目规划判断，不构成对招聘结果的保证。

### 1.2 先区分三类求职目标

| 目标岗位 | 需要通过项目证明什么 | 本文更匹配的方向 |
|---|---|---|
| 机器人三维感知／融合感知 | 几何精度、时序稳定性、多传感器处理、部署和真机问题分析 | 方向一、四、七，配合第 10—11 章 |
| 具身多模态／视觉语言感知 | 语言与视觉的关联、空间理解、数据构建、模型适配和任务评测 | 方向二、五，进一步参考第 12 章 |
| 操作感知／机器人学习 | 物体与交互位置、手眼几何、接触状态、操作闭环和任务泛化 | 方向三、六，进一步参考第 12 章 |

### 1.3 一个值得做的项目应满足的条件

1. **有具体使用者。** 能说清导航、运控、操作或业务团队实际消费什么输出。
2. **有可观察的痛点。** 例如机器人走动后地图抖动、柜体误认、机械臂接近时目标丢失。
3. **有你可以掌握的核心问题。** 如时间补偿、时序关联、交互点估计、异常复核策略，而不是所有关键模块都依赖他人。
4. **能建立基线。** 在同一数据、同一硬件和相同任务条件下比较改动前后的效果。
5. **有足够的数据与测试机会。** 能收集失败样本，允许模型或系统迭代。
6. **范围能够收敛。** 能定义第一版交付，不必等待整个人形机器人系统全部成熟。

### 1.4 多模态应落实到信息如何起作用

RGB、深度、激光、IMU、关节状态、语言、力、触觉和音频都可能贡献不同信息，但同时记录多个传感器并不等于已经实现有效融合。

融合可以发生在不同位置：利用姿态做几何补偿、用深度把语义投影到三维、在特征层结合视觉与触觉、在决策层根据模态质量选择证据。每种做法都应说明输入、融合位置、失效条件，并通过单模态对照或消融证明贡献。

RGB-D 与 IMU 的几何融合能证明机器人感知能力；如果目标岗位要求 VLM 训练，还需要额外证明视觉语言数据、模型适配和泛化评测能力。两者可以相互支撑，但简历里要准确区分。

## 2. 全部方向总览与优先级

### 2.1 按当前背景给出的初始排序

| 方向 | 最小任务 | 主要依赖 | 初始建议 | 主要简历价值 |
|---|---|---|---|---|
| 一：三维地形与可通行性 | 平地、门槛、坡面局部感知 | 深度或雷达、姿态／定位、导航或运控接口 | 优先作为主项目 | 人形运动条件下的三维感知、融合与落地 |
| 二：开放词汇语义地图 | 已建图区域内按描述定位设备并导航观察 | RGB-D、定位、语义模型、导航接口 | 想向多模态方向发展时优先 | 视觉语言理解与空间落地 |
| 三：操作位姿与交互点 | 一类按钮或把手的交互位置输出与验证 | 可用机械臂、标定、操作配合 | 硬件成熟时提升为第二主线 | 三维操作感知、视觉闭环 |
| 四：动态目标跟踪 | 行人和推车的三维位置、速度与轨迹 | 序列数据、位姿、深度或雷达 | 可并入巡检主线，或在动态场景多时独立 | 时序关联、动静分离、融合鲁棒性 |
| 五：主动巡检与异常复核 | 看不清时换视角、疑似异常时复查 | 可移动视点、设备真值、任务接口 | 巡检业务重视误报与人工复核时优先 | 主动感知、质量评估、业务闭环 |
| 六：视觉与力／触觉融合 | 一个操作中的接触或失败检测 | 稳定操作、力或触觉数据、同步采集 | 资源齐备后做 | 多模态时序建模、操作状态理解 |
| 七：跑道几何与时序跟踪 | 横向／航向偏差、置信度及丢线恢复 | 已有相机、姿态、运控接口 | 最快形成完整阶段成果 | 运动补偿、几何估计、低延迟闭环 |

“优先”以当前可见背景为前提。若公司主要做操作、已有大量示教数据和成熟机械臂，则方向三、六应上调；若没有深度或雷达，方向一需先缩减为明确假设下的地面几何试验，不能承诺可靠的任意三维障碍感知。

## 3. 方向一：三维地形与可通行性感知

### 3.1 项目定位：把“检测到障碍”推进到“向运动模块提供可靠的环境几何”

这是与你现有巡检项目衔接最顺的主线。业务问题可以限定为：人形机器人在厂房、园区和楼宇中巡检时，需要识别地面起伏、门槛、坡道、低矮障碍及通行空间，在行走造成的视角扰动下持续向导航与运控输出局部环境描述。项目价值不在于检测类别数量多，而在于几何是否准确、未知区域是否诚实表达、输出是否稳定且及时。

建议明确职责边界：感知模块输出地形、障碍和不确定性；导航、落脚规划与运控模块结合机器人状态、动作能力和安全余量决定怎样通过。这里的“可通行性”是**在给定机器人尺寸、动作限制和环境假设下的候选通行评分**，不是感知对动作一定可执行的保证。不要在简历中把完成高程图描述成已经解决自主上下楼或复杂地形运动控制。

### 3.2 最小版本与进阶版本

**最小可用版本：** 固定机器人与传感器配置，覆盖平地、静态箱体、低门槛和缓坡；生成随机器人移动的局部高程图，输出地面高度、局部坡度、粗糙度、障碍边界、观测置信度与未知区域。先从低速行走开始，使下游能够稳定查询“前方某个位置的高度及可信程度”。场景与高度范围应由公司真实路线及机器人能力确定。

**第二阶段：** 加入连续行走、转身、自遮挡、地面材质变化和传感器暂时失效，解决时间同步、自身点云过滤、历史地图残留、负障碍候选区域及局部地图更新问题。

**第三阶段：** 根据实际失败案例补充三维空间表达、躯干通道和头顶净空检查；与落脚规划团队共同验证感知候选落脚区域的有效性。复杂楼梯、草地与可变形地面应作为独立扩展任务，不要在首版同时承诺。

2.5D 高程图一般为一个水平网格单元记录一个表面高度，适合表达主要地表，查询成本较低；桌面与桌下、悬空横杆和桥下通道等多层结构不能由单高度充分表达。可以保留高程图服务脚下几何，同时在近身区域维护三维占据或额外净空层。不能因一个网格“有地面”便认为整个身体空间可通过。

### 3.3 输入、输出与接口约定

| 类别 | 建议字段或内容 | 工程注意点 |
|---|---|---|
| 环境观测 | 深度图或点云、可选 RGB、传感器时间戳、质量标记 | 不同材质的深度有效率可能差异很大 |
| 状态输入 | 传感器外参、机器人位姿、IMU 姿态、关节状态 | 区分传感器曝光／采样时刻与消息到达时刻 |
| 机器人先验 | 机体几何模型、脚掌尺寸、通道尺寸、动作约束版本 | 参数由机器人及运控团队确认 |
| 地图输出 | `frame_id`、分辨率、原点、有效范围、更新时间 | 明确地图是在世界系、里程计系还是机器人局部系 |
| 网格属性 | `height`、`variance`、`slope`、`roughness`、`observed`、`age` | 无观测、低置信度和确认空闲是不同状态 |
| 查询输出 | 区域高度统计、边界距离、候选通行评分、原因码 | 让下游知道低分来自坡度、障碍还是信息不足 |
| 健康状态 | 输入丢帧、位姿过期、标定版本、地图过期 | 用于减速、重新观察或暂停等上层策略 |

所有距离与角度单位、时间基准、坐标轴方向、最大可接受延迟都应写入接口文档。对需要执行动作的位置，返回观测时间和有效期；不要让下游把数秒前的地图当作刚刚测得的环境。

### 3.4 算法流程与选择依据

1. **标定与时间对齐。** 先用静态平面和运动序列检查深度尺度、外参及时间偏差。机器人原地摆动时若静态墙面或地面随之变形，应优先排查时序与坐标变换。
2. **观测预处理。** 依据传感器质量、距离和无效值过滤观测；若传感器具有帧内采样时间且运动影响明显，再加入相应去畸变。避免把整个步态周期内不同姿态的点直接叠加。
3. **自身点云过滤。** 通过关节状态和机器人几何模型剔除手臂、腿部等本体观测，并检查过滤边界是否误删脚边的真实障碍。盲区应保留为未知。
4. **局部几何构建。** 将观测投影到局部地图，估计网格高度及不确定性，采用适合噪声分布的稳健统计降低飞点影响。分辨率必须结合最小目标尺寸、有效点密度和计算预算选择。
5. **时序融合与清理。** 综合新观测质量、位姿质量和历史观测年龄更新地图；设计移走物体的清除条件。单纯累积点云容易产生拖影，单纯固定时间删除又可能清掉暂时被脚遮挡的静态障碍。
6. **地形属性与通行候选。** 计算坡度、粗糙度、阶跃、离边缘距离、有效观测覆盖率；按脚掌支撑尺度检查区域，而非只看单个网格。先采用可解释几何规则，后续只有在明确失效模式与标注条件下才考虑学习式评分。
7. **发布与在线诊断。** 输出局部地图、置信度和状态码，记录端到端延迟、地图更新率及降级状态。下游动作测试必须使用实际部署链路。

可参考 [Elevation Mapping CuPy 官方仓库](https://github.com/leggedrobotics/elevation_mapping_cupy) 的实现与接口设计。参考开源方案时，应把个人贡献落在机器人适配、质量建模、融合改进、失败诊断和真实评测上，而不是只写“部署某开源算法”。

### 3.5 人形特有难点与关键失败案例

- **步态扰动与姿态误差耦合：** 相机高度和姿态周期性变化，微小姿态偏差可使远处地面出现明显高度偏差。需要按速度、转身幅度和步态阶段分析误差。
- **足边盲区和自身遮挡：** 最近处恰好可能是即将使用的地面；历史观测能补充信息，但必须带有年龄和位姿误差说明。
- **负障碍：** 没有深度既可能是坑洞，也可能是反光、超量程或遮挡；应输出未知或边缘风险候选，不能直接断言是坑，也不能当作平地。
- **感知几何与接触性质不同：** 同样高度的地面可能是松软材料或可滑动物体；仅凭几何不应承诺承重、摩擦或稳定支撑。
- **空间尺度冲突：** 能容纳脚的位置未必容纳膝盖、躯干和摆臂；脚下候选区域与全身通道需要分别检查。
- **地图残影：** 行人离开后仍被视为障碍，或真实静态障碍因暂时无观测被清除；需要专门准备移入、停留、移出的序列评估。

### 3.6 数据集与标注方案

建立场景矩阵：地面类型、光照、传感器距离、目标高度／宽度、机器人速度、俯仰横滚幅度、自遮挡程度、动态干扰。第一轮优先采集业务路线中高频、易失败的组合，不必追求类别大全。

几何真值可以来自实测高度与尺寸的标准物体、静态高质量扫描、经验证的参考平面或离线重建；每种真值都要记录自身误差。标注包含地面／障碍／未知区域、障碍边界、结构尺寸、有效参考区域及失败原因。若参考重建本身看不到坑底，不应给出虚构完整真值。

按地点和采集批次划分训练、调参与测试集合，连续相邻帧应进入同一集合。保存整段原始传感器和机器人状态，保证可以重放不同融合参数；同时建立十余类固定失败片段，作为改动后的回归样本。学习式方法另外保存标签定义、标注一致性和各难例的数量分布。

### 3.7 离线与真机指标：写清分母和条件

| 指标 | 定义与统计条件 | 使用目的 |
|---|---|---|
| 高度误差 | 在具有可靠真值的已观测网格上统计绝对误差均值、P95；同时报告这些网格占参考区域的比例 | 防止只输出少量容易网格来获得低误差 |
| 障碍召回率 | 成功匹配的真值障碍数／预先定义几何视域内、参考系统确认可见且符合尺寸条件的真值障碍总数；不得按算法是否获得有效深度或输出置信度事后排除样本，按距离、尺寸与可见程度分桶 | 暴露低矮、小尺寸和远距离漏检 |
| 误报率 | 每平方米参考空闲区域中的误报数量，或被错误占用的面积比例；口径固定 | 评估虚假阻塞 |
| 未知区域比例 | 查询区域内被标为未知的面积／查询总面积；分场景和距离报告 | 与准确率共同反映信息可用性 |
| 地图稳定性 | 静态目标经参考位姿对齐后的高度波动和边界位置波动；在同一行走序列上统计 | 检验运动补偿和时序融合 |
| 端到端延迟 | 输出发布时刻减去其对应最新环境观测采样时刻，报告 P50／P95 与最大值 | 反映本次更新的处理延迟，需结合网格观测年龄使用 |
| 固定路线完成率 | 无人工介入完成规定路线的次数／所有符合测试协议的有效尝试次数 | 联合衡量系统表现，必须记录失败归因 |
| 干预频度 | 人工介入次数／累计行走距离，注明速度、路线、负载和地形配置 | 避免路线长短不同导致比较失真 |

最新融合观测的延迟只描述该次更新；对保留历史观测的地图，另统计实际查询区域各网格的观测年龄分布、最大值和过期面积，避免少量新数据掩盖整体陈旧。

真机比较时固定导航和运控版本，尽量交替运行基线与改进版，并记录每次尝试。地图质量提升不必然等于通行成功率提升；二者不一致时要检查接口、规划策略和机器人动作能力。

### 3.8 对比、消融与分阶段交付

以现有单帧障碍检测或简单点云栅格为基线，依次评估姿态补偿、自身过滤、多帧融合、观测年龄建模、未知区域处理和近身三维空间检查。每个消融只回答一个问题，例如“相同误报水平下，融合能否降低低矮障碍漏检”，而非只报告所有模块叠加后的最好结果。

阶段交付建议：第一阶段完成数据重放、坐标及时间诊断和基线报告；第二阶段交付可在线查询的高程地图及接口；第三阶段覆盖运动和遮挡难例并做消融；第四阶段与导航／运控联合完成固定路线验证及失败归因。排期主要依赖传感器质量、位姿可用性、真机时间和下游接口，不能仅按模型开发工作量估算。

### 3.9 面试准备与真实简历模板

面试应能解释：为何选 2.5D、何时需要 3D；如何区分未知与空闲；地图误差主要来自深度、外参还是姿态；怎样清除动态残影；感知与落脚规划的职责边界；一次真实失败如何通过日志定位并修复。准备一张系统图、一段对比视频、一张分场景指标表和一个完整失败分析，比仅展示彩色点云更有说服力。

简历模板：**“负责人形机器人巡检中的局部地形感知，融合【真实传感器与状态输入】，实现【本人负责的模块】，输出【高程／边界／置信度等实际字段】供【导航／落脚规划】使用；在【速度、场景、测试规模】下，将【明确指标】由【基线】改善至【结果】，并完成【实际部署与联合验证范围】。”** 只填已经完成且可追溯的数据；如果仅完成感知离线验证，就明确写离线，不提前写成自主跨越或上下楼。

## 4. 方向二：开放词汇目标定位与语义地图

### 4.1 项目定位与业务价值

建议项目名：**面向人形机器人巡检的开放词汇三维目标定位与语义地图**。

业务例子是：操作员输入“找到门口左侧的配电柜，走到能看清仪表的位置”，机器人解析目标、在当前视觉或已有地图中检索候选、确认具体设备，向导航模块输出可到达的观察位姿，并在到达后再次验证目标。你的核心产出是可靠的目标与空间关联，而不是仅仅让大模型生成一段回答。

这个方向适合你从传统几何感知向视觉语言感知拓展：原有的标定、投影、定位和地图能力仍然有用，新增能力集中在视觉与文本对齐、实例关联、语义地图维护和不确定性处理。它可以与巡检、主动观察、操作感知共享设备实例库。

### 4.2 先明确三种任务边界

| 任务 | 环境条件与输入 | 必须解决的问题 | 适合作为哪一阶段 |
|---|---|---|---|
| 已知地图中的语言目标导航 | 已有几何地图，目标可能已被拍摄并写入语义地图 | 语言检索、目标消歧、空间定位、选择观察点、到达确认 | 第一阶段主任务 |
| 未知环境中的目标搜索 | 地图不完整，目标可能从未进入视野 | 在前者基础上增加探索、搜索优先级、覆盖状态与终止规则 | 后续扩展 |
| 完整视觉语言导航（VLN） | 根据任务设定，需跟随涉及路径、地标、动作顺序的语言指令 | 沿途视觉与语言对齐、阶段进度判断、长期决策与恢复；评测依赖具体基准 | 独立的大项目 |

不要把“在地图中找到椅子并导航过去”直接写成已经完成通用 VLN，也不要把调用现成视觉语言模型等同于自行训练了基础模型。不同研究工作的任务定义可能不同，简历中应写清你实际支持的输入、环境前提和任务范围。

### 4.3 输入、输出与模块接口

输入包括 RGB 图像、可选深度或已配准点云、相机内外参、带时间戳的机器人位姿、关节状态、几何地图、语言查询，以及可选的设备台账。输出建议拆为以下两层：

- **感知结果：** `instance_id`、文本类别与属性、三维包围盒或表面区域、关联证据图像、最后观测时间、定位不确定性、匹配分数、状态（已确认／有歧义／未发现／过期）。
- **任务接口：** 候选观察位姿列表、目标面朝向或可见区域、导航前置条件、到达后的验证规则。感知只提出候选，导航模块检查路径可达性和运动约束。

文本相似度通常不是经过校准的正确概率。若需要使用“置信度”，应在独立验证集上分析分数与错误率的对应关系，并记录阈值适用的类别和场景。

### 4.4 推荐技术流程与选择依据

1. **语言结构化。** 将查询拆为类别、外观属性、编号和空间关系。“左边”必须有参照系：机器人当前视角、门的朝向，还是地图约定方向。无法确定时输出歧义状态，不能随意选一个目标。
2. **二维候选提取。** 采用开放词汇检测或图文特征检索得到候选，再按需要做分割。设备编号优先结合 OCR、二维码或台账；若业务允许使用标识，应把它作为强基线。
3. **三维定位。** 将有效深度反投影到地图坐标系，去除背景与离群点，估计目标空间范围。深度缺失时保留二维证据，或通过有足够视差的多帧重建补充，不应直接输出虚假的精确位置。
4. **跨帧实例关联。** 综合空间重叠、外观、文本属性、编号和可见性判断是否属于同一实例。对高度相似的相邻柜体，几何与编号通常比单独外观更有区分价值。
5. **语义地图维护。** 保存实例历史、更新时间与观测来源。物体移动后，要有重定位或旧记录失效机制；一次遮挡造成的未检出不能立即解释为目标已被移走。
6. **查询与消歧。** 先检索候选，再验证空间关系和身份。让语言模型负责解析或解释可以是实现选项，但目标坐标必须来自可追溯的感知与地图计算。
7. **观察位姿生成与闭环验证。** 根据目标表面、视距和可见性提出候选，导航到达后重新识别具体实例，避免“到达附近”被误计为“找到目标”。

地图表达可先选择**实例表＋三维几何位置＋代表性图像特征**，便于调试设备身份与更新逻辑；当需要对未预定义类别进行密集查询时，再考虑把图文特征融合到栅格、点云或体素中。表达越密集，存储、融合与查询成本越需要测量。

作为技术参考，VLMaps 将预训练视觉语言特征与场景几何重建结合，使地图可以被自然语言查询。这里建议借鉴其“语义特征落到几何空间”的思路，并围绕真实设备身份、地图更新和机器人接口补足工程能力。[VLMaps 官方项目](https://vlmaps.github.io/)

### 4.5 最小版本与进阶路线

- **最小可用版本：** 一个已建图场地、少量固定设备、类别和编号查询；完成离线建图、候选检索、三维目标定位与到达验证。
- **工程进阶：** 增加相似设备消歧、视角变化、遮挡、目标移动、未见类别和“目标不存在”测试，建立在线更新与证据管理机制。
- **算法进阶：** 在发现明确瓶颈后，选一个问题做专门改进，例如基于多视角一致性的实例关联、文本与几何联合匹配、针对设备域的模型适配、带观测时效的地图更新。
- **探索扩展：** 在地图不足时输出可执行的搜索目标，记录已经观察过的区域和证据质量，设置时间或路径预算；探索策略需要导航团队共同承担。

部署现成模型可以形成“机器人感知系统研发”项目。若希望简历体现模型研究，应额外承担数据构建、训练目标、冻结／微调策略、泛化分析和独立测试；仅修改提示词，不宜写成“训练了多模态大模型”。

### 4.6 人形平台的具体难点

头部转动、躯干摆动和升降会改变相机位姿，不能一直使用静态外参描述相机相对世界的关系；需要相机外参与机器人运动学、时间同步共同形成投影链。走动模糊可能造成错误候选进入地图，应按观测质量筛选关键帧。手臂自遮挡、俯视与平视外观差异，也需要在数据与关联逻辑中覆盖。导航终点还要满足人形机器人的站立空间与观察姿态要求。

### 4.7 数据采集与标注

按“场地—采集日期—设备实例—轨迹”组织数据，保留原始传感器与位姿。标注类别、设备实例 ID、属性／编号、二维框或掩码、三维参考位置和可见性。语言查询覆盖同义表达、相似设备、空间关系、含糊描述以及不存在的目标。

测试集应分别体现新视角、新设备实例、新场地和新类别，不能把同一段视频的相邻帧随机拆到训练和测试中。对实例身份与三维误差，使用人工核对、标识或测量建立参考真值，并说明真值精度。语言数据要包括真实用户表达，避免只测模板化指令。

### 4.8 离线与真机指标

| 指标 | 建议定义 |
|---|---|
| 查询成功率 | 在目标存在的查询中，第一候选的实例 ID 正确且三维位置落入预先设定容差的比例 |
| 三维定位误差 | 正确匹配实例后，预测参考点与真值参考点的距离；报告中位数和 P95，并另报未定位比例 |
| 相似设备误认率 | 包含同类干扰设备的查询中，最终输出错误实例的比例 |
| 不存在目标误接受率 | 目标确实不存在的查询中，仍返回“已确认目标”的比例；同时报告存在目标的拒识率 |
| 实例地图一致性 | 对人工匹配的实体，统计被拆成多条记录的比例、不同实体被误合并的比例与过期记录数量 |
| 任务成功率 | 目标存在的任务中，在预设时间内到达允许观察区域并验证正确实例的任务数／全部预定义正样本任务数；导航失败保留在分母。目标不存在的任务另统计预算内正确拒识率及误确认率 |
| 性能成本 | 指定硬件与地图规模下的建图速度、查询 P50／P95 时延、显存／内存、地图存储量 |

### 4.9 对比、消融与失败归因

至少比较固定类别检测＋设备台账、单帧图文检索、加入三维地图的方案。消融可以分别去掉时序关联、几何门控、编号信息、地图过期处理，确认改进来自哪里。所有对比使用相同测试任务、导航模块和成功判据。

典型失败包括：把两个柜体合并、语言“左侧”的参照错误、定位漂移造成地图重影、目标被遮挡后错误删除、目标移动后仍导航到旧位置。每个失败都应落到“语言解析／二维识别／几何定位／实例关联／地图维护／导航执行”的环节，避免用一个总体成功率掩盖问题。

### 4.10 阶段交付、面试与简历

阶段交付依次是：带数据规范的离线定位基线；可查询并显示证据的实例地图；与导航联调的到达验证；包含困难查询与负样本的评测报告；针对一个核心失败类型的算法改进。主要依赖稳定定位、可访问的导航接口、足够的设备采集权限和推理硬件。

准备回答：为什么采用实例地图而不是密集特征地图？相似度阈值怎样确定？设备移动后怎样处理旧位置？你如何证明提升来自感知而不是导航调参？模型哪些部分由你训练，哪些直接使用？陌生类别、陌生实例和陌生场地分别测试了吗？

真实简历模板：

> 负责【场地／设备范围】下的人形机器人开放词汇三维目标定位与语义地图，基于【实际模型】实现【多视角实例关联／语义几何融合／设备身份校验等个人贡献】，构建包含【真实规模】查询和【真实负样本范围】的独立测试集；将【明确定义的查询指标】由【基线】提升至【结果】，在【硬件】上达到【实测时延】，完成【真实次数】次语言目标导航与到达确认测试。

## 5. 方向三：面向操作的物体位姿与交互点感知

### 5.1 项目要解决什么业务问题

把巡检中的“看见设备”推进到“给操作模块提供可执行的目标”：发现需要复位的按钮，定位可按压区域；找到柜门把手，给出接近方向；找到工具，生成抓取候选；执行后判断按钮状态、柜门状态或物体位置是否发生预期变化。建议优先选择一种操作、少量对象和固定测试区域，先解决定位与动作之间的接口问题。

对你而言，这个方向可以复用检测、分割、三维几何、坐标变换、传感器标定经验，同时补充操作感知。它对机械臂、夹爪和操作团队的依赖明显高于导航感知，立项前应确认机器人能稳定完成“给定位姿后的接近、执行、撤离”。如果这个能力尚不存在，项目先定位为“交互目标定位”，不要承诺完整操作成功率。

### 5.2 MVP、进阶版本与范围控制

- **MVP：按钮交互点定位。** 选择几类尺寸和安装方向明确的按钮，在机器人站定时输出按钮中心或可按压区域、表面法向、置信度，支持深度无效时拒绝输出；与操作同事完成受控测试。
- **进阶一：末端靠近中的连续感知。** 增加头部相机与腕部相机协同、目标跟踪、遮挡处理和重定位；验证接近过程中目标坐标是否稳定。
- **进阶二：把手或工具位姿。** 引入完整物体姿态、抓取候选、碰撞空间和可达性检查；支持多种摆放姿态与部分遮挡。
- **进阶三：操作结果确认。** 用前后视觉、关节状态或力反馈判断任务是否完成；失败后选择重新观测、重新定位或交由上层恢复策略。

按钮任务通常只需接触点和法向，绕法向的转角可能没有业务意义；把手拉动需要抓取姿态、受力方向和后续运动约束；有特定插装方向的零件通常需要完整 6D 位姿。应从操作约束反推感知输出，避免为所有对象统一增加复杂位姿估计。

### 5.3 输入、输出与模块接口

**输入：** RGB 或 RGB-D、相机内外参、各帧时间戳、机器人关节状态、本体位姿、目标类别或语言描述，以及可选 CAD、参考图像、抓取模板。头部安装相机的外参会随颈部、腰部关节变化，应通过运动学链计算到机器人基座或操作参考系的变换。

**输出：** 目标 ID、目标坐标系、时间戳、三维交互点、法向或完整位姿、候选集合、质量分数、有效期、可见性与失败原因。若输出协方差，应说明估计与验证方法；普通网络置信度不能直接当成米或角度意义上的不确定度。

**接口约定：** 统一长度单位、旋转表示、坐标系命名与法向朝向。区分“当前观测到的目标位姿”和“控制器需要达到的末端位姿”；后者还需结合工具中心点、夹爪几何与预抓取偏移。对过期结果提供明确失效标记。

### 5.4 推荐技术流程与算法取舍

```text
相机/关节状态同步 → 目标检测或分割 → 深度质量筛选
→ 交互区域几何估计或物体位姿估计 → 时序跟踪与质量检查
→ 转换到操作坐标系 → 候选可达性/碰撞检查
→ 输出目标 → 执行后重新观测并确认状态
```

按钮首版可以采用“分割区域＋有效深度＋局部平面拟合”，以按压区域中心生成点、以平面估计法向；保留深度离群值、边缘混合像素和有效点比例检查。对小按钮，背景墙面法向可能更稳，但按钮表面高度不能直接用背景替代，需考虑凸起距离与末端允许误差。

规则物体可先评估几何拟合或已知关键点加位姿求解；丰富纹理、复杂形状或姿态变化较大时，再比较学习方法。FoundationPose 可以作为新物体位姿估计和跟踪基线，但其官方设定需要给定 CAD，或采集少量参考图像；不能把它描述为“仅输入任意单张图片即可无条件定位所有物体”。[FoundationPose 官方项目](https://nvlabs.github.io/FoundationPose/)

位姿跟踪要有重新初始化条件：目标长时遮挡、分割失效、重投影不一致或残差升高时，不应无限沿用上一帧。对有旋转对称性的对象，评估应允许等价姿态；若任务依赖纹理或按钮朝向，则应进一步判断这些对称性是否仍成立。

### 5.5 人形机器人上的关键难点

1. **位姿变化和同步。** 身体、头部、手臂同时运动时，图像与关节状态错位会造成目标漂移；首先排查时间戳与插值，再考虑换模型。
2. **标定误差累积。** 图像点误差、深度偏差、手眼标定、运动学误差、末端工具偏移共同影响接触位置。需要分项测量误差预算。
3. **操作遮挡。** 手指靠近时容易挡住关键区域，腕部相机也可能看不到完整物体。需设计视角切换与低置信度处理。
4. **可执行性。** 位姿准确不代表机械臂可达、不碰撞、夹爪能夹稳或全身保持平衡。感知、规划、控制的失败应分别归因。
5. **反光与透明。** 深度缺失时不能仅靠补全图宣称获得可靠毫米级定位，应验证误差并保留拒识路径。

### 5.6 数据采集、标注与划分

按对象实例、距离、俯仰角、光照、遮挡比例、机器人姿态和相机组合建立采集矩阵。标注目标框或掩码、交互区域、三维点与法向、对象位姿、可见性、深度质量和执行结果；并非每一类标签都需要首版具备。

位姿真值可以来自测量夹具、校准后的标记系统或外部测量设备，但要记录真值自身误差。如果用标记得到真值，应在测试时避免算法依赖标记，并检查标记是否改变检测难度。训练测试按物体实例、场景或独立采集批次分组；同一次接近过程的相邻帧不能拆到两侧。对“新物体泛化”单独留出未参与调参与训练的对象。

### 5.7 离线指标与真机指标

| 层次 | 建议指标 | 必须一起说明的条件 |
|---|---|---|
| 交互点 | 位置误差中位数、P95；法向角误差 | 距离范围、目标尺寸、有效真值数量；拒绝输出比例 |
| 完整位姿 | 平移/旋转误差及任务允许范围内通过率 | 对称物体处理、实例/类别设置、CAD 或参考条件 |
| 时序 | 静止目标坐标抖动、丢失时长、重定位时延 | 机器人姿态、移动速度、遮挡时长 |
| 部署 | 全链路时延 P50/P95、过期输出率 | 从传感器采集到接口发布；设备与并行负载 |
| 真机 | 首次操作成功率、允许重试后的成功率、平均重试次数 | 总尝试次数、对象/姿态分布、超时规则、人工介入规则 |

“有效定位帧中误差很低”可能同时存在大量无输出帧，因此误差与覆盖率必须成对报告。真机成功率的分母应包括符合预先任务条件的全部尝试，不能只统计“感知成功后挑出的样本”。操作成功需要定义，例如按钮功能状态确实改变，或物体被抓起并保持指定时间，不能只依据机械臂轨迹执行结束。

### 5.8 对比实验、消融与失败案例

基线可设为单帧 RGB-D 几何定位或现成位姿模型。分别比较：无/有时序融合、头部单相机/增加腕部视角、无/有深度质量门控、旧/新标定、无/有结果确认。固定对象和初始摆放条件，交错执行方案，减少测试顺序造成的偏差。

建立失败表：按钮框正确但中心落在边缘；法向符号反向；相机坐标正确而工具中心点偏移；目标对称导致姿态翻转；手臂遮挡后跟踪锁到背景；定位准确但末端路径不可达。每类记录传感器原始数据、标定版本、模型版本和控制反馈，才能将算法改善对应到系统收益。

### 5.9 阶段交付与协作边界

第一阶段交付可回放的数据、坐标检查脚本和单对象基线；第二阶段交付交互点接口、拒识条件及离线误差报告；第三阶段与操作团队完成定量真机测试；第四阶段根据主要失败原因扩展对象或视角。阶段长短由设备可用性和联调效率决定。

你适合负责目标识别、三维估计、融合跟踪、质量评估、结果确认和数据评测。规划团队负责可达性、碰撞检查与轨迹生成；控制团队负责接触执行、顺应控制及全身稳定。共同定义数据接口和失败归因，避免所有操作失败都被算作感知问题。

### 5.10 面试切入点与真实简历模板

面试可准备：为什么按钮不做完整 6D？怎样区分时间同步问题与标定误差？目标对称性如何处理？位姿误差阈值如何由夹爪容差反推？定位改善为何没有带来操作成功率改善？发生遮挡时怎样决定继续跟踪还是重定位？

> 负责【机器人平台】面向【按钮/把手/工具】的操作感知，基于【真实输入】实现【交互点与法向/6D 位姿】估计及【实际完成的质量门控或跟踪方法】，针对【具体失败问题】完成【具体改进】；在【对象数、姿态与距离范围、尝试次数】下，将【位置误差/首次操作成功率】由【实测 A】改善至【实测 B】，部署全链路 P95 时延为【实测值】。本人负责【边界】，与【团队】完成真机验证。

只有完成位姿模块时，就写模块指标；与操作团队共同完成的系统成绩可写“联合验证”，不要把控制、抓取规划等未承担工作归入个人成果。

## 6. 方向四：动态环境感知与三维目标跟踪

### 6.1 业务问题与项目边界

巡检机器人可能经过有人走动的走廊、推车经过的厂房、临时搬运物体的区域。单帧检测可以输出“这里有一个人”，导航通常还需要知道目标位置、运动方向、速度、占据范围、观测是否新鲜，以及目标短时被遮挡后还能否维持一致的轨迹。

本项目建议承担动态目标感知和预测信息输出，与导航团队共同验证。绕行动作、速度选择和全身稳定控制仍需由对应模块处理。轨迹预测表达一定条件下的估计及其不确定性，不能作为对人的运动行为的保证。

**最小版本：** 单相机配合深度或点云，在一个走廊场景对行人和推车做三维跟踪，处理短时遮挡，并输出位置、速度、置信度和动态障碍层。先用常速度运动模型建立可解释基线。

**进阶版本：** 多相机交接、类别未知的运动物体发现、相似目标交叉、静止与运动状态切换、考虑不确定性的短期轨迹分布，以及自运动较大条件下的稳定跟踪。只有现有数据表明简单预测存在明显瓶颈时，再增加学习式预测。

### 6.2 输入、输出与接口约定

| 项目 | 建议内容 | 需要注意 |
|---|---|---|
| 视觉输入 | RGB 图像、内参、曝光时间、采集时间戳 | 运动模糊与滚动快门会影响框和外观特征 |
| 几何输入 | 对齐深度或点云、有效性掩码 | 框内背景点会污染目标中心与尺寸 |
| 自身状态 | 指定时刻的相机／本体位姿及质量信息 | 不用图像发布时刻的姿态替代采集时刻姿态 |
| 单轨迹输出 | ID、类别、位置、速度、尺寸或占据轮廓、协方差、观测时间 | ID 只保证约定空间和时间范围内的一致性 |
| 生命周期输出 | tentative、confirmed、lost 等状态及最近观测时刻 | 区分当前被看见和仅通过预测维持 |
| 地图输出 | 动态占据层、更新时间、来源轨迹 ID | 从静态地图剔除动态物体后，仍要保留其当前障碍信息 |

必须明确坐标系：在连续局部里程计坐标系中估计目标运动，再转换给消费者；如果使用会重定位跳变的全局地图坐标系，需处理跳变或重置状态，避免把地图校正当成目标突然加速。

### 6.3 推荐技术链路与算法取舍

1. **输入校验与对齐。** 校验时间差、深度有效比例和机器人位姿状态，异常数据标记为低质量而非直接吞掉。
2. **检测或实例分割。** 优先复用已有模型。对背景干扰严重、细长推车等对象，评估分割是否比框内深度统计有实际收益。
3. **目标几何恢复。** 使用实例区域的有效深度、点云聚类或多帧几何，估计三维中心与占据范围。保留遮挡情况下尺寸不完整的标记。
4. **自运动补偿。** 将不同帧观测变换到同一连续坐标系；头部转动与躯干运动应进入完整变换链。
5. **预测与关联。** 以滤波预测和位置门限建立基线，再结合图像重叠、深度、尺寸、类别和外观关联。各项的权重应随观测质量调整。
6. **轨迹管理。** 控制轨迹建立、确认、遮挡维持、重识别与删除条件。遮挡时间增加时扩大不确定性，不无限维持旧位置。
7. **动静状态与地图更新。** 使用持续证据判断运动状态；人站住后仍可能再次移动，不能简单永久并入静态背景。
8. **输出短时预测。** 给导航提供预测轨迹和置信区间或占据包络，标注预测范围和有效时间。

先定位瓶颈再改模型。例如：检测召回不足需要改数据或检测；检测稳定但 ID 频繁切换需要改关联；世界坐标中所有目标同时移动可能是自运动补偿问题；预测速度尖峰可能源自时间戳错误或深度跳变。

NVIDIA 的 nvblox 技术文档给出了将人员或动态对象与静态重建分离的实例，并指出基于空间变化的动态检测依赖位姿精度。可以学习其分层思路，但需要确认所用版本、接口和传感器组合的支持范围。[nvblox 动态重建技术说明](https://nvidia-isaac-ros.github.io/v/release-3.1/concepts/scene_reconstruction/nvblox/technical_details.html)

### 6.4 人形平台上值得做深的难点

- **视野变化快。** 机器人转头会导致目标瞬间离开相机，视野外与遮挡要区分；看不到时应保留观测年龄，而不是输出看似新鲜的预测结果。
- **身体遮挡。** 摆臂可能挡住近处行人，剔除本体像素时也不能误删紧邻身体的外部障碍。
- **近处对象几何不完整。** 行人的脚和推车底部可能在近距盲区内，单个可见中心不代表完整占据。
- **自身运动与目标运动耦合。** 小量位姿误差就可能把远处静止目标判断成运动，需要按距离与姿态质量调节速度判定。
- **动态地图残留。** 人离开后旧占据持续存在，会让导航长期绕行；清除过快则可能漏掉暂时遮挡的目标。
- **人体关节运动。** 手臂摆动不等于整个人沿同样速度移动，目标中心估计和区域占据应避免被局部运动主导。

### 6.5 数据采集与标注方案

按完整序列采集以下组合：机器人静止／行走／转头，单人／多人，相向／横穿／同向跟随，无／短／长遮挡，行人站住再出发，推车停放后启动，弱光与反光地面。不要仅采集目标持续可见的正面视频。

标注至少包括目标身份、每帧框或实例区域、可见程度、类别和关键事件。三维位置真值可在一部分受控序列中通过外部测量或高质量参考系统建立，并记录参考误差。不能把模型自身估计的位置当作独立三维真值。

训练、验证和测试按录制序列、日期、路线或参与对象划分。若测试相同人的不同视频，应写清评估的是场景迁移还是身份泛化。学习式预测还需要避免同一段轨迹被切成重叠窗口后跨集合出现。

### 6.6 评测指标及统计口径

| 指标 | 推荐统计口径 | 解释用途 |
|---|---|---|
| 检测召回 | 在约定距离、可见度和匹配阈值下，被正确检出的可评测目标数／全部可评测目标数 | 定位上游漏检 |
| ID 一致性 | ID 切换次数，同时报告序列时长和有效目标数；有规范标注时补充 IDF1 或 HOTA | 评估关联，不用检测 mAP 代替 |
| 三维位置误差 | 正确关联且有独立真值的时刻上统计误差中位数与 P95，并报告覆盖率 | 防止只对容易样本报精度 |
| 速度误差 | 对有可靠轨迹真值的区间统计，说明真值速度的计算或平滑方法 | 判断动态信息是否能使用 |
| 遮挡恢复率 | 在规定遮挡时长且目标重新可见的事件中，按规定时间恢复正确 ID 的事件比例 | 检查恢复能力 |
| 地图残影时间 | 目标离开原区域到该处旧动态占据不再阻塞的耗时，按遮挡和真正离开分组 | 平衡清除与维持 |
| 提前感知时间 | 目标进入预定义冲突区域前，被稳定检出或跟踪的时间差 | 关联任务反应窗口 |
| 真机干预率 | 人工干预次数／完整路线次数，或每公里次数，分别列出感知、规划、控制原因 | 观察系统效果 |

HOTA 将检测、关联和定位质量纳入统一评价，可用于补充分析，但需要按相应实现准备标注并明确匹配定义，不能直接把二维默认阈值用于三维任务。[HOTA 论文](https://arxiv.org/abs/2009.07736)

### 6.7 对比实验与失败分析

至少比较：单帧检测与跟踪；有无自运动补偿；二维关联与加入三维位置；是否使用外观；固定门限与质量相关门限；不同轨迹维持时间；静态地图直接融合与动态分层。使用同一批回放数据和固定基线配置。

关键失败案例应保留同步可视化：原始图像、深度、位姿、检测结果、关联候选、滤波残差与轨迹状态。出现 ID 切换时，回答是两个外观相似目标交叉、三维估计错位，还是预测窗口过大。

建议先进行离线回放和受控低速联合测试，再扩大行走速度与目标数量。真机对比固定导航与运控版本，避免多个模块同时变化后无法归因。

### 6.8 阶段交付、依赖与缩减方案

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| 基线 | 单场景检测＋三维位置＋常速度跟踪；序列评测脚本 | 坐标和时间戳正确，失败可复现 |
| 稳定性 | 自运动补偿、轨迹生命周期、遮挡恢复、速度不确定性 | 在独立序列中有可量化改进 |
| 地图对接 | 动态图层、有效期、消费者处理约定 | 导航能区分实时观测和预测 |
| 联合验证 | 固定路线、多次测试、干预归因和资源统计 | 感知改进能解释系统变化 |

缺少可靠三维真值时，可先报告二维跟踪和受控位置测试；缺少导航接口时，交付离线及在线感知模块，不写成已经实现自主动态避障。只有一个相机时，先研究视野内与短时遮挡，暂不承诺跨相机持续身份追踪。

### 6.9 简历表达与面试准备

**项目名示例：** 人形机器人动态环境三维感知与目标跟踪。

**真实结果填入后的表述模板：**

> 负责巡检场景动态目标感知，结合【实际传感器】与机器人位姿实现【三维关联、自运动补偿或其他实际方法】，输出带观测时间与不确定性的目标轨迹及动态障碍层；在【场景、速度、目标数、序列规模】下，将【位置误差／ID 切换／遮挡恢复指标】由【A】改善为【B】，并与导航团队完成【实际测试范围】的联合验证。

面试应能解释：为什么某个关联条件最有效；如何区分自运动误差与真实目标运动；轨迹保留多久以及为什么；速度真值怎样获得；动态物体从静态地图剔除后如何继续表示；哪些联合测试失败实际上来自规划或控制。

## 7. 方向五：主动巡检与异常复核

### 7.1 项目定位与业务例子

建议项目名：**面向人形机器人巡检的观测质量评估、主动视点选择与异常复核**。

机器人到达设备附近后，固定角度照片可能存在反光、字太小、遮挡或运动模糊。项目目标是让机器人判断当前证据是否足够，选择一次有价值的补充观察，并给出有证据的巡检结果。例如发现仪表读数疑似越界后，先确认设备 ID，再调整头部角度消除反光、采集清晰近景、复读仪表，最后输出“确认异常／确认正常／证据不足”。

这条路线能直接升级现有巡检业务。即使只有 RGB 或 RGB-D，也可以先做完整项目；热成像和音频应由真实任务需求与硬件条件决定，不需要为了“多模态”把所有传感器都接上。

### 7.2 可拆分的具体任务

| 子任务 | 可落地的问题 | 主要产出 |
|---|---|---|
| 观测质量评估 | 当前图像能否可靠读表、辨认灯色或确认设备身份 | 可用／不可用及原因、质量分数 |
| 下一视点选择（Next Best View） | 抬头、转头、侧移或靠近，哪种动作最可能补足证据 | 候选视点、预期收益和动作成本 |
| 跨视角与跨次身份保持 | 这次拍到的柜体是否就是上次巡检的同一台 | 设备 ID、关联证据、身份不确定性 |
| 异常检测与复核 | 是真实变化、读数错误，还是观察条件改变 | 异常类型、证据、复核状态 |
| 结果归档 | 以后是否能够重放并解释这一次判断 | 原始观测、位姿、阈值版本、设备工况与时间 |

### 7.3 输入、输出与建议状态机

输入包括设备任务清单、设备空间位置与历史记录、RGB／深度、相机位姿、可用头部姿态范围、导航可达区域，以及按需接入的热成像原始测量数据或音频。输出应包含设备身份、观测有效性、测量值或状态、异常证据、下一观察动作和终止原因。

建议状态机：

```text
定位设备 → 确认身份 → 采集观测 → 判断观测质量
                           ├─ 质量不足 → 生成候选视点 → 执行并重新观测
                           └─ 质量足够 → 检测／测量 → 正常：完成
                                                  └─ 疑似异常：复核
复核 → 确认异常／确认正常／仍不可判定
```

设置最大观察次数、任务时间和可移动范围，记录每次行动的原因。达到预算仍无法确认时，应保留“未判定”状态；不能因为流程必须结束就把它标成正常。

### 7.4 技术流程与选择依据

1. **设备身份确认。** 组合地图位置、编号、外观、柜体布局和历史观测。编号不可见时保留候选集合；设备经过维修或更换时需要版本与台账更新。
2. **任务相关的质量判断。** 读数字关注字符尺寸、清晰度、曝光、倾斜与反光；判断指示灯关注灯区可见性和曝光；比较缺损关注同一区域是否对齐。图像“看起来清晰”不等于足以完成具体任务。
3. **产生可执行视点。** 先从头部转动和已经验证可达的站立位姿中生成少量候选。对每个候选估计目标可见比例、目标尺度、观察角度、预期遮挡与移动代价。
4. **视点排序。** 最小版本可采用规则与加权评分，如“预计能改善的质量－移动时间代价－额外动作代价”，并用日志解释选择。需要比较不同量纲前，应做适当归一化。
5. **获取新证据。** 在姿态稳定后采集，并检查新观测是否实际改善质量。改善不足时更新候选排序，防止在同样无效的角度间反复切换。
6. **异常复核。** 结合独立视角、重复测量、历史基线和工况验证异常。相邻视频帧高度相关，不能把连续十帧同样误读当作十份独立证据。
7. **记录结论与证据。** 保存异常位置、测量值、设备 ID、采集时间、复核动作和适用阈值；报告文字可由模型整理，但检测结论应能追溯至实际观测。

“下一最佳视点”可以是有限候选中的最佳选择，不必一开始就做复杂的强化学习。若要进一步学习视点评分，应收集“当前视点—候选动作—新观测质量—任务结果”的数据；只记录已经执行的动作，无法直接知道所有未执行动作的真实收益，需要另外安排候选视点采集或受控实验。

### 7.5 模态选择与真实边界

- **RGB／RGB-D：** 适合指示灯、数字仪表、指针表、可见缺损、明显渗漏外观和设备身份；深度可辅助视距、角度与避障，但不能自动解决反光读数问题。
- **热成像：** 适合有明确测温需求且硬件具备相应能力的任务。要区分伪彩图与可用于测温的辐射数据，记录标定、材料发射率、反射环境等条件。反光金属可能反射周围热源，不能仅凭图中“更红”断言设备真实温度更高；具体测温配置应按设备说明和现场验证确定。[FLIR 关于发射率与反射温度的说明](https://www.flir.com/discover/professional-tools/how-does-emissivity-affect-thermal-imaging/)
- **音频：** 可在固定设备类型与工况下检测偏离正常声音的片段。必须控制或记录机器人电机声、脚步、距离、混响和其他设备干扰。异常声检测不自动等于明确故障类型识别；缺乏真实故障标签时，可以输出待复核线索，不能声称能诊断任意故障。
- **融合策略：** 第一版适合在设备实例与时间窗口上做结果级融合，各模态保留质量与缺失标志。验证单模态基线后，再判断是否有必要做特征级或时序联合模型；不同模态相关误差可能并存，简单投票不能保证正确。

### 7.6 最小版本与进阶路线

最小版本可以只选择一种任务，例如数字仪表读数：固定路线到达设备，判断是否能读，尝试有限的头部视角或侧移观察，复读并输出带证据的结果。第一轮重点证明“主动补拍”相对于“固定视角拍照”有稳定收益。

工程进阶加入跨次设备身份、历史读数对齐、不同工况阈值、观察预算与失败恢复。算法进阶围绕任务质量预测、视点收益预测、跨视角一致性或有限标注的异常检测选择一个重点。只有业务上确有无法通过 RGB 完成的任务时，再扩展热成像或音频。

### 7.7 人形机器人难点与协作依赖

人形机器人可以利用头部和躯干改变视点，但动作过程中也可能产生更强抖动，实际站立状态与计划姿态存在偏差。需要与运控约定“已稳定可采集”的条件，并在感知端继续检查图像质量。身体动作会改变相机位姿，跨视角配准必须使用对应时刻的运动学与定位数据。

主动观察的候选动作应受已有可达性和动作接口约束。你可以负责“什么证据缺失、哪里更可能看清”，导航与运控负责路径、站立和具体动作执行。若真机无法自主侧移，先只做头部视角选择，照样能够形成完整的感知闭环。

### 7.8 数据与标注方案

数据单位应是一次完整的设备检查事件，包含初始视角、补拍轨迹、每个视角的图像与位姿、质量原因、设备身份、真实状态和最终人工确认。质量标签最好与具体任务挂钩：能否读出正确值、能否识别灯态，而不是仅主观评价画面美观。

按设备实例、采集日期、工况和场地划分训练测试。真实异常稀少时，可使用正常历史建立偏离检测，并通过可控场景变化测试流程；合成异常、摆拍异常和真实运行故障应分别统计，不能混合后宣传实际故障检出率。对温度或仪表数值使用可信参考测量，并记录其误差和采集时间差。

### 7.9 评测指标与对比实验

| 指标 | 定义与注意事项 |
|---|---|
| 可判定率 | 在全部检查任务中，系统能提供满足预设证据要求的结论的比例；未判定任务单独保留 |
| 主动观察恢复率 | 初始观测不可用的任务中，经有限次数主动观察后得到正确有效结果的比例 |
| 读数误差／状态准确率 | 在有参考真值的有效任务上统计数值误差或类别正确率，同时报告覆盖的任务比例 |
| 异常召回率与误报率 | 按独立异常事件统计检出率；按正常检查次数或设备运行小时统计误报，明确单位 |
| 复核后的错误确认率 | 误确认异常数／全部确认异常数；另报最终被错误确认正常的真实异常任务数／全部真实异常任务数，并单列未判定比例 |
| 设备身份关联错误率 | 跨次检查中关联到错误设备的次数／全部待关联检查次数 |
| 效率与成本 | 每台设备平均及 P95 检查时间、补拍次数、额外移动距离、超时与人工介入比例 |

对比固定视点单次检查、固定多视点检查、质量驱动的主动检查，并尽量匹配时间或观察次数预算。消融可移除任务相关质量、视点排序、设备身份确认、复核机制；多模态场景再增加单模态与缺失模态测试。不要只比较准确率而忽略多走了多少路、耗费了多少时间。

### 7.10 失败案例、交付与简历

重点积累：读表反光使所有视点都不可靠；移到近处后目标反而超出视野；设备编号遮挡导致检查错对象；正常工况变化被判异常；热反射被当作温升；机器人自身噪声触发音频异常；反复补拍仍无效。对应输出应包含身份待确认、测量无效、视点耗尽或证据冲突等具体原因。

阶段交付可以依次是：固定视点检查基线与数据集；任务质量评估器；有限候选视点执行接口；异常复核与设备历史库；相同预算下的真机对比报告。最好保留一组初始失败、自动补拍、最终正确确认的视频和完整日志，方便展示业务收益和技术过程。

面试准备：怎样定义“看清了”？为什么选这个视点？补拍收益如何评估？连续帧一致但全部读错怎么办？设备工况变化与异常如何区分？新增模态提供了什么独立信息？失去一种模态时系统如何输出？

真实简历模板：

> 负责人形机器人【具体设备与巡检任务】的主动视觉巡检，设计【质量指标／视点评分／身份关联／复核机制】，在【真实设备数量、场景和任务次数】的独立测试中，相比【固定视点等真实基线】将初始不可用观测的恢复率提升至【实测值】，在每次检查增加【实测时间／动作成本】的条件下，将【事件级误报或漏检指标】由【基线】改善至【结果】；支持输出设备身份、原始证据与未判定原因。

## 8. 方向六：视觉与力／触觉融合的接触状态估计和失败检测

### 8.1 项目要解决什么业务问题

机器人靠视觉完成接近后，仍可能抓空、夹住边缘、搬运途中滑移、插接时顶住孔口，或者接触后未完成动作。这个方向让系统回答“是否接触、是否稳定、是否失败、是否需要重新观测或重试”，适合已有抓放、按钮或插接任务的团队。

这是偏操作感知的项目，需要可靠的传感器同步、动作执行和重复试验条件。对目前主要做移动感知的你，可把它作为第二阶段拓展。若公司没有可用操作平台或真实力/触觉传感器，先做视觉与关节状态的操作结果检测，比在缺少数据时承诺高精度滑移感知更实际。

### 8.2 先澄清三类传感器能力

| 可用硬件 | 可以尝试的任务 | 需要承认的局限 |
|---|---|---|
| 夹爪位置、电流、关节力矩估计 | 抓空、夹持异常、粗接触事件 | 信号包含传动摩擦、重力和动态效应；不等于指尖接触力，更不等于空间触觉图 |
| 腕部六维力/力矩 | 外力接触、异常受力、插接阶段辅助判断 | 测量是合力和合力矩；通常难以独立确定每根手指的接触分布 |
| 指尖压力阵列或视觉触觉 | 接触区域、局部形变、剪切变化与滑移线索 | 存在覆盖范围、饱和、材料磨损、标定和传感器个体差异 |

例如 DIGIT 使用图像感知接触几何，结合相应方法可估计法向力、利用标记估计剪切力；这些能力需要对应传感器和处理方法，不能从普通 RGB 摄像头或电机电流直接等同获得。[DIGIT 官方介绍](https://digit.ml/digit.html)

### 8.3 MVP、进阶版本与状态定义

**MVP 建议：** 固定夹爪、少量刚性物体和稳定抓放轨迹，融合外部视觉与夹爪位置/力反馈，区分“抓空”“已夹持”“搬运中丢失”“完成放置”。先让失败检测与一次受控重试闭环工作，再增加滑移识别。

必须区分以下状态，否则标签会相互污染：

- **抓空：** 闭合后未形成有效夹持，通常是一次抓取尝试的结果。
- **接触：** 手与物体接触的事件或状态，不意味着已经抓稳。
- **稳定夹持：** 在当前观测时间窗和指定载荷条件下，物体相对夹爪没有超出允许范围的运动。
- **滑移：** 接触持续时发生相对切向运动；局部初始滑移与物体整体滑动需分别定义。
- **插接状态：** 未接触、孔口接触、对准进入、卡滞、到位等，需根据任务几何、运动和外力证据共同区分。

进阶可以扩展到未见物体、视野遮挡、移动身体下的受力变化，以及插接卡滞识别。不要首版同时覆盖脆弱物体、布料、灵巧手内操作和精密插装，它们的接触机制与数据需求不同。

### 8.4 输入、输出与技术流程

**输入：** 外部或腕部 RGB/RGB-D、触觉原始图像或阵列、力/力矩、夹爪位置与速度、关节状态、机器人身体姿态、动作阶段、命令与实际反馈；每种模态附带时间戳和有效标记。

**输出：** 接触状态、滑移/卡滞/抓空事件、置信度、事件起始时间、相关传感器质量、是否需要重新观测的建议。感知输出状态与依据，执行器如何增力、回退或重试由控制与任务模块决定。

```text
多模态采集与对时 → 零点/偏置及有效性处理
→ 视觉目标运动、触觉形变、力变化、夹爪状态特征
→ 因果时序融合 → 接触状态与失败事件判定
→ 去抖/迟滞/超时处理 → 上层策略响应 → 记录最终结果
```

先建规则或传统分类基线，例如按动作阶段组合夹爪闭合量、物体是否随手运动、力信号变化。数据足够后再比较轻量时序模型；简单后融合更易定位问题，特征级融合可能利用跨模态关联，但对同步和数据规模要求更高。推理只使用当前及历史数据，离线训练与评测不能无意读到未来帧。

### 8.5 人形场景的难点与算法取舍

身体晃动和手臂加减速会改变腕部受力，轻微外力不能直接从原始读数阈值判定；应明确零点、工具质量、重力与惯性影响的处理方式。电机电流中的传动摩擦也随速度、温度和姿态变化。模型可能学到动作速度而非接触状态，因此训练集要覆盖速度与负载变化。

视觉擅长观察全局物体位置，触觉接近接触本身，但覆盖区域有限；受力反映交互变化，却可能无法区分碰到目标还是环境。可以按动作阶段和传感器质量加权，保留“证据不足”状态。视觉被手遮住时不能自动认为触觉一定可靠，触觉饱和或脱落时也要显式降级。

滑移检测关注时序变化，采样率、同步偏差与处理延迟直接决定事件是否来得及响应。算法识别延迟、消息传输、控制周期和执行器响应应分别测量。检测出了滑移，并不意味着通过增大夹持力一定能恢复；还需考虑材料、抓取几何和允许接触力。

### 8.6 数据、标注与真值

按物体材质、重量、尺寸、夹持位置、闭合力、运动速度和传感器个体采集完整操作序列，同时覆盖稳定成功和常见失败。对每个事件标注开始/结束时间、状态类型、可见证据和不确定区间；动作阶段标签与成功结果标签分开保存。

滑移真值可通过独立相机追踪物体相对指尖运动、已标定装置或其他独立测量获得；注意物体整体运动与接触面局部滑移不是同一真值。没有足够观测手段时，先做“物体相对夹爪明显移动”的检测，不要把它宣传成微小初始滑移识别。插入到位也不能仅用力上升标注，应结合几何位置、行程或独立结果检测。

按完整试验、对象、采集日期或传感器划分数据，分别报告同对象新试验和未见对象表现。失败数据可以受控采集，但不要只生成夸张失败；生产中更常见的是短暂接触、边缘夹持和轻微卡滞。触觉仿真可辅助预训练和探索，真实材料、磨损与传感器差异仍需实机验证，不能声称合成数据天然保证迁移效果。

### 8.7 离线与真机评测

| 指标 | 正确定义及条件 |
|---|---|
| 事件召回率 | 被正确检测的独立滑移/失败事件数 ÷ 真实事件总数；给出时间匹配容差 |
| 事件精确率 | 匹配真实事件的报警数 ÷ 总报警数；规定连续报警如何合并 |
| 误报频率 | 每小时稳定操作或每 100 次成功操作的误报数量；避免只报帧准确率 |
| 检测时延 | 报警时刻减事件真值起始时刻；报告中位数/P95及漏检数量 |
| 状态识别 | 各类召回率、混淆矩阵和宏平均指标；单列抓空、稳定夹持与滑移 |
| 完整任务 | 首次成功率、重试后成功率、物体掉落率、任务耗时；均给出全部尝试数 |
| 恢复效果 | 被触发的恢复中成功次数 ÷ 恢复触发次数，同时报告误触发与总体任务收益 |

测试时固定或记录物体重量、表面状态、动作速度、光照、夹爪型号和传感器校准版本。漏检不能从时延统计里消失：时延只在检出事件上计算时，要明确这一条件。类别不平衡明显时，长时间“无事件”会让帧准确率虚高，因此优先看事件指标和每次操作的结果。

### 8.8 对比、消融与失败诊断

至少比较视觉单模态、力/触觉单模态、简单规则融合和拟议融合方法。进一步移除动作阶段、移除时序窗口、改变同步误差、模拟短时模态缺失，判断提升究竟来自新模态、历史信息还是数据规模。新增模型与基线应使用相同测试集和可比较的参数调优流程。

典型失败包括：手臂加速被误认为外部接触；物体随身体一起运动被判成滑移；夹爪碰到桌面却被认作抓稳；传感器温漂导致接触阈值漂移；插入时侧向卡滞被判为到位；掉落后视觉重新看到物体却没有正确更新状态。为每类失败保留同步曲线、视频和动作命令，优先排查信号质量与标注，再调整模型。

### 8.9 阶段交付与团队依赖

第一阶段交付硬件能力清单、对时与零点检查、可回放多模态数据；第二阶段交付明确状态定义和规则基线；第三阶段交付事件模型、跨对象评测与延迟分析；第四阶段在控制团队支持下验证失败重试，并与原系统比较总体成功率。

你可以负责采集、同步、特征与融合、状态估计、模型部署和评测；控制团队负责执行响应、接触力约束和恢复动作。若只有电流和关节状态，项目名称应如实写“视觉与本体状态融合的抓取失败检测”，不要写成“高分辨率视触觉融合”。

### 8.10 面试切入点与真实简历模板

准备回答：为什么帧准确率不能说明滑移检测好？事件真值怎样得到？如何处理动作惯性与接触力混淆？视觉失效时融合是否仍可靠？模型用了未来信息吗？检测延迟与控制恢复窗口如何匹配？跨物体与跨触觉传感器性能差多少？恢复功能是否增加无谓重试？

> 负责【平台与操作任务】的【视觉＋实际力/触觉/本体状态】融合感知，构建【真实事件定义】与【完整试验数、物体范围】数据集，实现【实际融合方法】及因果在线部署；在【独立测试条件】下，失败事件召回率为【实测值】，误报为【每小时/每百次操作实测值】，检测 P95 时延为【实测值】；与控制团队联合接入【实际恢复动作】，使【全部测试尝试上的指标】从【A】改善至【B】。

若没有完成控制恢复，写清“提供事件检测接口并验证检测性能”；有真实恢复闭环后，再补充系统收益。能够解释传感器局限、真值获取和失败归因，本身就是这个项目的重要专业价值。

## 9. 方向七：将现有跑道线检测升级为奔跑几何感知与时序跟踪

### 9.1 项目定位：让跑道检测成为可供运动闭环使用的状态估计

已有跑道项目很适合做短期可交付成果。原始检测任务回答“图像中哪些像素是跑道线”，升级后的任务回答“机器人相对目标跑道在哪里、朝向偏了多少、前方如何弯曲、当前估计是否可靠”。核心输出是带时间戳、坐标定义和置信度的跑道相对几何状态。

第一步要确认比赛或内部测试的实际要求：跟随跑道中心、保持指定侧距离、限制身体不越界，还是限制足部不踩线。这些要求决定中心线、机体投影和足部位置的接口，但最终步态控制、重心稳定和转向执行仍应由相应团队负责。你可以负责误差估计和失效状态，与运控共同完成闭环验证。

### 9.2 最小版本与进阶版本

**最小可用版本：** 在已知单一跑道、固定相机和低速条件下提取左右边界，估计地面坐标中的横向偏差与航向偏差；记录成功和失败片段，打通给运控的状态接口。跑道宽度可以使用经测量的场景先验，但要明确该先验的适用范围。

**第二阶段：** 扩展到弯道、不同速度、奔跑引起的相机姿态变化、短时遮挡和单侧边界可见，增加时序跟踪、曲率估计及置信度。

**第三阶段：** 处理多条平行线、起终点横线、阴影、相似地面纹理、逆光和线条磨损；加入丢线恢复状态机与严格评测。若实际跑道有明显起伏，需引入地面估计或深度信息，不能继续默认固定平面投影始终成立。

### 9.3 输入和输出设计

| 类别 | 建议内容 | 需要说明的问题 |
|---|---|---|
| 图像输入 | RGB 图像、内参、畸变参数、曝光时间戳 | 模糊与曝光变化是重要质量变量 |
| 几何状态输入 | 图像时刻相机相对地面的位姿或地面方程（含相机高度）、相机到机体的变换、关节状态及所需里程计 | IMU 姿态不能单独恢复奔跑上下起伏造成的相机高度变化；头部可转动时不能只用固定外参 |
| 场景先验 | 目标跑道编号或初始选择、宽度范围、行进方向 | 对多条平行线进行身份关联 |
| 边界输出 | 左右边界曲线、有效距离区间、观测／推断标记 | 单侧推断的边界应与实测边界区分 |
| 几何状态 | 横向偏差 `e_y`、航向偏差 `e_psi`、曲率 `kappa` 或中心线点列 | 明确参考点、正负方向、米与弧度 |
| 质量状态 | 拟合残差、观测覆盖率、估计协方差或校准后的质量分数、数据年龄 | 未校准的网络分数不要直接解释为成功概率 |
| 跟踪状态 | 正常、单侧退化、短时预测、丢失、重捕获 | 对应下游可执行的处理约定 |

建议把偏差定义在固定机体参考点或指定地面投影点上，弯道同时输出前方若干距离处的中心线。单一“航向角”不足以描述整个弯道；参考距离变化也会改变偏差含义，必须与运控保持一致。

### 9.4 算法流程：先建立几何基线，再按失败类型增加复杂度

1. **图像质量与畸变处理。** 检查曝光、模糊、有效视域和时间戳。低质量帧可以降低更新权重，但应统计被拒绝帧的比例，不能靠拒绝困难帧掩盖问题。
2. **候选线提取。** 从颜色阈值、边缘和几何约束建立低成本基线；若颜色与光照变化明显，再训练线条分割或关键点模型。对同一数据集比较精度、延迟和维护成本，不预设深度模型一定更合适。
3. **地面坐标恢复。** 使用相机模型、观测时刻相机相对地面的位姿与地面假设进行投影，同时处理旋转和相机高度变化。高度可来自经过验证的状态估计或深度地面拟合；如果暂时采用固定高度，应明确适用范围并量化奔跑起伏带来的误差。相机运动补偿与非平面地面建模是不同问题。低视角远处投影更敏感，需要限制可靠距离并传播或估计不确定性。
4. **边界拟合与选择。** 使用稳健拟合剔除离群点，按有效视野选择直线、低阶曲线或分段表示。高阶拟合可能降低当前帧残差却造成远处曲率异常，应约束曲率连续性并限定外推距离。
5. **左右边界和跑道身份关联。** 结合宽度范围、左右关系、历史位置及前进方向排除邻道线和横线。单侧可见时可短时使用宽度先验推断中心，并提高不确定性，不能伪装成双侧稳定观测。
6. **时序预测与更新。** 利用相对运动把上一时刻几何转到当前坐标系，再与当前观测融合。先做自运动补偿，再平滑，避免把机器人实际横移和转向误当作检测噪声滤掉。
7. **质量门控和恢复。** 结合可见长度、残差、姿态质量和与预测的一致性判定输出是否可用；短时无观测只在约定范围内预测，超过时间或不确定性阈值进入丢失状态。

这里的多模态能力主要来自视觉、本体姿态及可选深度的有效融合；无需为了名称更丰富而加入没有作用的语音或大模型。

### 9.5 奔跑条件下的关键难点

- **强姿态扰动：** 固定鸟瞰变换在相机上下运动和俯仰变化时会把同一条线投影到不同位置，导致控制收到周期性虚假偏差。
- **运动模糊与滚动快门：** 需要结合实际相机成像方式和曝光设置分析；仅做跨帧平滑可能降低跳变，却增加延迟。
- **奔跑时序预算：** 更新率和端到端延迟都影响下游状态新鲜度；“模型 FPS 很高”不代表完整链路延迟足够低。
- **直道与弯道差异：** 直道模型在入弯时可能持续给出偏小曲率；弯道拟合又可能在短可见线段下不稳定。
- **丢线重捕获：** 遮挡后最近的一条线可能属于邻道。重捕获需要保持跑道身份，不能仅选择分数最高候选。
- **先验失效：** 跑道宽度变化、标线交叉或赛场布置变化会破坏固定约束；先验冲突要被检测并记录。

### 9.6 数据采集、标签与真值

按直道／入弯／弯道／出弯、速度档位、光照、阴影、线条磨损、姿态变化、可见边界数量和遮挡持续时间建立采样表。不要只保留顺利跑完的视频，应保存启动、加速、急转、失误、人工接管前后的完整片段。

图像标签可使用线条掩码或折线，并标记目标跑道身份、左右边界、有效可见范围和遮挡。闭环所需的米级几何误差需要独立参考：例如测量后的跑道几何结合外部定位、动捕或其他经过验证的参考轨迹。若暂时只有像素标签，可以评估图像几何与稳定性，但不能据此声称横向位置误差达到若干厘米。

避免用待评估算法自身的姿态或同一套投影结果直接生成全部“真值”，否则共享误差可能被隐藏。数据划分以整次跑步和采集批次为单位，至少保留未参与调参的整段跑步；如果需要证明跨场地能力，必须有独立场地测试。记录标注误差和参考定位可用范围。

### 9.7 离线、闭环与资源指标

| 指标 | 明确定义 | 报告条件 |
|---|---|---|
| 边界检测质量 | 按固定像素容差匹配边界点后的精确率和召回率，或固定定义的分割指标 | 分左右边界、远近区域与直／弯道 |
| 横向偏差误差 | 有独立参考的有效时刻上，估计偏差与参考偏差绝对差的均值、P95、最大值 | 同时报告有效输出时刻／应评估时刻 |
| 航向误差 | 估计航向偏差与参考值的角度差，使用一致的角度环绕处理 | 注明参考点和参考曲线切向定义 |
| 曲率误差 | 在具有可靠参考且长度充分的曲线区间比较估计曲率 | 区分直道、入弯和稳定弯道 |
| 连续丢线时长 | 每次进入无有效观测状态至有效观测恢复的时间，报告分布和最大值 | 区分完全丢失和单侧退化 |
| 重捕获正确率 | 遮挡后正确恢复目标跑道身份的次数／全部预定义遮挡事件次数 | 固定遮挡时长和运动条件分组 |
| 端到端延迟 | 几何状态发布时刻减去图像曝光参考时刻，统计 P50／P95／最大值 | 明确是否含传输、预处理和排队 |
| 越界事件频度 | 独立越界事件数／实际完成距离；另列至少发生一次越界的测试比例 | 明确身体、参考点或足部的越界定义 |
| 完成率 | 按协议无人工介入完成目标距离或圈数的有效尝试次数／总有效尝试次数 | 固定速度范围、路线、控制器和停止条件 |

所有因感知失效而中止的有效测试都应计入完成率分母；设备未启动等排除项需要预先定义。报告闭环提升时，同时给出控制器版本和是否重新调参，不能把控制器优化全部归因于感知。

### 9.8 消融、里程碑和团队依赖

建议基线为“单帧线提取＋固定投影＋简单拟合”，逐步比较动态姿态补偿、稳健边界拟合、跑道身份关联、自运动补偿后的时序融合、质量门控和恢复策略。用同一批序列观察每个模块对误差、有效覆盖率、延迟和丢线恢复的影响。若替换成学习式检测器，应先固定后处理，确认收益究竟来自检测器还是几何与跟踪。

里程碑可以划分为：① 明确闭环状态定义，建立记录与重放工具；② 输出直道和弯道几何基线，完成独立参考验证；③ 解决运动扰动与遮挡，给出逐项消融；④ 在批准的测试条件下开展速度分档真机验证，形成完整结果表。与运控共同确定异常状态对应的减速、保持短时预测或停止策略，实际策略由系统负责人批准并执行。

依赖主要是带可靠时间戳的姿态、清晰可用的相机图像、对照参考、运控接口和可重复的测试场地。相机安装位置、曝光和时间同步通常比更换一个更大的模型更值得先排查。

### 9.9 失败分析与面试表达

每个失败应能回答四件事：当时哪些输入退化；几何输出如何出错；质量模块为何没有及时识别；下游因此发生了什么。典型案例可以是“奔跑时偏差出现周期振荡”“入弯曲率响应滞后”“遮挡后误切到邻道”。配合图像、姿态、估计曲线、参考误差和发布延迟的同步时间轴，展示诊断过程。

面试重点包括：为什么像素分割提升没有带来闭环提升；如何选择前视距离；单侧线推断何时失效；滤波为何会增加转弯滞后；怎样证明位置误差改善来自算法而不是参考或控制器变化。能够解释一个错误方法为什么失败，也是项目深度的一部分。

简历模板：**“负责面向人形机器人奔跑的跑道几何感知与时序跟踪，融合【视觉与实际姿态输入】，实现【姿态补偿、边界关联、曲线拟合、丢线恢复中的真实贡献】，向运控输出【横向偏差、航向偏差及曲率等】；在【速度范围、直／弯道、测试次数或里程】下，【指标】由【A】改善至【B】，并与运控联合完成【实际闭环验证范围】。”** 如果你只负责感知，请使用“向运控提供状态”“与运控联合验证”等准确措辞。

## 10. 所有项目共用的感知工程底座

### 10.1 传感器、标定与坐标管理

建立一张传感器表，记录型号、分辨率、帧率、内参、畸变模型、安装位置、时间戳来源、数据接口、近距盲区和典型失效场景。记录实际配置，而不是只保存厂商标称参数。

坐标管理至少需要相机、IMU、本体参考系、头部、腕部、末端工具、连续里程计和全局地图之间的关系。可动关节两侧的变换应结合关节状态求取，不能把站立时标定到本体的一个固定矩阵用于所有头部姿态。

推荐约定 `T_A_B` 表示把 B 系下的点变换到 A 系。接口文档给出单位、右手系轴向、旋转表示及四元数分量顺序。三维点转换可统一描述为 `p_A = T_A_B · p_B`；具体实现时区分齐次坐标、方向向量和法向，不要把平移错误地作用到方向上。

每次机械安装、相机更换或末端工具变化后，记录标定版本并运行一致性检查。图像重投影误差、不同视角下固定目标的位置一致性、实测距离误差和实际接触偏差分别检查；某一个指标好不能替代整条几何链正确。

### 10.2 时间同步与数据新鲜度

至少区分：曝光或测量时间、数据到达时间、模型开始和结束时间、接口发布时间、下游消费时间。若不同设备的时间源不一致，应建立时间对应关系，并记录偏移与漂移的估计方法。

对于图像时间 `t_img`，使用该时刻对应的机器人状态进行变换。采样不同频率时要规定插值方法、最大等待时间和允许时间差；IMU 插值、关节插值与位姿插值的处理不能混为同一操作。

推荐同时记录：

- 输入对齐误差及其 P50／P95／最大值。
- 从传感器采集到发布的全链路延迟。
- 发布后到控制或规划消费的消息年龄。
- 丢帧率、排队长度、无效数据率和超时次数。

帧率高不代表延迟低。系统可能持续输出高帧率的旧数据，因此要限制排队并明确丢旧帧策略。多帧融合能降低抖动，也可能增加滞后，应联合测量精度、延迟和动态响应。

### 10.3 观测质量、未知状态与接口失效

建议为感知结果统一设置以下元信息：

| 字段 | 作用 |
|---|---|
| `capture_stamp` / `publish_stamp` | 区分观测发生时间和发布时刻 |
| `frame_id` / `calibration_version` | 明确空间参考和几何配置 |
| `valid` / `reason_code` | 表达深度缺失、超时、遮挡或定位失效等原因 |
| `confidence` / `uncertainty` | 分别表达模型分数与经定义、验证的不确定性 |
| `last_observed_at` / `valid_until` | 区分当前观测、历史记忆与预测结果 |
| `source_modalities` / `model_version` | 记录信息来源和算法版本 |

这些是接口设计建议，实际字段可匹配公司框架。网络分类分数、滤波协方差和任务成功概率不是同一个概念；如果要把分数作为概率使用，需要额外检查校准效果。

下游应该能区分“这里有障碍”“这里已观测为空闲”“这里尚未可靠观测”。同样，目标未检出可能意味着目标不存在、视野不覆盖或传感器失效，接口应保留这些差异。

### 10.4 在线架构与算力安排

建议把需要连续更新的几何或跟踪模块，与相对低频的语义推理、地图查询和异常解释分开调度。所有模块用时间戳和有效期关联结果，语义输出延迟时，不应直接覆盖当前几何状态。

首版优先建立可调试的模块接口和可回放链路。模型压缩、量化、蒸馏或推理图优化应由性能分析驱动，并在优化后重新检查精度和失效场景。文档不预设具体芯片上的帧率或显存要求，实际运行配置确定后再测试。

记录模型推理耗时之外的图像解码、预处理、CPU／GPU 拷贝、坐标转换、地图更新和消息传输开销。在导航、运控、日志等进程同时运行的条件下测量资源，避免只报单模型独占设备的理想结果。

### 10.5 建议交付的工程材料

- 一个可重复执行的录制与回放入口。
- 一个统一的配置文件，固定传感器、模型、阈值与标定版本。
- 一套输出接口说明和最小消费者样例。
- 一套带原始观测、几何中间结果和置信度的可视化。
- 一个从数据清单到结果表的评测入口。
- 一份已知限制、失败案例和下一步改进清单。

这些材料应该服务于实际迭代。无需为了简历把小模块重构成庞大平台；当两个项目确实复用时，再提取共享部分。

## 11. 数据闭环与评测体系

### 11.1 从任务失败反推数据需求

先列出业务必须覆盖的场景和允许的任务范围。例如：室内走廊、限定速度、规定最小障碍尺寸；固定按钮尺寸与接近距离；规定仪表类型与可读条件。未覆盖的情况单独标注，避免把有限测试结论外推为通用能力。

用“现象—可能原因—需要数据—如何验证”组织失败库：

| 现象 | 可能原因 | 要保留的证据 | 后续验证 |
|---|---|---|---|
| 走起来地图整体抖动 | 状态时间错位、运动学或定位误差 | 原始点云、姿态、关节、时间差 | 补偿消融与固定目标测试 |
| 柜体识别正确但位置错 | 深度关联到背景、地图变换错误 | 掩码、深度、坐标链、地图版本 | 三维真值对比 |
| 按钮定位准但按不到 | 工具偏移、可达性、控制误差 | 末端标定、接近轨迹、控制反馈 | 模块化误差预算 |
| 巡检误报频繁 | 反光、视角、工况变化或模型偏置 | 同设备多视角、历史状态、运行工况 | 复查策略与独立标签 |
| 滑移报警延迟 | 采样不足、排队、窗口或标注偏差 | 原始曲线、事件真值、各阶段时间戳 | 因果在线时延测试 |

每个失败样本应关联可重现配置。只截一张检测失败图片，通常不足以诊断时序、地图或接触问题。

### 11.2 数据划分与泄漏防范

按完整序列、任务回合、采集批次、设备实例或场景分组。划分依据由希望证明的泛化能力决定：

- 同设备新日期：检验时间、光照和工况变化。
- 新设备实例：检验实例泛化。
- 新房间或新厂区：检验场景迁移。
- 新机器人或新相机：检验跨平台变化。
- 未见指令表达：检验语言变化；同时要防止对象或答案在数据中被隐含泄漏。

验证集用于选择阈值和模型，测试集用于最终比较。如果反复查看测试失败并据此修改模型，这部分数据事实上已经参与开发，需要另建独立测试集或明确报告开发集结果。

### 11.3 标注质量与真值可信度

检测框、三维点、法向、位姿、异常状态和滑移起始时间的真值获取方式不同。文档应注明测量工具、人工规则、模糊样本处理方法和标注一致性检查。

三维测量有自身误差，事件起始也可能只有一个不确定时间区间。指标的精细程度不能超过真值支持的程度。教师模型生成的伪标签可用于训练，但独立评测不应只验证学生是否复现同一个教师的偏差。

标注预算有限时，可以大量收集低成本序列，在关键子集上建立高质量几何或事件真值；明确各指标使用的子集，不把小规模高质量子集的结果当成全量覆盖。

### 11.4 指标应覆盖四个层次

| 层次 | 例子 | 主要回答的问题 |
|---|---|---|
| 单次感知 | 检测召回、位置误差、状态识别 | 当下判断是否正确 |
| 时序稳定性 | 坐标抖动、ID 切换、丢失恢复、事件延迟 | 连续工作是否稳定 |
| 工程性能 | 全链路延迟、资源、丢帧、长时间故障 | 是否能在实际平台运行 |
| 任务效果 | 完成率、人工干预、重试、复核成本 | 是否帮助机器人完成任务 |

任务成功率可写为“按预先条件完成的任务回合数／全部符合起始条件的任务回合数”。超时、算法失败和人工介入不能随意删除；外部设施故障等排除项应事先规定并报告数量。

几何精度应和输出覆盖率一起报告；事件时延应和漏检率一起报告；拒识能力应和误拒率一起报告；重试后成功率应和首次成功率、任务时长一起报告。

### 11.5 对比与消融怎样组织

先定义业务可用的朴素基线，再逐项加入技术。例：单帧几何→姿态补偿→时序融合→置信度门控。不要同时改变训练数据、模型规模、输入分辨率和后处理，然后把全部收益归因于融合算法。

对训练方法，保存随机种子、数据版本、训练设置和最佳模型选择规则；资源允许时使用多个种子估计波动。对真机测试，固定硬件与控制版本，交错运行不同方案或随机化顺序，避免电池状态、光线、人员熟练度等因素只作用于某一方案。

按独立任务回合统计结果和区间。视频中的连续帧高度相关，不能把十万帧简单当成十万个独立试验。具体统计方法随指标选择；样本较少时，至少同时给出成功次数与总次数，承认估计的不确定性。

## 12. 向 VLM／VLA 与机器人学习岗位延伸

### 12.1 先明确个人希望补充的能力

VLM 项目侧重视觉与语言的理解和关联；VLA 项目进一步输出机器人动作。跑通语言查询、返回三维目标、再调用传统导航，可以作为视觉语言应用与空间感知项目，但不应因此写成自己训练了端到端动作模型。

如果下一份工作希望承担模型训练，建议在现有任务中增加一个范围明确的学习问题，例如设备指代消歧、交互点预测、操作结果识别或视觉与触觉时序融合。这样可以积累数据设计、训练、验证、泛化和部署，而不会完全切断已有经验。

### 12.2 路线 A：领域视觉语言模型适配

**可选任务：** 给定现场图片和自然语言描述，定位指定设备或可交互部位，并在证据不足时输出未知。

**数据：** 图像、指令、设备身份、目标框或掩码、三维位置、答案或拒识标签。包含相似设备、同义表达、模糊指代、不存在的目标和遮挡样本。

**实施：** 先评估现成模型和简单检索基线；统计主要错误是否来自语言理解、视觉细节、类别知识还是空间信息；再决定微调、训练轻量预测头、增加几何约束或蒸馏。参数高效微调只是一种训练方式，选择依据应包括算力、数据规模和误差来源。

**验证：** 在独立设备或场景上测目标定位、拒识、指代消歧和机器人任务完成率；同时比较相同模型未适配时的效果。对空间问题单独设组，避免整体问答准确率被简单文本问题主导。

**简历核心：** 你构建了什么数据、改了模型的什么部分、采用什么训练目标、泛化改善在哪些范围成立，以及部署代价。

### 12.3 路线 B：一个操作任务的视觉策略学习

**前提：** 能持续获得动作可回放的示教数据，有稳定的观测—动作接口，有明确任务成功判定，并能进行受控真机验证。

**最小任务：** 固定工作区内的一类物体抓放或按钮操作。先明确动作空间是关节目标、末端位姿增量还是其他指令，单位、坐标系、控制频率和夹爪表示全部统一。

**学习路线：** 建立行为克隆基线，再视动作多样性和序列需求评估其他策略表示。Diffusion Policy 是以条件扩散过程生成动作序列的公开参考；其适用性需要结合自己的任务、数据和控制接口验证，不能直接照搬论文中的成功率。[Diffusion Policy 官方项目](https://diffusion-policy.cs.columbia.edu/)

**关键实验：** 视觉输入变化、是否使用本体状态、单视角与多视角、不同示教数量、物体初始位置变化、未见对象、遮挡和动作执行延迟。离线动作误差只作为诊断，最终需看闭环任务成功与失败模式。

### 12.4 路线 C：适配已有 VLA

OpenVLA 提供开放的视觉语言动作模型和适配流程，可作为研究起点；官方材料也强调目标机器人域的数据和微调。采用时应查清当前代码、权重、动作规范和支持范围。[OpenVLA 官方项目](https://openvla.github.io/)、[官方代码](https://github.com/openvla/openvla)

建议把项目拆成四个明确交付：

1. **数据接口正确。** 原始示教的图像、状态、指令和动作能够对齐，回放能完成原任务。
2. **训练链路可复现。** 数据转换、动作归一化、训练设置和模型选择可追踪。
3. **部署链路一致。** 在线观测预处理、动作反归一化与执行频率和训练约定一致。
4. **任务评测有效。** 比较基线，报告独立场景、语言表达和物体变化下的成功率及延迟。

对于感知背景，可以重点承担多视角输入、几何信息引入、视觉编码器适配或观测质量对策略的影响，但必须实际完成相应训练和消融才写入简历。没有证明作用的“加入点云”“加一个注意力模块”不足以说明贡献。

### 12.5 什么时候先缩减范围

没有稳定控制接口时，先完成方向三的感知模块；没有真实示教时，先验证数据采集和动作回放；没有训练算力时，先做模型评测、检索或轻量预测头；真机机会很少时，将离线研究与实机验证分别报告。

从零训练通用人形机器人 VLA 涉及数据、模型、动作、安全执行与大规模评测等多个团队职责。作为个人下一阶段目标，更适合认领可独立验证的子问题，逐步积累完整闭环经验。

## 13. 按资源和求职目标选择项目组合

### 13.1 组合 A：延续三维感知优势

**适用条件：** 已有深度或激光、姿态与定位接口，可以和导航、运控团队联调。

**项目组合：** 方向一作为主线，方向七尽快完成；方向四在动态干扰成为实际瓶颈时并入或独立立项。

**可以形成的经历：** 身体运动条件下的几何补偿与时序感知、局部地图、动态目标处理、实时部署和固定路线验证。求职时突出自己承担的感知部分，并准备算法与工程两类证据。

**主要依赖：** 位姿质量、数据可记录、下游愿意消费新的地图或状态输出。若外部接口不稳定，应先把离线与在线单模块评测做完整。

### 13.2 组合 B：向具身多模态感知发展

**适用条件：** 巡检需要识别多种设备、自然语言指令或减少人工复核，有语义模型部署资源。

**项目组合：** 方向一保留几何基础，方向二作为拓展主线，方向五解决真实巡检中的观测质量与复核问题。

**可以形成的经历：** 视觉语言目标定位、空间关联、实例记忆、主动观察和领域模型适配。若偏向模型研发，进一步承担第 12 章路线 A 的数据与训练工作。

**主要依赖：** 稳定定位、设备或异常标签、任务接口。要区分地图检索能力、模型理解能力与导航执行能力，分别展示贡献。

### 13.3 组合 C：向操作感知和机器人学习发展

**适用条件：** 操作平台已经能稳定执行给定末端目标，有机械臂或手、标定工具和足够真机时间。

**项目组合：** 方向三作为主线，方向六在接触状态成为瓶颈时展开；第 12 章的视觉策略或 VLA 适配作为后续延伸。

**可以形成的经历：** 交互位置与位姿、手眼几何、视角协同、结果确认、接触事件建模和操作数据。人形背景体现在身体、头部与手臂运动造成的额外约束，需要实际测试支撑。

**主要依赖：** 控制、示教、传感器和测试机会。若这些能力还在搭建，先完成可被未来操作链路复用的感知接口与几何评测。

### 13.4 组合 D：资源少或工作时间紧

**适用条件：** 只有已有检测项目、单相机或有限算力，无法推动新的硬件与大规模数据采集。

**项目组合：** 优先完成方向七中的标定、时序与几何输出；在巡检中选择一种可复现失败，解决检测到三维关联或观测质量评估问题。同步建设回放、评测和资源分析。

**范围约束：** 单目方案应明确地面、尺度或已知物体假设。没有机械臂时可以验证交互点估计，但不要报告操作闭环结果；没有定位时可以做当前视野的语言目标定位，但不能写成空间地图导航。

### 13.5 一个用于内部排序的打分表

每项按 1—5 分打分，并写一行理由。以下权重是个人决策工具，可随岗位目标调整，不是市场价值估计。

| 维度 | 建议权重 | 高分意味着什么 |
|---|---:|---|
| 业务需求与验收人 | 25% | 有真实痛点、使用方和明确交付 |
| 硬件、数据、接口可用性 | 25% | 可以立即开始并反复验证 |
| 个人可承担的核心算法深度 | 20% | 能拥有清楚的设计、实现和评测责任 |
| 与求职方向的匹配程度 | 20% | 能补齐明确的岗位能力缺口 |
| 能否形成可复用成果 | 10% | 数据、模块或方法能支持第二个任务 |

如果某个方向在资源可用性上接近最低分，先缩减为一个可验证子任务，再重新评分。不要因为名称热门就忽略交付和数据依赖。

## 14. 实施路线、阶段交付与验收

### 14.1 六个月示例计划

以下是已有机器人平台、能够持续投入研发和联调条件下的粗略排期示例。周数不构成承诺；机械臂成熟度、真机排期、数据标注和接口变动可能显著改变周期。

| 时间窗口 | 核心任务 | 可交付结果 | 需要作出的判断 |
|---|---|---|---|
| 第 1—2 周 | 资源盘点、故障采样、接口与指标定义 | 传感器表、失败清单、基线数据、立项页 | 哪个问题能由自己推进并验证 |
| 第 3—6 周 | 跑道或巡检一个小范围闭环 | 可运行基线、回放评测、第一份对比报告 | 技术瓶颈在数据、几何、模型还是接口 |
| 第 7—12 周 | 地形或所选主项目的核心算法 | 稳定接口、核心改进、独立测试结果 | 哪项改进值得继续投入 |
| 第 13—16 周 | 真机联调、性能优化、失败迭代 | 多次任务测试、延迟与资源报告、失败归因 | 模块改善是否转化为任务收益 |
| 第 17—22 周 | 选一个语义或操作拓展 | 与主线复用的第二项能力、对比评测 | 拓展是否补齐求职能力缺口 |
| 第 23—24 周 | 汇总、复现、材料整理 | 项目说明、图表、视频索引、简历条目 | 结果是否真实、清楚、可重复解释 |

实际工作可以有交叠，但同时推进的核心研究问题建议控制在能够稳定跟踪实验的数量。维护已有交付也要计入时间。

### 14.2 每个项目都可以采用的四阶段验收

**阶段一：基线可复现。** 同一份数据能够重复得到相同或可解释波动的结果，所有输入和坐标正确，评测脚本有可检查样例。

**阶段二：核心假设得到验证。** 一个明确改动在预先确定的验证条件下优于基线，且消融能够说明原因；如果没有改善，保留结果并转向真正瓶颈。

**阶段三：在线接口可用。** 数据新鲜度、无效状态、资源占用和异常恢复符合消费者要求，能持续记录完整链路。

**阶段四：任务测试有结论。** 既报告成功，也报告失败、限制和影响因素；明确个人模块贡献与联合系统结果。

### 14.3 如何设定指标目标而不拍脑袋

先由任务约束反推感知需求。例如：按钮可按压区域、工具尺寸和总误差预算共同决定接触点容差；跑道可用宽度、身体占据、控制跟踪误差和感知延迟共同决定所需几何精度；移动速度和处理延迟共同影响观测到执行期间的位移。

可以用“速度×总延迟”估算这段时间内的平移量级，用“角速度×时间错位”估算姿态错位量级，但它们只是误差预算中的近似项，不包含所有动态、定位与控制影响。

先测基线再设阶段目标，说明阈值来自任务需要、硬件极限还是暂定试验条件。文中没有预填 95%、30 FPS 或毫米级等通用承诺，因为这些数值必须由具体平台和任务决定。

### 14.4 何时调整项目范围

- 若模型改进不改变主要失败，转查时间同步、几何或下游接口。
- 若缺少可靠真值，先建立小而可信的评测子集。
- 若算力不足，缩小地图、调整更新频率或任务范围，随后验证代价。
- 若机械臂或运控迟迟不可用，先交付可回放、在线输出与感知误差报告，把联合验证列为明确依赖。
- 若一个方向没有使用方且难以拿到数据，优先回到已有巡检和跑道中的真实问题。

## 15. 简历写法、成果材料与面试准备

### 15.1 统一的项目描述结构

可以按“任务与平台—个人责任—核心难点—实际方法—测试范围—实测结果”组织。项目名应与实际完成范围一致，先让读者知道机器人完成了什么，再介绍算法。

> 在【平台与业务场景】中负责【具体模块】，针对【可验证的失败问题】，设计并实现【核心方法】，向【导航／运控／操作】提供【输出】；在【独立场景／对象、速度、任务次数、硬件条件】下，将【指标】从【基线】改善到【结果】，并完成【实际部署或联合验证范围】。

不要把所有指标都塞进一条。通常选择一个主要精度或稳定性指标、一个任务结果，以及必要的实时性信息；其余放入项目说明。

### 15.2 七个方向各自应突出什么

| 方向 | 简历里最值得突出的技术贡献 | 适合配套的证据 |
|---|---|---|
| 地形感知 | 运动补偿、近距几何、未知处理、稳定局部地图 | 分尺寸召回、地图误差、时序对比和路线测试 |
| 语义地图 | 指代定位、三维关联、设备身份、地图更新 | 正负查询集、实例混淆、定位与任务结果 |
| 操作感知 | 交互点／位姿、手眼误差、遮挡恢复、质量门控 | 几何误差、覆盖率、首次与重试成功率 |
| 动态跟踪 | 自运动补偿、关联、速度估计、动态图层 | 轨迹指标、遮挡恢复、动态路线干预 |
| 主动巡检 | 观测质量、视点选择、异常复核、跨次身份 | 误报／漏报、复查收益、时间和人工成本 |
| 视觉与力／触觉融合 | 因果时序、状态定义、跨模态信息、失败检测 | 事件指标、单模态消融、在线时延和恢复收益 |
| 跑道感知 | 地面投影、时序几何、丢线恢复、低延迟 | 偏差误差、速度分组、越线与完成率 |

### 15.3 几类表述怎样写得准确

| 实际完成的工作 | 合适的表述 | 需要额外完成后才能声称的内容 |
|---|---|---|
| 部署现有检测模型并优化数据和性能 | 检测适配、数据迭代、部署优化，列出具体改进 | 自研基础模型或通用视觉能力 |
| RGB-D 与姿态做几何补偿 | 多传感器时空对齐、姿态补偿、几何融合 | 端到端多模态模型训练 |
| 给地图增加语言检索 | 语言目标定位、语义地图查询 | 未知环境探索或完整 VLN，除非实际做了 |
| 输出物体位姿 | 操作目标定位或位姿估计 | 抓取规划、接触控制、全身操作，除非实际承担 |
| 输出失败事件 | 操作状态估计、失败检测 | 自动恢复成功，除非已经联调并测量 |
| 改进感知后联合测试成功率提升 | 与相关团队联合验证系统收益 | 全部系统收益均由个人模块独立造成 |
| 复现并改造开源方法 | 说明基线来源及自己的适配、改进和验证 | 原创算法，除非有明确的新方法和证据 |

### 15.4 建议持续积累的成果包

1. 一页项目说明：业务需求、个人职责、核心方法与主要结果。
2. 一张系统图：输入、坐标、模块、输出与消费者。
3. 一份实验表：基线、消融、测试条件、样本量和主要指标。
4. 几个代表性成功及失败案例：能说明技术难点和改动效果。
5. 一份技术复盘：至少两个没奏效的方法、原因和最终选择。
6. 一份部署记录：硬件、资源、全链路延迟与长期运行情况。
7. 一套可复现配置：数据版本、模型版本、标定和参数。

上述材料首先在公司允许的工作环境中积累。对外求职使用可公开或获准披露的内容；涉及客户现场、内部数据和代码时，可用抽象图、合规的汇总结果或自行制作的演示材料说明能力，不把内部资料默认当成可公开作品。

### 15.5 面试时重点准备的十个问题

1. 这个任务为什么需要你采用的传感器与表示？
2. 基线是什么，主要失败在哪里？
3. 你亲自设计和实现的核心部分是什么？
4. 为什么先解决这个问题，而不是换一个更大的模型？
5. 训练和测试如何划分，真值如何获得？
6. 哪个消融最能证明你的方法有效？
7. 误差、置信度、覆盖率和时延之间如何取舍？
8. 真机没有达到离线效果时，怎样定位原因？
9. 结果可以泛化到哪些对象、场景和平台，哪些还不行？
10. 给你更多时间或资源，下一步优先解决哪个瓶颈？

每个答案最好都有一个具体例子。能讲清一次失败怎样定位和解决，通常比列出大量模型名称更能体现实际工作深度。
